심화 탐구 프로젝트 · 속성을 더 모으면 예측이 달라질까

7차시 교재에서는 표에 이미 들어 있는 변수를 켜고 끄며 점수를 비교했습니다. 이 실험실에서는 순서를 반대로 놓습니다. 흥행에 영향을 줄 것 같은 것을 먼저 적고, 그 속성이 데이터에 실제로 있는지 확인한 다음, 데이터를 모으고 하나씩 넣어 보며 쓸모를 판단합니다. 마지막에는 그렇게 만든 모델로 자신이 고른 영화 한 편의 관객 수를 예측합니다.

← 7차시 교재로

🎯 여섯 단계
  • 1 가설 — 흥행을 가르는 것이 무엇일지 적는다
  • 2 확인 — 그 속성이 데이터에 있는지 문서에서 찾는다
  • 3 수집 — 두 표를 영화 코드로 합친다
  • 4 검토 — 새 속성을 하나씩 넣고 점수 변화를 적는다
  • 5 학습 — 고른 속성으로 모델을 다시 학습시킨다
  • 6 예측 — 관심 있는 영화 한 편을 예측한다

이 실험실이 사용하는 표는 어제까지 모인 기록입니다. 화면에 나오는 편수와 점수는 사람마다, 날마다 조금씩 다릅니다. 그래서 본문에는 값을 적어 두지 않았습니다. 각자 화면에서 읽은 숫자를 표에 적습니다.

1. 가설 세우기 — 무엇이 흥행을 가른다고 생각합니까

예측 모델을 만들 때 가장 먼저 할 일은 코드를 쓰는 것이 아닙니다. 무엇을 재료로 삼을지 정하는 것입니다. 데이터에 있는 열을 전부 넣고 결과를 기다리면 점수가 오르든 내리든 그 까닭을 설명할 수 없습니다. 그래서 데이터를 열기 전에 가설을 먼저 적습니다.

가설은 두 부분으로 이루어집니다. 무엇이 흥행에 영향을 준다는 주장, 그리고 그렇게 생각하는 까닭입니다. 여기에 조건이 하나 더 붙습니다. 그 주장은 표의 한 열로 옮길 수 있어야 합니다. "재미있는 영화가 흥행한다"는 맞는 말일 수 있지만 재미를 적어 둔 열이 없으므로 확인할 방법이 없습니다. "상영시간이 길면 관객이 적을 것이다"는 상영시간이라는 열만 있으면 바로 확인할 수 있습니다.

가설을 적을 때 가중치의 부호까지 함께 생각해 두면 나중에 결과를 읽기 쉬워집니다. 주연이 많을수록 관객이 많아진다고 보았다면 그 속성의 가중치는 양수여야 하고, 상영시간이 길수록 관객이 줄어든다고 보았다면 음수여야 합니다. 학습을 마친 뒤 부호가 예상과 반대로 나오면 그때부터 살펴볼 대목이 생깁니다. 가설이 틀렸을 수도 있고, 함께 넣은 다른 변수가 같은 것을 담고 있어서 부호가 뒤집혔을 수도 있습니다.

💡 가설을 적어 본 예
가설그렇게 생각한 까닭확인할 방법
주연이 여럿인 영화일수록 관객이 많을 것이다.이름이 알려진 배우를 여럿 세운 영화는 홍보가 크게 붙는다.주연 수를 세어 둔 열이 있는지 확인하고, 있으면 모델에 넣어 점수 변화를 본다.
상영시간이 길면 총 관객이 적을 것이다.한 상영관에서 하루에 돌릴 수 있는 회차가 줄어든다.상영시간 열을 넣어 보고 가중치의 부호를 확인한다.
청소년 관람 불가 등급은 총 관객이 적을 것이다.볼 수 있는 관객의 범위가 좁다.관람등급을 0과 1로 바꾼 열을 만들어 넣는다.

위의 예는 예일 뿐입니다. 아래 표에는 각자 생각한 가설을 적습니다. 세 줄을 모두 채우기 어려우면 한 줄만 적어도 됩니다. 이 실험실은 가설 하나를 끝까지 확인하는 것으로도 충분합니다.

2. API 문서에서 확인하기 — 있는 열과 없는 열

가설을 적었으면 다음은 그 속성이 실제로 있는지 확인하는 순서입니다. 데이터를 받기 전에 무엇이 들어 있는지 알려 주는 문서를 먼저 읽습니다. 영화진흥위원회 오픈 API는 영화 한 편의 상세 정보를 돌려주는 창구를 따로 두고 있고, 거기에서 감독·배우·상영시간·관람등급·배급사를 받을 수 있습니다. 이 실험실에서는 그 결과를 미리 모아 둔 표를 사용합니다.

실제로 데이터를 다루는 일은 대체로 이 순서로 이루어집니다. 필요한 것을 먼저 정하고, 그것을 어디에서 얻을 수 있는지 문서에서 찾고, 얻을 수 없으면 계획을 고칩니다. 데이터를 먼저 받아 놓고 무엇을 할지 정하면, 손에 든 열에 맞추어 질문이 바뀌게 됩니다.

kobis_people.csv — 영화 한 편의 인물과 상영 정보를 한 줄씩 정리한 표입니다. 7차시에서 사용한 kobis_movies.csv와 영화 코드가 같습니다.

🔎 데이터에 없는 것
  • 제작비와 홍보비 — 공개하지 않는 영화가 많아 이 표에 없습니다.
  • 예고편 조회수 — 영화진흥위원회가 모으는 데이터가 아닙니다.
  • 감독의 이전 흥행 기록 — 감독 이름은 있지만 이전 작품의 관객 수는 없습니다.

감독의 이전 흥행 기록은 특히 아쉬운 항목입니다. 감독 이름이 표에 있으니 이전 작품의 관객 수만 붙이면 될 것처럼 보입니다. 그런데 이 표는 최근에 10위권에 든 영화만 모은 것이라 한 감독의 영화가 대체로 한 편씩만 올라 있습니다. 감독 이름으로 묶어 보면 같은 감독의 이전 작품이 함께 들어 있는 경우가 드물어서, 이전 흥행 기록을 계산할 데이터 자체가 없습니다. 표에서 감독 이름별로 몇 편이 올라 있는지 직접 세어 보면 이 사정이 그대로 보입니다.

가설을 적었는데 확인할 데이터가 없는 일은 자주 일어납니다. 그때 할 수 있는 일은 세 가지입니다. 첫째, 뜻이 비슷한 다른 열로 대신합니다. 둘째, 데이터를 더 모읍니다. 여러 해에 걸친 기록을 모으면 같은 감독의 영화가 여러 편 들어오므로 이전 흥행 기록을 계산할 수 있습니다. 셋째, 지금은 확인할 수 없다고 적어 두고 다음으로 넘어갑니다. 확인하지 못한 가설을 기록으로 남기는 것도 결과입니다.

  • 확인할 수 없는 가설은 어떤 데이터가 더 있어야 확인할 수 있습니까.
  • 대신할 열을 골랐다면, 그 열은 원래 가설과 같은 것을 재고 있습니까. 다른 것을 재고 있다면 무엇이 다릅니까.

3. 데이터 수집 — 두 표를 영화 코드로 합치기

확인이 끝났으면 데이터를 모읍니다. 7차시에서 사용한 영화별 표와 이번에 붙일 인물 표는 서로 다른 파일이므로 하나로 합쳐야 합니다. 두 표에 모두 있는 movieCd 열이 같은 영화를 가리키므로 이 열을 기준으로 붙입니다. 한쪽에만 있는 영화는 합친 표에서 빠지므로, 합친 뒤 몇 편이 남았는지 화면에 적게 합니다.

모델에 넣기 전에 그림 두 개를 먼저 봅니다. 상영시간과 관객 수를 흩어 놓은 그림, 그리고 관람등급별 관객 수를 나란히 놓은 그림입니다. 눈으로 먼저 확인하면 1단계에서 적은 가설이 데이터와 어느 정도 맞는지 미리 가늠할 수 있습니다.

# main.py — 영화 흥행 예측기 (심화 탐구 프로젝트)
import pandas as pd
import plotly.express as px
import streamlit as st
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, r2_score

MOVIES = "https://raw.githubusercontent.com/greatsong/modudata/main/data/kobis_movies.csv"
PEOPLE = "https://raw.githubusercontent.com/greatsong/modudata/main/data/kobis_people.csv"

BASE = ["first_scrn", "first_show", "peak"]
EXTRA = {
    "배우 수": "actors_n",
    "주연 수": "lead_n",
    "상영시간": "showTm",
    "청소년관람불가": "adult",
    "대형 배급사": "bigco",
}

st.title("영화 흥행 예측기")


@st.cache_data
def load():
    movies = pd.read_csv(MOVIES, encoding="utf-8-sig", dtype={"movieCd": str})
    people = pd.read_csv(PEOPLE, encoding="utf-8-sig", dtype={"movieCd": str})
    people = people[["movieCd", "director", "actors_n", "lead_n", "showTm", "watchGrade", "company"]]
    df = movies.merge(people, on="movieCd", how="inner")
    df = df[(df["total_audi"] > 0) & (df["first_scrn"] > 0) & (df["showTm"] > 0)]
    df = df.sort_values("movieCd").reset_index(drop=True)
    df["adult"] = (df["watchGrade"] == "청소년관람불가").astype(int)
    big = df["company"].value_counts().head(5).index
    df["bigco"] = df["company"].isin(big).astype(int)
    return df


def split(df):
    test = (df.index % 10) < 3          # 열 편마다 앞의 세 편이 시험용
    return df[~test], df[test]


def score(train, test, cols):
    model = LinearRegression().fit(train[cols], train["total_audi"])
    pred = model.predict(test[cols])
    return r2_score(test["total_audi"], pred), mean_absolute_error(test["total_audi"], pred), model

df = load()
train, test = split(df)
st.write(f"합친 표 {len(df)}편 · 학습용 {len(train)}편 · 시험용 {len(test)}편")
st.dataframe(df[["movieNm", "director", "first_scrn", "actors_n", "showTm", "total_audi"]].head(10))

합친 표가 원래 표보다 적어졌다면 한쪽에만 있는 영화가 있었다는 뜻입니다. 값이 비어 있는 영화가 몇 편인지도 함께 확인합니다. 빈 값을 그대로 두고 학습하면 오류가 나거나 그 영화가 통째로 빠지고, 그러면 앞의 결과와 같은 조건에서 비교할 수 없습니다.

두 표에는 이름이 같은 열이 몇 개 있습니다. 영화 이름과 개봉일이 양쪽에 모두 들어 있습니다. 합칠 때 이런 열은 하나만 남기거나 이름을 구분해 두어야 나중에 어느 쪽 값인지 알 수 있습니다. 합친 표가 제대로 만들어졌는지는 영화 한 편을 골라 두 원본 표의 값과 맞추어 보면 확인할 수 있습니다.

4. 속성이 쓸모 있는지 보기 — 하나씩 넣는다

새 속성을 한꺼번에 다 넣으면 점수가 달라져도 무엇 때문인지 알 수 없습니다. 그래서 기본 변수 세 가지에서 출발해 새 속성을 한 번에 하나씩만 더합니다. 기본 변수 세 가지는 7차시에서 쓴 첫 관측일 스크린수·첫 관측일 상영횟수·성수기 개봉 여부입니다. 매번 R²와 평균절대오차를 함께 적고, 앞줄과 얼마나 달라졌는지도 적습니다.

관람등급과 배급사는 글자로 적힌 열이라 그대로 넣을 수 없습니다. 7차시에서 성수기를 0과 1로 만든 것과 같은 방법으로 바꿉니다. 관람등급은 청소년 관람 불가이면 1, 아니면 0인 열로 만들 수 있고, 배급사는 표에 자주 나오는 몇 곳을 대형 배급사로 묶어 1, 나머지를 0으로 둘 수 있습니다.

한 번에 하나씩 넣는 까닭은 원인을 좁히기 위해서입니다. 배우 수와 상영시간을 함께 넣고 점수가 올랐다면 둘 가운데 무엇이 올렸는지 알 수 없고, 점수가 내려갔다면 무엇이 내렸는지도 알 수 없습니다. 다섯 개를 한 줄씩 다섯 번 확인하는 편이 결과를 설명하기에 낫습니다.

② 개선
합친 표로 총 관객 수를 예측하는 다중 선형회귀를 만들어 줘.
영화를 영화코드 순으로 정렬한 다음, 열 편마다 앞의 세 편을 시험용으로 떼어 놓고
나머지로 학습해 줘. 어떤 속성을 넣든 이 나누기는 똑같이 유지해 줘.
기본 변수는 첫 관측일 스크린수·첫 관측일 상영횟수·성수기 개봉 세 가지야.
관람등급이 청소년관람불가이면 1, 아니면 0인 열을 만들어 줘.
배급사는 합친 표에 가장 많이 나오는 다섯 곳을 대형 배급사로 보고 1, 나머지는 0인 열을 만들어 줘.
기본 변수 세 가지만 쓴 경우를 첫 줄에 두고, 거기에 배우 수·주연 수·상영시간·
청소년관람불가 여부·대형 배급사 여부를 하나씩만 더한 경우를 한 줄씩 표로 보여 줘.
줄마다 시험용 영화로 잰 R²와 평균절대오차를 적고, 첫 줄과의 차이도 함께 적어 줘.
같은 내용을 가로 막대그래프로도 그려 줘. 그래프는 plotly로 그려 줘.
선생님이 실행해 확인한 예시 코드
main.py에 이어 붙일 부분
st.header("속성을 하나씩 넣어 본다")
base_r2, base_mae, _ = score(train, test, BASE)
rows = [{"넣은 속성": "기본 세 가지만", "R²": base_r2, "평균절대오차": base_mae, "R² 차이": 0.0}]
for name, col in EXTRA.items():
    r2, mae, _ = score(train, test, BASE + [col])
    rows.append({"넣은 속성": name, "R²": r2, "평균절대오차": mae, "R² 차이": r2 - base_r2})
table = pd.DataFrame(rows)
st.dataframe(table.style.format({"R²": "{:.3f}", "평균절대오차": "{:,.0f}", "R² 차이": "{:+.3f}"}))
st.plotly_chart(px.bar(table, x="R² 차이", y="넣은 속성", orientation="h"))

기본 변수 세 가지
스크린수·상영횟수·성수기

첫 줄은 비교의 출발점입니다. 둘째 줄부터는 새 속성 하나의 이름을 적고 그때의 값을 적습니다.

❓ 표를 채운 뒤 함께 답할 질문
  • 새 속성을 넣었을 때 R²와 평균절대오차가 같은 방향으로 움직였습니까.
  • 앞줄과의 차이가 거의 없는 속성이 있었습니까. 그것은 흥행과 관계가 없다는 뜻입니까, 아니면 이미 넣은 변수가 같은 것을 담고 있다는 뜻입니까.

5. 프롬프트로 모델 학습 — 고른 속성으로 다시 학습한다

4단계 표를 보고 사용할 속성을 정합니다. 차이가 거의 없는 속성을 굳이 남길 이유는 없습니다. 다만 넣었을 때 점수가 조금이라도 오르고 그 까닭을 한 문장으로 설명할 수 있으면 남겨 둡니다. 정했으면 그 속성만으로 모델을 다시 학습시킵니다. 이때도 학습 데이터와 평가 데이터를 나누는 조건은 그대로 유지합니다. 조건을 바꾸면 4단계의 표와 비교할 수 없습니다.

③ 프롬프트
지금까지 살펴본 속성 가운데 내가 고른 것만으로 총 관객 수를 예측하는 모델을 다시 학습시켜 줘.
쓸 속성은 화면에서 체크박스로 고를 수 있게 하고, 처음에는 기본 변수 세 가지가 켜져 있게 해 줘.
학습용과 시험용 나누기는 앞과 똑같이 해 줘. 영화코드 순으로 정렬한 다음
열 편마다 앞의 세 편이 시험용이야. 시험용 영화는 학습에 쓰지 마.
학습에 쓴 영화 편수와 점수를 잰 영화 편수를 화면에 적어 줘.
시험용 영화로 잰 R²와 평균절대오차를 큰 숫자로 보여 주고, 학습용 영화로 잰 값도 작게 함께 보여 줘.
속성마다 가중치를 0을 가운데 두고 좌우로 뻗는 막대그래프로 그리고,
부호가 음수인 속성은 색을 다르게 해 줘.
단위가 다르면 가중치의 크기를 그대로 비교할 수 없다는 안내를 그래프 아래에 적어 줘.
시험용 영화의 실제 총 관객 수를 가로축, 예측한 총 관객 수를 세로축에 둔 산점도도 그려 줘.
예측이 실제와 같을 때를 나타내는 기준선을 함께 그리고, 두 축은 로그로 그려 줘.
그래프는 plotly로 그려 줘.
필요한 라이브러리 목록(requirements.txt)도 같이 줘. 버전 숫자 없이 이름만.
선생님이 실행해 확인한 예시 코드
main.py에 이어 붙일 부분
st.header("고른 속성으로 다시 학습한다")
picked = [col for name, col in EXTRA.items() if st.checkbox(name, value=False)]
cols = BASE + picked
r2, mae, model = score(train, test, cols)
c1, c2 = st.columns(2)
c1.metric("시험용 R²", f"{r2:.3f}")
c2.metric("시험용 평균절대오차", f"{mae:,.0f}명")
weight = pd.DataFrame({"속성": cols, "가중치": model.coef_})
st.plotly_chart(px.bar(weight, x="가중치", y="속성", orientation="h"))
st.caption("단위가 다르면 가중치의 크기를 그대로 비교할 수 없습니다.")
look = test.assign(예측=model.predict(test[cols]))
st.plotly_chart(px.scatter(look, x="total_audi", y="예측", hover_name="movieNm", log_x=True, log_y=True))
💡 점수가 거의 그대로일 때

속성을 여러 개 더 넣었는데 R²가 소수점 아래 둘째 자리에서만 움직이는 일이 흔히 있습니다. 실패가 아닙니다. 넣어 보기 전에는 그 속성이 도움이 되는지 알 수 없고, 넣어 본 뒤에야 도움이 되지 않는다는 것을 알게 됩니다. 값이 거의 그대로라는 결과도 데이터의 성질을 알려 줍니다. 배우 수나 상영시간이 스크린 수가 이미 담고 있는 것을 되풀이하고 있다는 뜻일 수 있습니다. 표에 그대로 적고, 왜 그런지 한 문장을 함께 남깁니다.

6. 내가 관심 있는 영화 예측 — 한 편을 골라 넣어 본다

마지막은 자신이 고른 영화입니다. 최근에 개봉한 영화나 좋아하는 영화 한 편을 정하고, 그 영화의 속성 값을 모델에 넣어 총 관객 수를 예측합니다. 상영시간과 관람등급은 대체로 개봉 전에 공개되므로 극장 예매 화면에서 확인할 수 있습니다. 스크린 수와 상영 횟수는 개봉한 뒤에야 집계되는 값이므로, 개봉 전 영화라면 비슷한 규모의 영화를 참고해 넣어 보고 그 사실을 함께 적습니다.

④ 개선
학습이 끝난 모델에 내가 고른 영화 한 편의 값을 직접 넣어 예측해 보고 싶어.
화면에 입력칸을 만들어 줘. 영화 이름, 첫 관측일 스크린수, 첫 관측일 상영횟수,
성수기 개봉 여부, 그리고 내가 고른 속성들의 값을 넣을 수 있게 해 줘.
넣은 값으로 예측한 총 관객 수를 큰 숫자로 보여 줘.
합친 표에 있는 영화들의 실제 총 관객 수 분포를 그리고, 그 위에 내 예측값이 어디쯤인지
세로선으로 표시해 줘. 그래프는 plotly로 그려 줘.
예측값이 음수로 나오면 그대로 보여 주고, 회귀는 음수도 예측한다는 안내를 함께 적어 줘.
합친 표에서 총 관객 수가 내 예측값과 가장 가까운 영화 다섯 편을 이름과 함께 표로 보여 줘.
기본 변수 세 가지만 쓴 모델의 예측값도 같은 화면에 나란히 보여 줘.
선생님이 실행해 확인한 예시 코드
main.py에 이어 붙일 부분
st.header("내가 고른 영화를 예측한다")
name = st.text_input("영화 이름", "블루웨일의 대모험")
값 = {}
값["first_scrn"] = st.number_input("첫 관측일 스크린수", value=800)
값["first_show"] = st.number_input("첫 관측일 상영횟수", value=3000)
값["peak"] = 1 if st.checkbox("성수기 개봉", value=True) else 0
for col in picked:
    값[col] = st.number_input(col, value=float(df[col].median()))
mine = pd.DataFrame([[값[c] for c in cols]], columns=cols)
pred = float(model.predict(mine)[0])
st.metric(f"{name}의 예측 총 관객 수", f"{pred:,.0f}명")
near = df.assign(차이=(df["total_audi"] - pred).abs()).nsmallest(5, "차이")
st.dataframe(near[["movieNm", "total_audi"]])
영화 이름넣은 값예측값실제값차이

아직 개봉하지 않은 영화라면 실제값과 차이는 비워 두고, 개봉 뒤에 확인해 채웁니다.

기본 변수 세 가지만 쓴 모델의 예측값과 새 속성을 더한 모델의 예측값이 거의 같을 수도 있습니다. 두 값을 모두 적어 두면 새 속성이 이 영화의 예측을 얼마나 바꾸었는지 바로 보입니다. 차이가 없다면 그것도 적어 둘 결과입니다. 속성을 더 모으면 예측이 좋아진다는 규칙은 없고, 넣어 본 다음에야 알 수 있습니다.

예측값 하나만 적어 두면 나중에 그 숫자가 무엇을 뜻하는지 알 수 없습니다. 어떤 속성을 넣었는지, 어느 시점을 가정했는지, 학습에 몇 편을 썼는지를 함께 적어 두어야 다른 사람이 같은 조건에서 다시 해 볼 수 있습니다.

❓ 예측을 마친 뒤 답할 질문
  • 방금 한 예측은 개봉 전 예측입니까, 첫 주 집계가 끝난 뒤의 예측입니까.
  • 이 모델을 다른 사람에게 보여 준다면, 예측값과 함께 반드시 적어야 할 조건은 무엇입니까.

여섯 단계를 마쳤습니다. 이 실험실에서 확인한 것은 속성을 많이 모으면 예측이 좋아진다는 규칙이 아닙니다. 넣어 보기 전에는 그 속성이 도움이 되는지 알 수 없다는 것, 그래서 가설을 적고 데이터를 확인하고 하나씩 넣어 보는 순서가 필요하다는 것입니다. 점수가 오른 경우와 그대로인 경우를 모두 기록으로 남기면, 다음에 같은 데이터를 다룰 때 같은 실험을 되풀이하지 않아도 됩니다.

🎒 오늘의 체크

  • 흥행에 영향을 줄 것 같은 가설을 적고, 표의 한 열로 옮길 수 있는지 판단했다.
  • 데이터에 있는 열과 없는 열을 구분하고, 없는 속성을 어떻게 할지 정했다.
  • 두 표를 영화 코드로 합치고 합친 편수와 빈 값을 확인했다.
  • 새 속성을 하나씩 넣어 R²와 평균절대오차의 변화를 표에 적었다.
  • 고른 속성으로 모델을 다시 학습시키고, 관심 있는 영화 한 편을 예측했다.
  • 그 예측이 어느 시점의 정보로 만든 값인지 설명할 수 있다.
