0. 왜 배우나

버스 도착 알림, 날씨 앱, 예매 앱의 실시간 순위 — 이런 앱들은 데이터 파일을 미리 내려받아 두지 않습니다. 여러분이 화면을 여는 순간, 앱이 데이터를 가진 서버에 요청을 보내고 응답을 받아 보여 줍니다. 1차시의 기온 앱은 내려받아 둔 파일(그 시점의 복사본)로 만들었습니다. 오늘은 데이터를 받는 두 번째 방법을 배웁니다. 한 번 익혀 두면 영화·급식·날씨·대중교통 등 세상의 수많은 실시간 데이터가 여러분 앱의 재료가 됩니다.

오늘 쓸 KOBIS는 영화진흥위원회가 운영하는 영화관입장권 통합전산망입니다. 전국 극장의 관객 수가 매일 집계되는 공식 통계라, 뉴스에 나오는 "천만 영화"의 근거가 바로 이 데이터입니다.

1. 개념 이해 — 데이터의 세 가지 형태

📖 교과서의 정의 『데이터 과학』 19·20쪽

"정형 데이터(structured data)는 데이터의 속성이나 구조가 명확하고 체계화된 데이터를 말한다." (19쪽)

"비정형 데이터(unstructured data)는 구조를 명확하게 정의하기 어려운 데이터를 말한다." (20쪽)

"반정형 데이터는 일부분이 정형화된 데이터로, 구조가 존재하지만 구조를 바꿀 수도 있는 유연한 형태의 데이터를 말한다." (20쪽)

→ 행과 열이 반듯하면 정형, 구조가 아예 자유로우면 비정형, 구조는 있되 표는 아니면 반정형.

정형 데이터의 대표는 행과 열로 이루어진 표입니다. 1차시의 서울 기온 CSV가 바로 이것입니다 — 날짜·평균기온 같은 열이 속성이고, 하루가 행 하나입니다. 교과서 19쪽이 정형 데이터의 예로 든 것도 마침 일별 박스 오피스 표입니다. 비정형 데이터는 이미지·텍스트·음성·영상처럼 구조의 제약 없이 자유롭게 표현된 데이터입니다. 그리고 그 사이에 반정형 데이터가 있습니다 — 오늘의 주인공입니다.

말보다 실물이 빠릅니다. 당곡고 급식 하루치가 세 가지 모습으로 기록된 것을 나란히 놓고 봅니다. 셋 다 같은 급식입니다.

정형 — 표 (CSV 파일)
날짜식사메뉴

행과 열이 반듯한 표. 열이 속성, 행이 하루입니다. 표 그대로 분석에 들어갑니다.

2. JSON — 라벨 붙은 상자

📖 교과서의 정의 『데이터 과학』 20쪽

"대표적인 반정형 데이터로는 XML(eXtensible Markup Language)과 JSON(JavaScript Object Notation)이 있다." (20쪽)

"이러한 반정형 데이터는 데이터 구조를 쉽게 변경할 수 있고, 필요한 경우 표 형태로도 쉽게 변환할 수 있어 데이터 공유에 많이 활용된다." (20쪽)

→ 오늘 KOBIS가 돌려주는 응답이 바로 이 JSON이다. "표로 쉽게 변환할 수 있다"는 문장을 실습에서 직접 확인한다.

JSON은 JavaScript Object Notation의 약자입니다. 웹 프로그래밍 언어인 자바스크립트에서 데이터를 적던 표기법이 언어와 무관한 공용 형식으로 자리 잡은 것으로, 오늘날 대부분의 API가 이 형식으로 응답합니다. 생김새는 {"라벨": 값} 짝으로 이루어진 상자입니다. 상자 안에 상자를 넣을 수 있어서, 복잡한 데이터도 층층이 담을 수 있습니다. 오늘 우리 앱이 받게 될 실제 응답의 일부를 봅니다 — 이 교재를 만들던 날(2026년 8월 25일 조회)의 진짜 데이터입니다.

실제 응답 (일부 발췌)
{
  "boxOfficeResult": {
    "boxofficeType": "일별 박스오피스",
    "showRange": "20260825~20260825",
    "dailyBoxOfficeList": [
      {
        "rank": "1",
        "movieNm": "오디세이",
        "openDt": "2026-08-05",
        "audiCnt": "164382",
        "audiAcc": "7460311",
        "scrnCnt": "1917"
      },
      { "rank": "2", "movieNm": "스파이더맨: 브랜드 뉴 데이", … },
      { "rank": "3", … }
    ]
  }
}
  • 값 꺼내기 = 라벨을 따라 들어가기 — 겉상자 boxOfficeResult 안에서 dailyBoxOfficeList 목록을 꺼내면, 영화 한 편이 상자 하나씩 들어 있습니다. 그 상자에서 movieNm(영화명)·audiCnt(그날 관객수)를 꺼내는 식입니다. "상자에서 상자를 꺼내라"고 말할 수 있으면 JSON을 읽을 수 있습니다.
  • 👀 눈여겨볼 것 — 숫자가 따옴표에 싸여 있다. "audiCnt": "164382" — 16만 명이 넘는 관객수가 숫자가 아니라 따옴표 친 글자로 옵니다. 글자인 채로 정렬하면 사전순이 되어 "9"가 "164382"보다 커집니다. 크기 비교·정렬·그래프 전에 숫자로 바꾸는 한 단계가 꼭 필요합니다.
  • 표로 바꾸면 정형이 된다 — dailyBoxOfficeList의 상자 하나가 표의 행 하나가 됩니다. 교과서 20쪽의 "필요한 경우 표 형태로도 쉽게 변환할 수 있다"가 바로 이 작업입니다.

3. API — 요청과 응답의 약속

이 JSON은 누가, 어떻게 보내 줄까요? 보내 주는 통로가 API입니다. API는 Application Programming Interface의 약자로, 프로그램(application)끼리 기능과 데이터를 주고받도록 정해 둔 접점(interface)이라는 뜻입니다. 지도 앱이 지도 데이터를 받아 오고, 쇼핑 앱의 결제 버튼이 카드사와 통신하는 것이 전부 API를 통한 일입니다. 이 수업에서 다루는 것은 그중 데이터를 요청해 받는 API이고, 한 문장으로 줄이면 정해진 주소로 조건을 담은 요청을 보내면, 정해진 양식(JSON)의 응답을 돌려주기로 한 약속입니다. 내 앱이 KOBIS 서버에 "어제의 박스오피스"를 요청하면, 서버는 약속된 형식으로 순위 데이터를 돌려줍니다. 서버 내부에서 무슨 일이 일어나는지는 몰라도 됩니다 — 약속(요청 형식과 응답 형식)만 알면 데이터를 받을 수 있습니다. API를 이루는 네 가지는 다음과 같습니다.

🔬 움직여 보기 — 요청과 응답, 클릭으로 한 단계씩

내 앱이 박스오피스 데이터를 받아 오는 과정입니다. 그림을 클릭할 때마다 한 단계씩 움직입니다 — ①요청 만들기 → ②서버로 보내기 → ③응답(JSON) 만들기 → ④응답 받기.

응답에는 상태코드라는 세 자리 숫자 코드가 함께 옵니다. 셋만 기억하면 됩니다 — 200 성공 · 404 없음(주소가 틀렸거나 없는 자료) · 429 과다 요청(호출이 너무 잦음 — 잠깐 쉬기).

내려받기와 API는 무엇이 다를까요? 1차시에 쓴 기온 CSV는 그 시점의 복사본입니다. 내일 기록이 늘어나도 내 파일은 모릅니다. API는 호출할 때마다 서버가 지금 가진 데이터를 보내 주므로 항상 최신이고, 날짜 같은 조건을 지정해 필요한 만큼만 받을 수 있습니다.

4. 주소창 맨눈 보기 — 약속의 실물 확인

코드를 쓰기 전에, API가 정말 "주소에 조건을 담아 보내면 JSON으로 답하는 약속"인지 브라우저로 확인합니다. 클래스룸에서 받은 키를 아래 상자에 붙여 넣으면 어제 날짜가 채워진 완성 주소가 만들어집니다. 그 전에, 요청 주소 자체를 해부해 봅니다.

요청 주소의 해부 — 한 줄에 실려 가는 구성 요소
https://www.kobis.or.kr/kobisopenapi/webservice/rest/boxoffice/searchDailyBoxOfficeList.json
                                                  ↑ 어디에 — 요청 URL
?key=발급받은 인증키                              ← 누가 — 🔑 인증키 (6절)
&targetDt=20260825                                ← 조건 — 날짜. 이 값을 바꾸면 응답이 그날 것으로 바뀐다
§3 표의 구성 요소(요청 URL·조건·인증키)가 주소 한 줄에 모두 실려 간다. 응답만 JSON으로 돌아온다.
🔗 주소 만들기 — 클래스룸에서 받은 키를 붙여 넣기만 하세요
키를 붙여 넣으면, 어제 날짜가 채워진 완성 주소가 여기 나타납니다
↗ 새 탭에서 열어 보기
키는 이 화면 안에서만 쓰이고 어디에도 저장·전송되지 않습니다 · 날짜는 한국 시간 기준 어제로 자동 계산 · 아래 6절의 비밀 금고(Secrets) 예시에도 이 키가 자동으로 채워집니다

새 탭에 화면 가득 글자 덩어리(JSON)가 뜨면 성공입니다. 한 줄로 뭉쳐 보여도 정상입니다. 중괄호와 따옴표 사이에서 다음을 찾아보세요.

  • 겉상자와 목록 — boxOfficeResult 안의 dailyBoxOfficeList. 영화 한 편이 상자 하나입니다. 2절에서 본 구조 그대로인지 확인합니다.
  • 따옴표 친 숫자 — audiCnt(그날 관객수)의 값이 따옴표에 싸여 있습니다. 실습에서 이 함정을 프롬프트로 미리 막습니다.
  • 날짜 조건을 바꾸면 — 주소 속 targetDt의 여덟 자리를 다른 날로 고쳐 다시 접속하면 응답이 그날 것으로 바뀝니다. 같은 주소, 다른 조건입니다.
⚠️ 날짜의 약속 — 가장 늦은 조회일은 어제

조회 날짜(targetDt)는 하이픈 없는 여덟 자리 숫자(예: 20260825)로 적습니다. 그리고 오늘 날짜를 넣으면 오류가 아니라 빈 목록이 옵니다 — 오늘 관객수는 아직 집계 전이기 때문입니다. 가장 늦게 조회할 수 있는 날은 어제입니다. "응답이 비어 있다 = 고장"이 아니라는 것, 오늘 여러 번 확인하게 됩니다.

💡 뭔가 이상한 응답이 왔다면 — 그대로 AI에게

키를 잘못 붙여 넣는 등의 이유로 순위표 대신 낯선 오류 안내가 올 수 있습니다. 원인을 외울 필요는 없습니다 — 화면에 뜬 내용을 통째로 복사해 AI에게 붙여넣고 "무엇이 문제냐"고 물으면 됩니다. 오류를 다루는 것도 바이브 코딩의 일부입니다.

5. API 문서 읽는 법 — 다 읽지 않아도 됩니다

오늘 실습 프롬프트의 끝에는 "공식 문서에서 복사한 부분"이 붙어 있습니다. 그 발췌가 어디서 왔는지, 문서를 직접 열어 봅니다. KOBIS 오픈API 홈페이지는 영화진흥위원회가 전국 극장의 매출·관객 집계를 누구나 프로그램으로 받아 갈 수 있게 공개한 곳입니다 — 예매 앱과 뉴스의 박스오피스도 결국 이 집계에서 나옵니다.

  1. 문서까지 가는 길
    홈페이지 상단 메뉴에서 OPEN API를 누르면 제공서비스 목록이 나옵니다. 왼쪽 목록에서 일별 박스오피스를 고르면 오늘 쓰는 API의 문서가 열립니다.
  2. 문서의 생김새
    문서는 네 부분입니다 — 1. REST 방식(기본 요청 URL) · 2. SOAP 방식 · 3. 인터페이스(요청 인터페이스 표와 응답 구조 표) · 4. 응답 예시. 빽빽해 보여도 우리가 읽을 곳은 정해져 있습니다.
  3. 볼 곳은 세 곳
    어디무엇을일별 박스오피스에서는
    ① 기본 요청 URL (1번 항목)어느 주소로 요청하는가 — 끝을 .json으로…/searchDailyBoxOfficeList.json
    ② 요청 인터페이스 표 (3번 항목)필수 표시가 붙은 변수key(발급받은 키) · targetDt(yyyymmdd 여덟 자리) — 나머지(다양성/상업 구분 등)는 조건이 필요할 때만
    ③ 응답 구조 표 (3번 항목)내가 쓸 필드의 진짜 이름rank·movieNm·openDt·audiCnt·audiAcc·scrnCnt…
💡 처음 보면 낯선 말들 — 몰라도 되는 것 먼저

REST와 SOAP은 요청을 주고받는 두 가지 방식의 이름입니다. 요즘 API는 대부분 REST 방식이고, 우리도 REST의 주소만 씁니다 — SOAP·WSDL 줄은 읽지 않고 지나가도 됩니다. 주소 끝의 .xml과 .json은 응답 형식을 고르는 스위치입니다. 우리는 .json을 씁니다.

⚠️ 4번 응답 예시 링크를 눌러 보면 — 익숙한 상자가 뜹니다

문서 끝의 응답 예시에는 보기용 키가 들어간 주소가 있는데, 보기용 키가 만료되어 지금 누르면 오류 안내가 옵니다. 주소의 key= 값을 내 키로 바꾸면 실물 응답이 뜹니다.

✔️ 바이브 코딩의 문서 활용법 — 이해가 아니라 복사

문서를 다 이해한 뒤 옮겨 적는 것이 아닙니다. 위의 세 곳을 마우스로 긁어 그대로 복사해, 프롬프트 맨 끝에 붙입니다. AI는 이 API의 문서를 읽은 적이 없어서 필드 이름을 지어내기도 하는데, 문서 발췌를 붙여 주면 실제 이름으로 코드를 씁니다. 오늘 ① 프롬프트의 "──── 아래는 KOBIS 공식 문서에서 복사한 부분 ────"이 바로 그렇게 만든 것입니다. 처음 보는 API를 만나도 방법은 같습니다 — 5차시에 다른 API의 문서로 직접 해 봅니다.

6. 비밀 금고(secrets) — 키를 코드 밖에 둔다

API 키(인증키)는 서비스가 발급해 주는 긴 무작위 문자열로, 누가 얼마나 쓰는지를 세는 장치입니다. KOBIS 키에는 하루 3,000회의 호출 한도가 있습니다. 오늘은 선생님이 발급한 공용 키를 나눠 씁니다 — 클래스룸에 비공개로 게시된 키를 복사해 쓰고, 코드에는 절대 붙여 넣지 않습니다. 코드에 적은 채 공개 저장소에 올리는 순간 남이 내 이름으로 호출하고, 그 사용량과 책임은 내 몫이 됩니다.

키가 갈 곳은 코드가 아니라 스트림릿의 비밀 금고(secrets)입니다. 넣는 절차는 세 걸음입니다.

  1. 내 앱의 관리 화면 열기
    배포된 내 앱 오른쪽 아래의 Manage app을 누르고, 메뉴(⋮)에서 Settings를 엽니다.
  2. Secrets에 키 저장
    Secrets 칸에 다음 한 줄을 적고 저장합니다. 등호 왼쪽이 이름, 오른쪽 따옴표 안이 선생님이 준 키입니다.
    Secrets에 넣을 한 줄 (4절 상자에 키를 붙여 넣었다면 이미 채워져 있음)
    KOBIS_KEY = "선생님이 준 키를 여기에"
  3. 저장 — 앱이 스스로 다시 시작
    저장하면 앱이 자동으로 다시 시작됩니다. 화면이 잠깐 깜빡여도 고장이 아닙니다.
⚠️ 이름 세 곳 일치 — 하나라도 다르면 못 찾는다

키의 이름 KOBIS_KEY는 세 곳에 등장합니다. 세 곳의 철자가 한 글자까지 똑같아야 합니다. 대문자·밑줄까지 다르면 앱은 금고에서 키를 찾지 못하고 멈춥니다(KeyError).

어디어떤 모습
① 비밀 금고(Secrets)KOBIS_KEY = "…" — 방금 저장한 한 줄
② 프롬프트"비밀 금고(secrets)의 KOBIS_KEY에서 불러와" — AI에게 알려 주는 이름
③ AI가 준 코드st.secrets["KOBIS_KEY"] — 코드가 금고에서 찾는 이름

7. 실습 — 어제의 박스오피스 대시보드 (①②③)

준비가 끝났습니다. 1차시처럼 프롬프트를 통째로 붙여 넣고, AI가 준 코드로 앱의 main.py를 교체해 커밋합니다. 프롬프트 끝에 KOBIS 공식 문서에서 복사한 부분이 붙어 있는 것을 눈여겨보세요 — 문서를 함께 주면 AI가 라벨 이름을 지어내지 못합니다.

  1. ① 샘플 프롬프트 — 그대로 붙여 넣기
    ① 프롬프트
    어제의 박스오피스를 보여 주는 스트림릿 앱 하나(main.py)를 만들어 줘. 스트림릿 클라우드에 올릴 거야.
아래에 공식 API 문서에서 복사한 내용을 붙였어.

- 인증키는 비밀 금고(secrets)의 KOBIS_KEY에서 불러와. 코드에는 절대 쓰지 마.
- 조회 날짜는 고정하지 말고 '어제'를 자동으로 계산해서 써. 오늘 건 아직 집계 전이거든.
  '어제'는 한국 시간 기준이야. 배포 서버 시계는 한국 시간이 아니야.
- 순위·영화명·개봉일·관객수·누적관객·스크린수를 표로 보여 줘.
- 1위 영화는 지표 카드 세 장으로 크게, 관객수 상위 5편은 막대그래프로.
- 숫자가 글자로 오니 숫자로 바꿔서 정렬과 그래프에 써 줘.
- 같은 날짜를 다시 물으면 API를 또 부르지 말고, 불러온 결과를 한 시간쯤 기억해 줘.
- 요청이 실패하거나, 오류 상자(faultInfo)가 오거나, 영화 목록이 비어서 올 때는
  빈 화면 대신 무엇을 확인해야 하는지 한국어로 안내해 줘.
- 필요한 라이브러리 목록(requirements.txt)도 같이 줘. 버전 숫자 없이 이름만.
- 초보자용 한국어 주석을 달고 main.py 전체 코드를 한 번에 줘.

요청 주소: https://www.kobis.or.kr/kobisopenapi/webservice/rest/boxoffice/searchDailyBoxOfficeList.json
요청변수: key(발급받은 인증키) · targetDt(조회 날짜, yyyymmdd 여덟 자리)
응답 구조: boxOfficeResult 안의 dailyBoxOfficeList 목록에 영화별로
  rank(순위) · rankInten(전날 대비 순위 증감) · movieNm(영화명) · openDt(개봉일) ·
  audiCnt(그날 관객수) · audiAcc(누적 관객수) · scrnCnt(스크린수) · showCnt(상영횟수)
  ※ 숫자 값이 전부 문자열로 온다.
  ※ 인증키가 틀려도 상태코드는 200이고, 대신 faultInfo 상자가 온다.
  2. ② AI가 준 코드 예시 — 이런 모습이면 성공
    AI가 준 main.py로 교체해 커밋하면 앱이 다시 배포됩니다. 아래는 실제로 실행해 확인한 코드 예시입니다. 여러분 코드가 글자까지 같지 않아도 됩니다 — 어제 날짜의 순위표·지표 카드·막대그래프가 나타나면 성공입니다. 이 교재를 만들던 날에는 1위 자리에 「오디세이」(어제 관객수 164,382명)가 떠 있었습니다. 여러분 화면의 1위는 여러분의 어제가 정합니다.
    ② AI가 준 코드 예시 — 
    # 어제의 박스오피스 — KOBIS 일별 박스오피스 API
import datetime

import pandas as pd
import plotly.express as px
import requests
import streamlit as st

st.set_page_config(page_title="어제의 박스오피스", page_icon="🎬", layout="wide")

# 인증키는 비밀 금고(secrets)에서 불러온다 — 코드에 직접 쓰지 않는다
API_KEY = st.secrets["KOBIS_KEY"]
URL = "https://www.kobis.or.kr/kobisopenapi/webservice/rest/boxoffice/searchDailyBoxOfficeList.json"

# '어제'를 한국 시간 기준으로 계산한다 (배포 서버의 시계는 한국 시간이 아니다)
KST = datetime.timezone(datetime.timedelta(hours=9))
yesterday = datetime.datetime.now(KST).date() - datetime.timedelta(days=1)
target_dt = yesterday.strftime("%Y%m%d")


@st.cache_data(ttl=3600)  # 같은 날짜는 한 시간 동안 기억해 두고 API를 다시 부르지 않는다
def fetch_boxoffice(date_str):
    """KOBIS API에서 해당 날짜의 일별 박스오피스를 받아 온다."""
    params = {"key": API_KEY, "targetDt": date_str}
    res = requests.get(URL, params=params, timeout=10)
    res.raise_for_status()
    return res.json()


st.title("🎬 어제의 박스오피스")
st.caption(f"조회 날짜: {yesterday} (한국 시간 기준 어제)")

try:
    data = fetch_boxoffice(target_dt)
except requests.RequestException:
    st.error("서버에 연결하지 못했습니다. 인터넷 연결을 확인하고 잠시 뒤 새로고침해 주세요.")
    st.stop()

# 인증키가 틀리면 상태코드는 200이지만 faultInfo 상자가 온다
if "faultInfo" in data:
    st.error(f"API가 오류를 돌려주었습니다: {data['faultInfo'].get('message', '')}")
    st.info("비밀 금고(secrets)의 KOBIS_KEY 값이 올바른지 확인해 주세요.")
    st.stop()

movies = data.get("boxOfficeResult", {}).get("dailyBoxOfficeList", [])

# 영화 목록이 비어서 오면 — 아직 집계 전인 날짜다
if not movies:
    st.warning("영화 목록이 비어 있습니다. 아직 집계 전인 날짜는 아닌지 확인해 주세요.")
    st.stop()

df = pd.DataFrame(movies)

# 숫자가 글자로 오므로 숫자로 바꿔야 정렬과 그래프에 쓸 수 있다
for col in ["rank", "audiCnt", "audiAcc", "scrnCnt"]:
    df[col] = pd.to_numeric(df[col])

# 1위 영화는 지표 카드 세 장으로 크게
top = df.sort_values("rank").iloc[0]
st.subheader(f"🥇 1위 — {top['movieNm']}")
c1, c2, c3 = st.columns(3)
c1.metric("어제 관객수", f"{top['audiCnt']:,}명")
c2.metric("누적 관객수", f"{top['audiAcc']:,}명")
c3.metric("스크린수", f"{top['scrnCnt']:,}개")

# 전체 순위표
st.subheader("📋 어제의 순위표")
table = df.sort_values("rank")[["rank", "movieNm", "openDt", "audiCnt", "audiAcc", "scrnCnt"]]
table.columns = ["순위", "영화명", "개봉일", "관객수", "누적관객", "스크린수"]
st.dataframe(table, hide_index=True, width="stretch")

# 관객수 상위 5편은 막대그래프로
st.subheader("📊 관객수 상위 5편")
top5 = df.sort_values("audiCnt", ascending=False).head(5)
fig = px.bar(top5, x="movieNm", y="audiCnt", labels={"movieNm": "영화명", "audiCnt": "어제 관객수"})
st.plotly_chart(fig, width="stretch")

    🧰 requirements.txt — 내 앱이 쓰는 도구 목록

    requirements.txt는 내 앱이 쓰는 라이브러리 이름을 한 줄에 하나씩 적은 파일입니다. 스트림릿 클라우드는 배포할 때 이 목록을 보고 라이브러리를 설치합니다 — 목록에 없는 라이브러리를 코드가 쓰면 앱이 ModuleNotFoundError로 멈춥니다. 오늘 코드는 그래프를 그리는 plotly와 API를 부르는 requests를 쓰므로 위 목록이 필요합니다. 고치는 방법은 main.py와 같습니다 — 깃허브 저장소에서 requirements.txt를 열어 연필 아이콘으로 편집하고 커밋하면 앱이 다시 배포됩니다. ① 프롬프트에 "requirements.txt도 같이 줘"라는 줄이 들어 있는 이유가 이것입니다. AI가 코드와 함께 도구 목록까지 만들어 주면, 여러분은 두 파일을 나란히 올리기만 하면 됩니다.

  3. ③ 프롬프트 개선 — 같은 대화창에서 이어서
    ③ 개선
    좋아, 여기서 이어서 고쳐 줘.
- 날짜를 어제로 고정하지 말고, 달력에서 골라 그날의 박스오피스를 볼 수 있게 해 줘.
  고를 수 있는 가장 늦은 날짜는 어제까지야. 오늘 건 아직 집계 전이니까.
- 고른 날짜에 영화 목록이 비어서 오면 "그날은 아직 집계 전입니다"라고 알려 줘.
- 문서를 보니 rankInten이라는 값이 전날 대비 순위 증감이래. 양수면 순위가 오른 것, 음수면 내린 것.
  표에서 오른 영화는 빨간 위 화살표, 내린 영화는 파란 아래 화살표를 붙여 줘.
- 누적관객이 100만 명을 넘은 영화는 영화명 옆에 트로피 이모지를 붙여 줘.
    ③이 "좋아, 여기서 이어서 고쳐 줘."로 시작하는 것을 눈여겨보세요. 새 대화를 열지 않고 같은 대화창에서 잇는 것이 개선의 요령입니다 — AI가 방금 준 코드를 기억한 채로 고칩니다.
✅ 여기까지 되었는지 확인
  • 어제 날짜의 순위표·1위 지표 카드·상위 5편 막대그래프가 내 앱에 나타난다.
  • 인증키가 코드 안에 보이지 않는다 — 비밀 금고(secrets)에서 읽어 온다.
  • ③ 개선까지 반영해 달력으로 날짜를 고를 수 있다.
⚠️ 발견 — 내려받지 않았는데 어제의 극장이 내 앱에 있다

화면에 뜬 순위표는 내 컴퓨터 어디에도 파일로 존재하지 않습니다. 앱이 실행될 때마다 KOBIS 서버에 요청을 보내고 응답을 받아 표시한 것입니다. 그리고 이 숫자는 검증할 수 있습니다 — 오늘 저녁, 포털에서 "박스오피스"를 검색해 내 앱의 순위표와 대조해 보세요. 같은 데이터에서 온 같은 숫자를 확인하게 됩니다. 대조한 화면은 과제로 제출합니다(스크린샷).

8. 개념 정리

오늘 배운 것을 한 줄로 줄이면 이렇습니다. API는 정해진 주소로 조건을 보내면 정해진 양식(JSON)으로 답하는 약속이고, JSON은 라벨 붙은 상자라서 표로 바꿔 쓸 수 있다. 정형(표)·반정형(JSON)·비정형(사진)을 구분했고, 키는 코드가 아니라 비밀 금고에 둔다는 습관을 시작했습니다. 다만 오늘 받은 것은 어제 하루치뿐입니다. "이 영화는 뜨는 중인가, 지는 중인가"에 답하려면 여러 날을 쌓은 표가 필요합니다 — 다음 시간에 354일 치 축적 표로 그 질문을 엽니다.

9. 확인 문제

문제 1 다음을 정형·반정형·비정형으로 구분해 보세요. 답을 눌러 확인합니다.
(가) KOBIS가 보내 준 어제의 박스오피스 JSON 응답
"라벨": 값의 구조는 있지만 표는 아니고 구조를 바꿀 수 있음 — 반정형입니다.
(나) 1차시에 쓴 서울 기온 CSV 파일
행과 열로 속성과 구조가 명확한 표 — 정형입니다.
(다) 영화 포스터 이미지
구조를 명확하게 정의하기 어려운 이미지 — 비정형입니다.
문제 2 응답 속 관객수가 "audiCnt": "164382"처럼 따옴표에 싸여 옵니다. 이대로 정렬하면 무슨 일이 생기고, 무엇을 해야 할까요?
글자 "9"는 사전순으로 "164382"보다 뒤에 오므로, 글자인 채 정렬하면 9명이 16만 명을 이기는 순위표가 됩니다. 계산·정렬·그래프에 쓰려면 숫자로 바꾸는 한 단계가 필요합니다. ① 프롬프트의 "숫자가 글자로 오니 숫자로 바꿔서 써 줘"가 이 함정을 미리 막은 문장입니다.
문제 3 1차시에는 기온 데이터를 파일로 내려받아 썼고, 오늘은 박스오피스를 API로 받았습니다. API로 받는 방식의 좋은 점으로 알맞은 것은?
내려받은 파일은 그 시점의 복사본으로 멈춰 있습니다. API는 호출할 때마다 최신이고, 조건(날짜 등)으로 필요한 만큼만 받습니다. 어느 쪽이 좋은가는 질문에 달려 있습니다 — 100년 치 역사가 필요하면 파일이, 어제의 순위가 필요하면 API가 맞습니다.

🎒 오늘의 체크

  • 정형·반정형·비정형을 각각 예를 들어 구분할 수 있다.
  • 주소창에서 KOBIS의 JSON 원문을 열어 상자 구조와 따옴표 친 숫자를 찾았다.
  • 키를 비밀 금고(secrets)에 넣었고, 이름 세 곳(금고·프롬프트·코드)이 일치해야 하는 이유를 말할 수 있다.
  • 어제의 박스오피스 대시보드를 배포했고, 오늘 저녁 포털 순위와 대조할 준비가 되었다.
