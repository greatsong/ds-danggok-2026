우리 학교 급식 월드컵 · 만들고, 모으고, 세어 보기

"빨리 가려면 혼자 가고, 멀리 가려면 함께 가라."
속담 — 오늘 데이터가 '내 파일'에서 '우리의 저장소'가 됩니다

“친구들이 가장 좋아하는 반찬은 무엇일까?” 오늘은 급식 월드컵 앱을 만듭니다. 두 반찬 가운데 하나를 고르는 대결을 일곱 번 치러 우승 반찬을 가리고, 학급의 대결 기록을 모아 분석합니다. 13차시에서 읽기만 했던 테이블에 이번에는 우리 손으로 행을 쌓습니다. 공통 수업의 마지막 시간이며, 뒤이어 시작할 팀 프로젝트의 팀과 주제도 오늘 정합니다.

오늘 모으는 대결 기록은 지금까지 쌓인 데이터입니다. 친구들이 판을 치를 때마다 표에 행이 늘어나므로, 화면에 나오는 대결 수와 승률은 사람마다, 시간마다 다릅니다. 숫자가 다른 것은 잘못이 아니며, 그 숫자를 어떻게 읽을지가 오늘의 과제입니다.

🎯 오늘 하는 순서
  • ① 만들기 — 프롬프트를 붙여 넣어 급식 월드컵 앱을 받는다
  • ② 한 판 — 여덟 반찬으로 토너먼트를 치르고 일곱 행을 쌓는다
  • ③ 모으기 — 학급의 기록이 한 테이블에 합쳐졌는지 확인한다
  • ④ 세어 보기 — 반찬별 승리 수와 승률을 구해 순위를 읽는다
  • ⑤ 팀 짜기 — 프로젝트 팀을 구성하고 주제 후보를 고른다

0. 오늘의 목표

13차시에서 SQL 문장이 무엇을 하는지 읽었습니다. 오늘은 그 문장이 실제로 실행되는 자리를 만듭니다. 순서는 이렇습니다 — 앱을 만들고 → 한 판을 치르고 → 학급 기록이 모이는지 확인하고 → 승률을 세어 봅니다. 그러고 나면 팀을 짜고 프로젝트 주제를 고릅니다.

  • 프롬프트로 급식 월드컵 앱을 만들어 대결 기록을 테이블에 저장할 수 있다.
  • 학급이 함께 쌓은 기록에서 승리 수와 승률을 구하고, 두 순위가 갈리는 까닭을 분모로 설명할 수 있다.
  • 팀의 주제 후보를 데이터가 충분히 있는가·문제 해결에 적합한가·윤리적으로 사용할 수 있는가 세 물음으로 판단할 수 있다.

1. 따라 만들기 — 급식 월드컵 앱

🧩 무엇이 한 행이 되나

한 판은 8강 네 번, 4강 두 번, 결승 한 번으로 일곱 번을 고릅니다. 대결 한 번이 한 행이므로 한 판을 마치면 테이블에 일곱 행이 쌓입니다. 열은 일곱 개뿐입니다 — id · game_id · round · left_menu · right_menu · winner · created_at. 이름·학번·비밀번호는 받지 않습니다.

좋아하는 급식 반찬을 1대1로 겨루는 8강 토너먼트를 만듭니다. 아래 ① 프롬프트를 그대로 붙여 넣으면 앱이 나옵니다. 받은 코드를 실행해 한 판을 치르고, 학급의 기록이 한곳에 모이는지 확인한 뒤, ③ 프롬프트로 분석 화면을 붙입니다.

후보 여덟 가지는 어떻게 골랐나 — 5차시 급식 API 집계

5차시에서 배운 급식 API 집계 방법을 적용하여 후보를 선정합니다. 조회 기간은 2025년 9월부터 2026년 9월까지이며, 중식 184일 동안의 데이터를 대상으로 합니다. 밥과 김치, 국, 곁반찬, 후식을 걸러 낸 뒤 남은 주요리 가운데 자주 나온 여덟 가지를 후보로 정합니다. 아래 후보는 수업에 사용할 목록으로 고정합니다. 같은 기간을 다시 조회해도 원데이터가 수정되거나 반찬 이름 정리·제외 기준이 다르면 결과가 달라질 수 있으므로, 비교할 때는 같은 저장본과 처리 기준을 사용합니다.

💡 수파베이스 — 우리가 쓸 데이터베이스

Supabase는 PostgreSQL 데이터베이스와 API·인증 등의 기능을 제공합니다. 13차시에 문장으로만 읽었던 테이블을 이번에는 실제로 만들어 씁니다. 다만 테이블을 만드는 일은 교사 또는 모둠 대표 한 명이 하고, 다른 학생은 같은 프로젝트에 연결합니다. 그래야 여러 기기에서 보낸 대결 기록이 한곳에 모입니다.

🔧 준비 — 테이블과 접속 정보

실습에 앞서 대결 기록을 담을 테이블과 접속 정보가 준비되어 있어야 합니다. 이 준비는 교사 또는 모둠의 준비 담당자가 한 번만 하며, 절차는 준비 안내에 따로 정리해 두었습니다. 나머지 학생은 준비된 접속 정보와 배포된 앱 주소를 받아 아래 ① 프롬프트부터 시작합니다.

  1. ① 샘플 프롬프트 — 그대로 붙여 넣기
    ① 프롬프트
    급식 월드컵 스트림릿 앱을 만들어 줘. 파일 이름은 main.py 하나로.
후보는 제육볶음·간장찜닭·가자미순살튀김·돈육불백·미트볼데리야끼볶음·수육·진미채고추장볶음·치즈떡닭갈비 여덟 가지야.
8강 토너먼트로 진행해 줘. 판을 시작할 때 후보 순서를 섞고, 두 반찬을 나란히 보여 준 뒤 하나를 고르게 해.
이긴 반찬만 다음 라운드로 올려서 8강 네 번, 4강 두 번, 결승 한 번으로 모두 일곱 번 고르게 해 줘.
이름·학번·비밀번호는 받지 마.
반찬 이름은 한글이니까 저장하고 읽을 때 UTF-8로 다뤄서 글자가 깨지지 않게 해 줘.
서로 다른 두 후보 중 하나를 골랐을 때만, 교사가 준비한 표에 대결을 한 행씩 저장해 줘.
표 이름은 menu_duels이고 public 스키마에 있어. 표 이름에 스키마 이름을 붙여 쓰지는 마.
이 표의 열 이름은 id, game_id, round, left_menu, right_menu, winner, created_at 일곱 가지야.
id는 자동으로 늘어나는 정수이고 created_at은 저장 시각이 기본값이라 앱이 넣지 않아.
앱이 채우는 열은 game_id(한 판을 묶는 문자열), round('8강'·'4강'·'결승' 가운데 하나), left_menu, right_menu, winner 다섯이고 모두 문자열이야.
새 표를 만들지 말고 이 표에 그대로 연결해 줘. 수정·삭제 기능은 넣지 마.
접속 정보는 비밀 금고(secrets)의 SUPABASE_URL과 SUPABASE_KEY에서 읽어 줘.
판이 끝나면 우승 반찬을 보여 주고, 다시 시작하는 버튼을 넣어 줘.
저장 결과를 확인하지 못하면 대결을 진행하지 말고 재선택을 잠근 뒤 확인이 필요하다고 안내해 줘.
필요한 라이브러리 목록(requirements.txt)도 같이 줘. 버전 숫자 없이 이름만.
    준비 확인 — 만든 표의 열과 행 수 읽기

    표 생성은 준비 안내의 SQL로 한 번만 합니다. 아래는 생성 뒤 확인하는 조회 코드입니다.

WHERE table_schema = 'public' AND table_name = 'menu_duels'
ORDER BY ordinal_position;
SELECT COUNT(*) AS 대결기록수 FROM public.menu_duels;
  2. ② AI가 준 코드 — 한 판을 끝까지 해 본다
    배포한 뒤 한 판을 끝까지 진행합니다. 8강 네 번, 4강 두 번, 결승 한 번으로 일곱 번을 고르면 우승 반찬이 나옵니다. 표에는 일곱 행이 쌓입니다. 두 번째 판을 시작하면 대진표가 다시 섞여 다른 상대를 만납니다.
    실습용 예시 코드

    main.py와 requirements.txt, 두 파일로 저장합니다. 실제 공유 저장은 준비 안내 4절의 두 기기 확인 절차로 점검합니다.

    main.py
    # main.py — 급식 월드컵 8강. 대결 한 번이 표의 한 행이 된다.
import random
import uuid

import streamlit as st
from supabase import create_client

MENUS = ["제육볶음", "간장찜닭", "가자미순살튀김", "돈육불백",
         "미트볼데리야끼볶음", "수육", "진미채고추장볶음", "치즈떡닭갈비"]
ROUND = {8: "8강", 4: "4강", 2: "결승"}

st.header("🏆 급식 월드컵")
st.caption("이름 없이 참여하는 연습 게임입니다. 대결 기록 수는 참여 인원과 다릅니다.")


@st.cache_resource
def connect():
    return create_client(st.secrets["SUPABASE_URL"], st.secrets["SUPABASE_KEY"])


try:
    db = connect()
except Exception:
    st.error("연결 정보를 확인하세요. 선생님이 표와 권한을 준비한 뒤 연결합니다.")
    st.stop()


def new_game():
    order = MENUS[:]
    random.shuffle(order)                      # 대진표를 판마다 섞는다
    st.session_state.game_id = uuid.uuid4().hex
    st.session_state.queue = order             # 이번 라운드에서 겨룰 차례
    st.session_state.winners = []              # 이번 라운드에서 이긴 반찬
    st.session_state.size = len(order)         # 이번 라운드의 크기 (8·4·2)
    st.session_state.save_pending = False


if "queue" not in st.session_state:
    new_game()

# 이번 라운드가 끝났으면 다음 라운드를 준비한다
if not st.session_state.queue and len(st.session_state.winners) > 1:
    st.session_state.queue = st.session_state.winners
    st.session_state.winners = []
    st.session_state.size = len(st.session_state.queue)

def choose(winner, left, right, round_name):
    st.session_state.save_pending = True
    try:
        db.table("menu_duels").insert({
            "game_id": st.session_state.game_id,
            "round": round_name,
            "left_menu": left,
            "right_menu": right,
            "winner": winner,
        }).execute()
    except Exception:
        # 통신 오류여도 DB에는 저장되었을 수 있어 재제출을 잠근다
        st.rerun()
    st.session_state.save_pending = False
    st.session_state.winners.append(winner)
    st.session_state.queue = st.session_state.queue[2:]
    st.rerun()


if not st.session_state.queue:                 # 결승까지 끝났다
    st.success("우승: " + st.session_state.winners[0])
    if st.button("다시 하기"):
        new_game()
        st.rerun()
else:
    left, right = st.session_state.queue[0], st.session_state.queue[1]
    round_name = ROUND[st.session_state.size]
    st.subheader(round_name)
    if st.session_state.save_pending:
        st.warning("저장 결과를 확인하지 못했습니다. 재선택을 잠갔습니다. 선생님에게 확인하세요.")
    col_l, col_r = st.columns(2)
    if col_l.button(left, use_container_width=True, disabled=st.session_state.save_pending):
        choose(left, left, right, round_name)
    if col_r.button(right, use_container_width=True, disabled=st.session_state.save_pending):
        choose(right, left, right, round_name)

st.caption("판 번호: " + st.session_state.game_id)
st.caption("반복 참여를 막지는 않습니다. 저장 결과 확인이 필요하면 이 판 번호를 준비 담당자에게 알려 주세요.")

  3. ③ 개선 프롬프트 — 학급의 대결 기록을 분석한다

    한 판이 끝나면 우승 반찬 하나가 남습니다. 우승만으로는 그 반찬이 정말 인기 있는지 알 수 없습니다. 토너먼트에서는 이긴 반찬만 다음 라운드로 올라갑니다. 그 결과 다음 라운드에 진출한 반찬은 겨룬 횟수가 많아집니다. 승리 수와 함께 이긴 횟수를 겨룬 횟수로 나눈 비율인 승률을 살펴봅니다. 승률도 상대와 대진표의 영향을 받으므로 학급 전체의 선호 비율로 해석하지 않습니다.

    ③ 개선
    이 앱에 학급 전체의 대결 기록을 분석하는 화면을 추가해 줘.
menu_duels에 저장된 전체 기록을 대상으로 해. id, game_id, round, left_menu, right_menu, winner 여섯 열을 읽어서 반찬별 대결 수·승리 수·승률·우승 횟수를 비교하게 해 줘.
대결 수는 left_menu와 right_menu 양쪽을 모두 세고, 우승 횟수는 round가 '결승'인 행의 winner를 세어 줘.
모든 후보를 표시하고 대결 기록이 없는 후보의 승률은 아직 알 수 없다고 안내해 줘.
승률은 백분율로 보여 주고 높은 순서의 표와 가로 막대그래프로 비교해 줘.
그래프는 plotly로 그려 줘.
집계에 사용한 대결 기록 수와 판 수를 화면에 적어 줘. 기록 수와 참여 인원은 다르며, 진행 중에 남긴 대결도 집계에 들어간다고 표시해 줘.
한 판이 끝난 화면에서도 분석을 볼 수 있게 하고 결과를 다시 불러오는 버튼을 넣어 줘.
기록이 아직 없을 때와 조회에 실패했을 때를 구분해 안내해 줘.
필요한 라이브러리 목록(requirements.txt)도 같이 줘. 버전 숫자 없이 이름만.
    실습용 예시 코드

    앞 코드 끝에 이어 붙입니다. 실제 데이터베이스의 저장·조회 결과는 배포 후 확인합니다.

    main.py에 이어 붙일 부분
    # main.py에 이어 붙일 부분 — 학급의 대결 기록을 분석한다
import pandas as pd
import plotly.express as px

st.divider()
st.subheader("학급 대결 기록")

st.button("결과 새로 불러오기")
try:
    # 조회 시작 때의 마지막 id까지만, 빠짐없이 나누어 읽는다
    latest = db.table("menu_duels").select("id").order("id", desc=True).limit(1).execute().data
    upper = latest[0]["id"] if latest else 0
    records = []
    after = 0
    while after < upper:
        page = (db.table("menu_duels")
                .select("id,game_id,round,left_menu,right_menu,winner")
                .gt("id", after).lte("id", upper).order("id").limit(500).execute().data)
        if not page:
            raise RuntimeError("마지막 기록까지 조회하지 못했습니다.")
        records.extend(page)
        after = page[-1]["id"]
except Exception:
    st.error("기록을 불러오지 못했습니다.")
    st.stop()

if not records:
    st.info("아직 대결 기록이 없습니다.")
    st.stop()

duels = pd.DataFrame(records)
# 겨룬 횟수는 왼쪽과 오른쪽을 모두 센다
fought = pd.concat([duels["left_menu"], duels["right_menu"]]).value_counts()
won = duels["winner"].value_counts()
champion = duels[duels["round"] == "결승"]["winner"].value_counts()

board = pd.DataFrame({"겨룬 횟수": fought, "이긴 횟수": won, "우승": champion}).reindex(MENUS).fillna(0).astype(int)
board["승률(%)"] = (board["이긴 횟수"] / board["겨룬 횟수"].where(board["겨룬 횟수"] > 0) * 100).round(1)
board = board.sort_values("승률(%)", ascending=False).reset_index(names="반찬")

st.caption("대결 " + str(len(duels)) + "번 · 기록이 있는 판 " + str(duels["game_id"].nunique()) + "개")
st.caption("결승 기록이 있는 판 " + str(duels.loc[duels["round"] == "결승", "game_id"].nunique()) + "개 · 진행 중 기록도 포함합니다.")
st.caption("대결이 없는 후보의 승률은 비어 있습니다. 대결 수와 판 수는 참여 인원이 아닙니다.")
st.dataframe(board, hide_index=True, width="stretch")

fig = px.bar(board.dropna(subset=["승률(%)"]).sort_values("승률(%)"), x="승률(%)", y="반찬", orientation="h",
             text="승률(%)", color="승률(%)", color_continuous_scale="Oranges",
             title="반찬별 승률")
fig.update_layout(coloraxis_showscale=False, yaxis_title="")
st.plotly_chart(fig, width="stretch")
st.caption("조회 도중 들어온 새 기록은 다시 불러오면 반영됩니다. 승률은 대진표와 반복 참여의 영향을 받습니다.")

앱 배포와 두 기기 완료 확인 절차는 준비 안내 3·4절에 있습니다. 배포한 앱에서 한 판을 마친 뒤, 학급의 대결 기록이 실제로 합쳐졌는지 그 절차로 확인합니다.

🧩 승률의 분모 — 승리 수와 승률은 다른 숫자입니다

승리 수는 이긴 횟수를 그대로 센 값이고, 승률은 그 승리 수를 겨룬 횟수로 나눈 값입니다. 토너먼트에서는 이긴 반찬만 다음 라운드로 올라가므로 반찬마다 겨룬 횟수가 다릅니다. 8강에서 한 번 지고 끝난 반찬의 분모는 1이고, 결승까지 올라간 반찬의 분모는 3입니다. 분모가 다른 값을 나란히 놓고 비교하면 순위가 뒤집힐 수 있습니다.

  • 겨룬 횟수가 유독 많은 반찬은 무엇입니까? 왜 그 반찬의 분모가 커졌습니까?
  • 겨룬 횟수가 한두 번뿐인 반찬이 있습니까? 그 반찬의 승률 옆에 겨룬 횟수를 함께 적어 둡니다.

3. 정리 — 오늘 만든 것

오늘 여러분이 만든 것은 학급이 함께 쓰는 테이블 하나입니다. 13차시에 문장으로만 읽었던 INSERT와 SELECT가 이 테이블에서 실제로 실행되었습니다. 대결 한 번이 한 행으로 쌓이고, 그 행들을 이긴 쪽 기준으로 묶어 세면 승률표가 나옵니다.

권한 정책 — 허용할 동작을 명시하는 이유

RLS는 활성화된 테이블에서 어떤 행에 접근할 수 있는지 정하는 정책입니다. 일반 앱 역할에는 테이블 권한과 해당 정책이 모두 필요합니다. RLS가 꺼져 있거나 관리자 권한을 사용하면 정책의 보호 범위가 달라집니다. 이번 설계는 로그인 없는 연습용으로 읽기·추가만 허용하며, 누구나 그 권한으로 여러 판을 반복할 수 있다는 한계가 있습니다. 앱의 버튼 숨기기는 DB 권한 검사를 대신하지 못합니다. Supabase RLS 문서에서 원리를 확인할 수 있습니다.

⚠️ 바이브 코딩에서 가장 자주 만나는 DB 오류

연결·저장·조회 오류의 원인은 다를 수 있습니다. 표 이름과 열 이름, 접속 대상, 허용된 동작, RLS 정책을 순서대로 확인합니다. 오류를 없애려고 관리자 키를 넣거나 모든 권한을 열지 말고, 필요한 동작만 교사와 확인합니다.

AI에게 DB를 주문할 때 알려 줄 네 가지

SQL 문장을 직접 쓰지 않더라도, AI가 데이터베이스 코드를 맞게 짜려면 AI가 볼 수 없는 사실을 프롬프트에 적어 주어야 합니다. 1절의 ① 샘플 프롬프트에 이미 네 가지가 다 들어 있었습니다.

알려 줄 것왜①의 문장
표 이름과 열 이름(필요하면 데이터형)AI는 표를 볼 수 없다. 이름이 한 글자만 달라도 저장되지 않는다."표 이름은 menu_duels이고 public 스키마에 있어. 이 표의 열 이름은 id, game_id, round, left_menu, right_menu, winner, created_at 일곱 가지야"
새 표를 만들지 말 것학급 공용 프로젝트에서는 학생이 표를 만들 권한이 없다"새 표를 만들지 말고 이 표에 그대로 연결해 줘"
접속 정보는 비밀 금고에주소와 키가 코드에 박히면 공개 저장소로 새어 나간다"접속 정보는 비밀 금고(secrets)의 SUPABASE_URL과 SUPABASE_KEY에서 읽어 줘"
무결성 조건빈 값이나 잘못된 값이 들어가지 않게"서로 다른 두 후보 중 하나를 골랐을 때만, 교사가 준비한 표에 대결을 한 행씩 저장해 줘"

팀 프로젝트에서도 앱의 목적, 실제 표의 구조, 접속 정보의 이름, 허용된 입력과 동작을 알려 줍니다. 코드를 받은 뒤에는 저장한 값과 조회·집계 결과가 맞는지 작은 예로 확인합니다.

1차시에 질문 던지기로 시작한 공통 수업이 여기서 끝납니다. 질문을 세우고 첫 앱을 배포하고(1차시), API로 데이터를 구해 오고(2·5차시), 그래프로 데이터를 읽고(3·4차시), 회귀·분류·군집·연관의 네 가지 틀로 모델을 만들고(6~12차시), 데이터가 저장되는 곳과 그 문장을 읽고(13차시), 그 데이터를 다룰 때의 기준을 세웠습니다(14차시). 이제 같은 도구로 팀의 질문에 답할 차례입니다.

  • 친구와 같은 대결 기록 표에 연결하여 서로의 대결 기록이 집계에 반영되는지 확인했다.
  • 승리 수 순위와 승률 순위가 어디서 갈리는지 분모를 들어 설명할 수 있다.
  • 팀을 구성하고, 데이터 후보를 세 물음으로 판단해 주제 카드를 냈다.
