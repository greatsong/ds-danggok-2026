두 번째 API — 우리 학교 급식

"물고기를 주면 하루를 먹이고, 잡는 법을 가르치면 평생을 먹인다."
속담 — 오늘은 두 번째 API를 여러분 손으로 붙입니다

🔎 더 자세한 판 보기 →

오늘은 나이스(NEIS) 급식 API로 학교 점심을 불러오는 앱을 새로 만듭니다. 나이스는 교육행정정보시스템(National Education Information System)의 약자로, 전국 학교의 학사·행정 정보를 다루는 시스템입니다. 여러분의 성적표와 생활기록부도 이 시스템에 있습니다. 방법은 2차시의 KOBIS와 같습니다. 공식 문서 발췌를 읽고, 완성 주소로 응답을 먼저 확인한 뒤, 문서를 프롬프트에 붙입니다. 2차시 KOBIS API는 인증키가 필요했지만, 나이스 급식 API는 인증키 없이 호출할 수 있습니다. 키 없이 호출하면 한 번에 받을 수 있는 건수에 상한이 있으며, 두 학기처럼 넓은 기간을 조회할 때는 팀당 인증키 한 개를 발급받아 해결합니다.

🎯 오늘 하는 것
  • API 비교 — KOBIS와 나이스의 같은 점과 다른 점
  • 인증키 — 없어도 되는 호출과 팀당 한 개 발급
  • 팀 미션 — 알아낼 것을 정하고 문서를 붙인 프롬프트로 팀 앱 제작
  • 개인 미션 — 설문 제출, 12차시에 다시 사용

0. 왜 배우나

세상의 API는 수천 개가 넘고, 수업이 그것을 전부 소개할 수는 없습니다. 그래서 오늘 배우는 것은 급식 API 하나가 아니라, 처음 보는 API에 다가가는 순서입니다.

1. 두 API 비교 — 같은 순서, 다른 규칙

KOBIS에서 밟은 순서는 나이스에서도 통합니다. 그러나 규칙은 API마다 다릅니다. 가장 큰 차이는 인증키입니다.

KOBIS 박스오피스 (2차시)나이스 급식 (오늘)
인증키필요 — 비밀 금고(secrets)에 보관키 없이 부를 수 있으나 한 번에 받는 건수에 상한이 있고, 인증키를 발급하면 상한이 완화된다
빈 응답의 정체오늘 것은 아직 집계 전주말·방학은 급식이 없는 날 — 오류가 아니다
받자마자 다듬을 것숫자가 따옴표 친 글자로 온다메뉴 전체가 한 덩어리 글자로 온다 — 구분 기호와 알레르기 괄호를 떼야 표가 된다
⚠️ 건수 제한의 실물 — 넓게 물으면 잘려 온다

인증키가 없는 호출로 2025년 9월부터 2026년 9월까지 중식을 요청하면 응답이 알려 주는 전체 건수는 184건이지만 목록에 오는 것은 5건입니다. 이 과정에서 오류 표시가 나타나지 않아 알아채기 어렵습니다. 한 번에 받을 행 수를 늘리는 항목도 키가 없으면 무시됩니다. 조회 기간을 하루나 한 주로 짧게 잡거나 넓은 기간이 필요하면 3절의 절차대로 인증키를 발급받습니다.

2. 완성 주소 맨눈 보기 — 급식 JSON 해부

📖 더 알아보기 — 포털과 문서까지 가는 길

open.neis.go.kr은 나이스의 학교 데이터 일부를 누구나 사용할 수 있도록 공개한 곳입니다. 급식 식단 말고도 학교 기본 정보·학사 일정·시간표 API가 있고, 우리 학교만이 아니라 전국 어느 학교든 학교 코드만 바꾸면 조회됩니다. "우리 학교와 옆 학교의 급식은 얼마나 다를까" 같은 질문의 재료가 됩니다.

문서까지 가는 방법은 2차시에 KOBIS에서 했던 것과 같습니다. 포털 첫 화면에서 데이터셋 메뉴로 들어가 급식식단정보를 찾아 열고, 상세 화면의 Open API 항목을 펼치면 오늘의 문서가 나옵니다. 볼 곳 세 곳의 이름이 KOBIS와 조금 다릅니다. 신청주소(요청 주소) · 신청인자 표(요청변수 — 교육청·학교 코드 등) · 출력값 표(응답 구조). 이름이 달라도 하는 일은 같아서, 세 곳을 긁어 프롬프트 끝에 붙이면 됩니다. 아래 ①의 발췌가 바로 그 결과물입니다.

2차시와 같은 순서입니다. 코드를 쓰기 전에 완성 주소를 새 탭에서 열어, 응답 JSON을 맨눈으로 확인합니다. 먼저 주소를 해부해 봅니다. KOBIS 주소에 있던 key=가 여기에는 없습니다.

요청 주소의 해부 — 인증키 없는 요청
https://open.neis.go.kr/hub/mealServiceDietInfo   ← 어디에 — 요청 주소
?Type=json                                        ← 응답 형식 — 이 줄이 빠지면 XML로 온다
&ATPT_OFCDC_SC_CODE=B10                           ← 조건 — 교육청(서울)
&SD_SCHUL_CODE=7010073                            ← 조건 — 학교(당곡고)
&MMEAL_SC_CODE=2                                  ← 조건 — 식사(중식)
&MLSV_FROM_YMD=20260602&MLSV_TO_YMD=20260602      ← 조건 — 기간(하이픈 없는 여덟 자리)
&MLSV_YMD=20260907                                ← 하루만 볼 때는 위 두 줄 대신 이 한 줄
요청 주소와 조건은 2차시 KOBIS와 같은 구조인데, 인증키만 없다. 날짜 값을 바꾸면 응답이 그 날짜 것으로 바뀐다.

키가 없어도 완성 주소를 브라우저 새 탭에서 바로 열어 볼 수 있습니다. 수업에서 함께 연 주소는 당곡고등학교 2026년 9월 7일 급식이며, 주소 끝에 붙은 Type=json은 응답을 JSON으로 받겠다는 지정입니다. 이 항목을 생략하면 응답 형식은 XML이 됩니다. 바로 아래 인쇄된 응답 예시는 2026년 6월 2일 중식입니다.

실제 응답 (일부 발췌 · 2026-06-02)
{
  "mealServiceDietInfo": [
    { "head": [ { "list_total_count": 1 } ] },
    { "row": [
        {
          "SCHUL_NM": "당곡고등학교",
          "MLSV_YMD": "20260602",
          "DDISH_NM": "친환경현미밥 <br/>오징어무국 (5.6.13.17)<br/>두부조림 (5.6.13)<br/>
                       찜닭(당면) (5.6.13.15)<br/>얼갈이무침 <br/>배추김치 (9)<br/>초코맛아이스크림 (2)",
          "CAL_INFO": "941.7 Kcal",
          "ORPLC_INFO": "닭고기 : 국내산 ..."
        }
    ] }
  ]
}
  • 값 꺼내기는 2차시와 같다 — KOBIS의 boxOfficeResult → dailyBoxOfficeList와 이름만 다를 뿐, 상자에서 상자를 꺼내는 읽기는 같습니다.
  • 👀 눈여겨볼 것 — 메뉴 일곱 개가 한 칸에 들어 있다. DDISH_NM에는 그날 메뉴 전체가 <br/>라는 구분 기호로 이어진 한 덩어리 글자로 옵니다. 메뉴 뒤 괄호 속 숫자는 알레르기 유발 식품 번호입니다. 이대로는 "배추김치가 며칠 나왔나"를 셀 수 없습니다. 구분 기호로 낱개를 나누고 괄호를 떼는 다듬기가 필요합니다.
📖 교과서의 정의 『데이터 과학』 20쪽

"이러한 반정형 데이터는 데이터 구조를 쉽게 변경할 수 있고, 필요한 경우 표 형태로도 쉽게 변환할 수 있어 데이터 공유에 많이 활용된다." (20쪽)

→ 2차시에 읽은 문장이 오늘 두 번째로 실물이 된다. 급식 JSON도 row 하나가 표의 행 하나로 바뀐다.

3. 인증키 — 없어도 되지만, 넓게 보려면 팀당 하나

인증키 없이도 호출할 수 있으나, 한 번에 오는 건수의 상한이 있어 두 학기 전체를 한 번에 묻는 질문에는 맞지 않습니다. 인증키를 발급하면 건수 상한이 완화되며, 발급은 무료이고 몇 분 정도 소요됩니다. 팀당 한 개를 발급받아 공동으로 사용할 수 있습니다. 하루나 한 주만 조회하는 앱이라면 키 없이 진행해도 됩니다.

  1. ① 회원 가입
    나이스 교육정보 개방 포털에 회원 가입을 합니다.
  2. ② 인증키 신청
    인증키 신청 화면에서 신청하며, 무료이고 신청 즉시 발급됩니다.
  3. ③ 비밀 금고(secrets)에 넣기
    2차시에 KOBIS 인증키를 넣은 곳과 같은 스트림릿 앱 설정의 Secrets 칸에 한 줄을 입력한 뒤 저장합니다. 코드에서 값을 꺼내는 방법은 st.secrets["NEIS_API_KEY"]이며, 꺼낸 값을 요청의 KEY 항목으로 전달합니다. 키를 코드에 직접 적어 커밋하면 저장소를 여는 누구나 그 키를 사용할 수 있습니다.
    Secrets에 넣을 한 줄
    NEIS_API_KEY = "발급받은 인증키"
인증키를 붙인 요청 — 넓은 기간을 한 번에
https://open.neis.go.kr/hub/mealServiceDietInfo   ← 어디에 — 요청 주소
?KEY=발급받은_인증키                            ← 인증키 — 비밀 금고에서 꺼내 붙인다
&Type=json                                    ← 응답 형식
&ATPT_OFCDC_SC_CODE=B10&SD_SCHUL_CODE=7010073 ← 조건 — 교육청·학교
&MLSV_FROM_YMD=20250901&MLSV_TO_YMD=20260930  ← 조건 — 두 학기 전체
&pSize=1000                                   ← 한 번에 받을 행 수
2차시 KOBIS에서 key를 붙였던 것과 같은 모양이다. 항목 이름과 붙는 자리만 API마다 다르다. 키 없이 같은 기간을 물으면 전체 184건이라고 알려 주면서 목록에는 5건만 오고, pSize도 무시된다(실측). 키를 붙이면 184행이 한 번에 온다.
💡 선생님 키

수업용 키를 준비했으며, 키 값은 클래스룸 게시글에 올립니다. 받은 키도 코드에 적지 않고 비밀 금고에 입력합니다.

4. 팀 미션 — 급식 데이터로 무엇을 알아낼까

이 절부터 팀 단위로 활동합니다. 만들 화면이 정해져 있지 않으며, 무엇을 알아낼지 정하는 일부터 팀의 몫입니다. 학기말 5주 팀 프로젝트의 순서를 한 시간으로 압축한 미니 프로젝트입니다.

  1. ① 아이디어 발산 — 최소 세 개
    급식 데이터로 알아낼 수 있는 새로운 사실과 해결할 수 있는 문제를 세 개 이상 나열합니다. 좋고 나쁨을 따지기 전에 먼저 적습니다.
    • 이웃 학교와 우리 학교의 식단이 같은 날 같은 지역인데도 왜 다를까요?
    • 칼로리가 높은 날과 낮은 날의 차이는 요일, 계절, 메뉴 종류 중 무엇에서 비롯될까요?
    • 알레르기 번호가 자주 붙는 메뉴는 무엇이고, 특정 알레르기가 있는 학생이 먹을 수 있는 날수는 얼마나 될까요?
  2. ② 아이디어 수렴 — 하나를 고른다
    판단 기준은 분석 가능성과 임팩트 두 가지입니다. 분석 가능성은 급식 API가 실제로 주는 값으로 답할 수 있는 질문인지를 뜻합니다. API가 주지 않는 값의 예로는 맛 평가와 잔반량이 있으며, 이 두 기준은 1차시 질문 카드에서 사용한 것과 같습니다.
  3. ③ 프롬프트 작성 — 문서를 붙이고, 우리 문제를 설명한다
    이 순서는 2차시부터 반복해 온 것입니다. 공식 문서 발췌를 첨부하면 AI가 필드 이름을 지어내지 못하게 막습니다. 팀이 풀려는 문제를 말로 설명하며, 문서는 포털 상세 화면에서 직접 복사할 수 있고 아래 인쇄된 발췌를 사용해도 됩니다.
    프롬프트 끝에 붙일 문서 발췌
    ──── 아래는 나이스 교육정보 개방 포털 문서에서 복사한 부분 ────
[학교기본정보] 요청 주소: https://open.neis.go.kr/hub/schoolInfo
요청변수: Type=json · SCHUL_NM(학교 이름, 일부만 적어도 검색된다)
응답 구조: schoolInfo의 두 번째 상자 안 row 목록에 학교별로
  SCHUL_NM(학교명) · ATPT_OFCDC_SC_CODE(교육청 코드) · SD_SCHUL_CODE(학교 코드) · LCTN_SC_NM(지역)
  ※ 못 찾으면 row 없이 RESULT 상자가 온다. 인증키 없이 한 번에 5건까지 온다.
[급식식단정보] 요청 주소: https://open.neis.go.kr/hub/mealServiceDietInfo
요청변수: Type=json · ATPT_OFCDC_SC_CODE, SD_SCHUL_CODE(위에서 찾은 두 코드) · MMEAL_SC_CODE=2(중식) ·
  MLSV_FROM_YMD, MLSV_TO_YMD(조회 시작일과 끝일, 하이픈 없는 여덟 자리)
응답 구조: mealServiceDietInfo의 두 번째 상자 안 row 목록에 날짜별로
  MLSV_YMD(급식일) · DDISH_NM(메뉴 전체 - <br/>로 구분되고, 메뉴 뒤 괄호 숫자는 알레르기 번호) · CAL_INFO(칼로리)
  ※ 급식이 없는 날은 row가 없고 RESULT 상자가 온다. 오류가 아니다.
  4. ④ 만들고, 다른 팀이 쓸 수 있게 공개한다
    조건 세 가지는 모든 팀 공통이며, 나머지는 팀 재량입니다.
    ✔️ 필수 조건 셋
    • 그래프 작성 — 3차시와 4차시에 사용한 plotly로 그래프를 그립니다.
    • 학교 선택 — 당곡고등학교를 기본값으로 두고 학교를 세 곳 이상 고를 수 있게 구성합니다.
    • 앱 주소 정리 — 앱 주소를 알아보기 쉽게 정리하여 다른 학생이 그대로 열어 사용할 수 있게 합니다.
🍪 간식 시상

가장 재미있고 독창적인 아이디어를 낸 팀을 시상합니다. 기준은 완성도가 아니라 질문입니다.

🧰 막힐 때 여는 예시 — 선생님이 실행해 확인한 프롬프트와 코드

팀의 질문이 정해지기 전이거나 진행이 막혔을 때 여는 출발점입니다. 그대로 따라 만드는 정답이 아니며, 첫 예시인 학교 검색 화면은 학교를 세 곳 이상 고르는 조건의 기준점입니다.

예시 1 — 학교를 검색해 고르면 그 학교의 급식을 보여 주는 첫 화면. 학교를 세 곳 이상 고르는 조건을 여기서 출발시킬 수 있습니다.

① 프롬프트
스트림릿 앱(main.py)을 새로 만들어 줘. 제목은 '학교 급식 찾아보기'.
아래에 나이스 교육정보 개방 포털 문서에서 복사한 내용을 붙였어. 두 API 모두 인증키가 없어도 돼.

- 학교 이름을 입력하면 학교 정보 API로 그 이름이 들어간 학교를 찾아 목록에서 고를 수 있게 해 줘.
  같은 이름의 학교가 여러 지역에 있으니 지역도 함께 보여 줘.
- 날짜를 달력에서 고르면, 고른 학교의 그날 중식 메뉴를 보여 줘.
- 날짜의 기본값은 한국 시간 기준 오늘로 해 줘(배포 서버 시계는 한국 시간이 아니야).
  메뉴 뒤 괄호 속 숫자는 알레르기 번호니까 떼고 보여 주고, 칼로리도 함께.
- '수도여고'처럼 줄여 적은 이름은 정식 이름('수도여자고등학교')의 일부가 아니라서 못 찾아.
  못 찾으면 '여고'는 '여자고등학교', '고'는 '고등학교'로 풀어서 한 번 더 찾아 줘.
- 학교를 못 찾거나 그날 급식이 없으면 오류 대신 안내 문구를 보여 줘.
- 필요한 라이브러리 목록(requirements.txt)도 같이 줘. 버전 숫자 없이 이름만.

[학교기본정보] 요청 주소: https://open.neis.go.kr/hub/schoolInfo

  ※ 못 찾으면 row 없이 RESULT 상자가 온다. 인증키 없이 한 번에 5건까지 온다.
[급식식단정보] 요청 주소: https://open.neis.go.kr/hub/mealServiceDietInfo
요청변수: Type=json · ATPT_OFCDC_SC_CODE, SD_SCHUL_CODE(위에서 찾은 두 코드) · MMEAL_SC_CODE=2(중식) ·
  MLSV_FROM_YMD, MLSV_TO_YMD(조회 시작일과 끝일, 하이픈 없는 여덟 자리)
응답 구조: mealServiceDietInfo의 두 번째 상자 안 row 목록에 날짜별로
  MLSV_YMD(급식일) · DDISH_NM(메뉴 전체 - <br/>로 구분되고, 메뉴 뒤 괄호 숫자는 알레르기 번호) · CAL_INFO(칼로리)
  ※ 급식이 없는 날은 row가 없고 RESULT 상자가 온다. 오류가 아니다.

# main.py — 학교를 검색해 고르면 그 학교의 급식을 보여 주는 첫 화면
import datetime
import re

import requests
import streamlit as st

st.set_page_config(page_title="학교 급식 찾아보기", layout="wide")
st.title("🍚 학교 급식 찾아보기")
st.write("학교 이름을 검색해 고르면 그 학교의 그날 중식을 보여 줍니다. 왼쪽 메뉴에는 우리 학교만 보는 페이지가 있습니다.")

name = st.text_input("학교 이름", value="당곡고등학교")
picked = st.date_input("날짜를 고르세요", value=(datetime.datetime.utcnow() + datetime.timedelta(hours=9)).date())  # 한국 시간 기준 오늘

# 1) 학교 이름으로 교육청 코드와 학교 코드를 찾는다 (인증키 없이, 한 번에 5건까지)
def search_schools(query):
    info = requests.get(
        "https://open.neis.go.kr/hub/schoolInfo",
        params={"Type": "json", "SCHUL_NM": query},
        timeout=10,
    ).json()
    # 못 찾으면 row 없이 RESULT 상자만 온다 — 오류가 아니다
    return info["schoolInfo"][1]["row"] if "schoolInfo" in info else []


schools = search_schools(name)
if not schools:
    # '수도여고'처럼 줄여 적은 이름은 정식 이름의 일부가 아니라 못 찾는다 — 풀어서 다시 찾는다
    for short, full in [("여고", "여자고등학교"), ("고", "고등학교"), ("중", "중학교"), ("초", "초등학교")]:
        if name.endswith(short):
            schools = search_schools(name[: -len(short)] + full)
            break
if not schools:
    st.warning("그 이름의 학교를 찾지 못했습니다. 정식 이름으로 적어 보세요. (예: 수도여자고등학교)")
    st.stop()

labels = [f"{s['SCHUL_NM']} ({s['LCTN_SC_NM']})" for s in schools]
chosen = schools[labels.index(st.selectbox("학교 고르기", labels))]

# 2) 고른 학교의 그날 중식을 불러온다
ymd = picked.strftime("%Y%m%d")
meal = requests.get(
    "https://open.neis.go.kr/hub/mealServiceDietInfo",
    params={
        "Type": "json",
        "ATPT_OFCDC_SC_CODE": chosen["ATPT_OFCDC_SC_CODE"],
        "SD_SCHUL_CODE": chosen["SD_SCHUL_CODE"],
        "MMEAL_SC_CODE": "2",
        "MLSV_FROM_YMD": ymd,
        "MLSV_TO_YMD": ymd,
    },
    timeout=10,
).json()

st.subheader(chosen["SCHUL_NM"] + " · " + picked.strftime("%Y년 %m월 %d일") + " 중식")
if "mealServiceDietInfo" not in meal:
    # 급식이 없는 날은 row 없이 RESULT 상자만 온다 — 오류가 아니다
    st.info("급식이 없는 날입니다. (주말·방학·공휴일)")
else:
    row = meal["mealServiceDietInfo"][1]["row"][0]
    for dish in row["DDISH_NM"].split("<br/>"):
        # 괄호 속 알레르기 번호는 떼고 보여 준다
        st.markdown("- " + re.sub(r"\s*\([0-9.]+\)", "", dish.strip()))
    st.metric("칼로리", row["CAL_INFO"])

AI가 준 코드 예시 — 
# pages/1_달력별_급식.py — 나이스 급식 API로 그날 식단을 카드로 보여 주는 페이지
import datetime
import re

import requests
import streamlit as st

st.title("🍚 우리 학교 급식")

# 날짜와 알레르기 스위치를 나란히 놓는다
left, right = st.columns([2, 1])
picked = left.date_input("날짜를 고르세요", value=(datetime.datetime.utcnow() + datetime.timedelta(hours=9)).date())  # 한국 시간 기준 오늘
show_allergy = right.toggle("알레르기 정보 보기")
ymd = picked.strftime("%Y%m%d")

# 나이스 급식 API — 인증키 없이 호출한다 (조회 기간은 하루)
url = "https://open.neis.go.kr/hub/mealServiceDietInfo"
params = {
    "Type": "json",                # 응답을 JSON으로
    "ATPT_OFCDC_SC_CODE": "B10",   # 서울시교육청
    "SD_SCHUL_CODE": "7010073",    # 당곡고등학교
    "MMEAL_SC_CODE": "2",          # 중식
    "MLSV_FROM_YMD": ymd,
    "MLSV_TO_YMD": ymd,
}
data = requests.get(url, params=params, timeout=10).json()

weekday = "월화수목금토일"[picked.weekday()]
st.subheader(picked.strftime("%Y년 %m월 %d일") + f" ({weekday}) 중식")

if "mealServiceDietInfo" not in data:
    # 급식이 없는 날은 row 없이 RESULT 상자만 온다 — 오류가 아니다
    st.info("급식이 없는 날입니다. (주말·방학·공휴일)")
else:
    row = data["mealServiceDietInfo"][1]["row"][0]
    # 메뉴 전체가 한 덩어리 글자로 온다 — <br/>로 잘라 낱개 메뉴로
    dishes = [d.strip() for d in row["DDISH_NM"].split("<br/>") if d.strip()]
    if not show_allergy:
        # 괄호 속 알레르기 번호 떼기
        dishes = [re.sub(r"\s*\([0-9.]+\)", "", d) for d in dishes]

    # 큰 숫자 카드 — 메뉴 가짓수와 칼로리
    m1, m2 = st.columns(2)
    m1.metric("메뉴", f"{len(dishes)}가지")
    m2.metric("칼로리", row["CAL_INFO"])

    # 메뉴를 카드 세 칸씩 나란히
    cols = st.columns(3)
    for i, dish in enumerate(dishes):
        with cols[i % 3].container(border=True):
            st.markdown(f"**{dish}**")

③ 페이지 추가 프롬프트
pages 폴더에 '우리 학교 메뉴별 급식' 페이지를 하나 더 추가해 줘. 파일 이름은 2_메뉴별_급식.py.
앞 페이지는 그대로 두고 새 파일로.
- 2025년 9월부터 2026년 9월까지 두 학기 전체가 궁금해. 인증키를 붙여 한 번에 받아 줘.
  인증키는 비밀 금고에 NEIS_API_KEY라는 이름으로 넣어 뒀어. 코드에 직접 적지 말고 거기서 꺼내 써.
  한 번에 받을 행 수(pSize)는 1000으로 하고, 중식만 골라 줘.
- 메뉴는 한 덩어리 글자로 오니까 <br/> 기준으로 낱개로 나누고, 뒤에 붙은 괄호 속 알레르기 번호는 떼 줘.
- 같은 날 같은 메뉴가 두 번 적혀 있어도 하루로 세 줘.
- 이 기간에 가장 자주 나온 메뉴 TOP 10을 가로 막대그래프로 보여 줘.
- 메뉴마다 며칠 나왔는지 일수와 비율을 함께 보여 줘.
- 화면을 보기 좋게: 몇 위까지 볼지는 슬라이더로, 위에는 집계한 날수·1위 메뉴·1위 비율을 큰 숫자 카드로,
  막대는 1위가 맨 위에 오고 값이 클수록 진한 색으로.
pages/2_메뉴별_급식.py
# pages/2_메뉴별_급식.py — 인증키로 두 학기를 한 번에 받아 최다 등장 메뉴 TOP N
import re

import pandas as pd
import plotly.express as px
import requests
import streamlit as st

st.title("🥇 두 학기 최다 등장 메뉴")


@st.cache_data
def load_lunch(frm, to):
    res = requests.get(
        "https://open.neis.go.kr/hub/mealServiceDietInfo",
        params={
            "Type": "json",
            "KEY": st.secrets["NEIS_API_KEY"],   # 인증키 — 비밀 금고에서 꺼낸다
            "pSize": 1000,                       # 한 번에 받을 행 수 (키가 있어야 듣는다)
            "ATPT_OFCDC_SC_CODE": "B10",         # 서울시교육청
            "SD_SCHUL_CODE": "7010073",          # 당곡고등학교
            "MMEAL_SC_CODE": "2",                # 중식만
            "MLSV_FROM_YMD": frm,
            "MLSV_TO_YMD": to,
        },
        timeout=20,
    ).json()
    days = {}
    for row in res["mealServiceDietInfo"][1]["row"]:
        # 한 덩어리 글자를 낱개로 나누고 괄호 속 알레르기 번호를 뗀다
        dishes = [re.sub(r"\s*\([0-9.]+\)", "", d).strip() for d in row["DDISH_NM"].split("<br/>")]
        days[row["MLSV_YMD"]] = {d for d in dishes if d}   # 같은 날 중복은 하루로 센다
    return days


meals = load_lunch("20250901", "20260930")
days = len(meals)

counts = (pd.Series([d for dishes in meals.values() for d in dishes])
          .value_counts().rename_axis("메뉴").reset_index(name="일수"))
counts["비율(%)"] = (counts["일수"] / days * 100).round(0).astype(int)

# 몇 위까지 볼지 슬라이더로 고른다
top_n = st.slider("몇 위까지 볼까요?", min_value=5, max_value=20, value=10)
top = counts.head(top_n).copy()
top.insert(0, "순위", range(1, len(top) + 1))

# 큰 숫자 카드 셋 — 집계 일수, 1위 메뉴, 1위 비율
first = top.iloc[0]
c1, c2, c3 = st.columns(3)
c1.metric("집계한 날", f"{days}일")
c2.metric("1위 메뉴", first["메뉴"])
c3.metric("1위 등장 비율", f"{first['비율(%)']}% ({first['일수']}일)")

# 막대는 1위가 맨 위, 값이 클수록 진한 색, 막대마다 일수와 비율
top["표시"] = top["일수"].astype(str) + "일 (" + top["비율(%)"].astype(str) + "%)"
fig = px.bar(
    top.sort_values("일수"), x="일수", y="메뉴", orientation="h",
    text="표시", color="일수", color_continuous_scale="Oranges",
    title=f"중식 {days}일 중 가장 자주 나온 메뉴 TOP {top_n}",
)
fig.update_layout(coloraxis_showscale=False, xaxis_title="등장 일수", yaxis_title="")
st.plotly_chart(fig, width="stretch")

st.dataframe(top[["순위", "메뉴", "일수", "비율(%)"]], hide_index=True, width="stretch")
st.caption(f"중식 {days}일 기준 · 이 그래프로 알 수 있는 것: (한 문장으로 적어 보세요)")

화면이 둘 이상이 되면 한 파일에 덮어쓰지 말고 pages 폴더로 나눕니다. main.py 옆에 pages 폴더를 두면 그 안의 파일 하나하나가 왼쪽 메뉴의 페이지가 됩니다. 폴더 이름은 소문자 pages여야 하고, 위치는 main.py와 나란한 곳이며, 파일 이름은 .py로 끝나야 합니다.

5. 발견 — 184일의 1위

무엇이 가장 자주 나왔는지 묻는 질문은 하루씩 조회해서는 답할 수 없습니다. 인증키를 붙인 한 번의 요청으로 두 학기 중식 184일이 한꺼번에 오며, 3절에서 발급받은 키가 여기서 쓰입니다. 메뉴를 낱개로 나눠 세면 고유 메뉴 498종이고 하루 평균 6.8품입니다.

6. 개인 미션 — 설문 제출

팀 앱과 별도로 각자 설문 한 건을 제출합니다. 수행평가가 아니라 생기부에 기록되는 활동입니다. 학기말 프로젝트에 앞서 오늘의 미니 프로젝트를 각자 정리하는 자리이며, 팀에서 맡은 일과 알아낸 것을 자기 문장으로 기록합니다. 설문 주소는 클래스룸 과제에서 안내합니다.

설문에 포함된 문항 하나는 특정 메뉴가 함께 나올 것 같은 짝 세 개를 예상하게 구성했습니다. 예를 들어 "○○가 나오는 날엔 △△도 나온다"와 같은 꼴로 예상을 적습니다. 두 학기 표에는 무엇이 함께 나왔는지에 대한 정보가 담겨 있습니다. 12차시에 같은 표로 함께 나오는 메뉴의 규칙을 확인하고 오늘 적은 예상과 대조합니다. 데이터를 열어 보기 전의 직감이라는 점이 중요하므로 오늘 기록합니다.

💡 예상을 고를 때 한 가지

위 표에서 봤듯 배추김치는 둘에 하루꼴로 나옵니다. 거의 매일 나오는 메뉴를 짝으로 적으면 맞을 가능성이 높습니다. 그 "맞은 예상"이 과연 의미가 있는지도 12차시에 함께 따져 봅니다.

7. 갤러리 — 팀 앱을 공개한다

팀 앱 주소를 갤러리에 게시하며, 갤러리 주소는 클래스룸 게시글을 참고합니다. 다른 반 학생이 받아 적을 수 있을 만큼 정리된 주소로 올리고, 다른 팀의 앱을 열람한 뒤 두 줄 피드백을 남깁니다.

  • 좋았던 것 — 우리 팀이 생각하지 못한 질문, 화면, 문구
  • 궁금한 것 — 앱을 사용하다 생긴 물음

8. 개념 정리

오늘 배운 것을 한 줄로 줄이면 이렇습니다. API마다 규칙(키·빈 응답·응답 모양)은 다르지만, 다가가는 순서는 같다. 문서 발췌를 읽고, 완성 주소를 맨눈으로 확인하고, 프롬프트에 문서를 붙여 부탁한다. 이 순서를 KOBIS와 나이스에서 두 번 밟았으니, 세 번째 API는 여러분 혼자서도 만날 수 있습니다. 그리고 받은 데이터가 바로 셀 수 있는 모양이 아닐 때가 많다는 것도 확인했습니다 — 한 덩어리 글자를 낱개로 나누는 다듬기(전처리)를 거쳐야 "184일 중 102일" 같은 숫자가 나옵니다. 오늘 더해진 것은 만들 화면을 받는 대신 무엇을 알아낼지 팀이 먼저 결정한 점입니다. 학기말 프로젝트는 같은 순서로 5주 동안 진행됩니다.

9. 확인 문제

문제 1 일요일 날짜로 급식 API를 불렀더니 식단 없이 "해당하는 데이터가 없습니다"라는 안내만 왔습니다. 가장 알맞은 해석은 무엇일까요?
주말·방학은 급식이 없는 날이므로 돌려줄 데이터가 없습니다. 오류가 아니라 정상 응답이고, 좋은 앱은 이 경우를 "급식이 없는 날입니다"로 안내합니다.
문제 2 KOBIS와 나이스 급식 API의 차이를 인증키를 중심으로 두 가지 써 보세요.
예시 답 펼쳐 보기

① KOBIS는 인증키가 요청에 실려 가야 하고 키는 비밀 금고(secrets)에 보관하지만, 나이스 급식 API는 키 없이 부를 수 있다. ② 대신 나이스는 키가 없으면 한 번에 오는 건수에 제한이 있어 조회 기간을 짧게 잡는다. 인증키를 발급하면 건수 상한이 완화되고, 발급받은 키는 KOBIS와 마찬가지로 비밀 금고에 보관한다.

문제 3 메뉴 열은 한 날의 메뉴 여러 개가 구분 기호로 이어진 한 덩어리 글자입니다. "가장 자주 나온 메뉴 TOP 10"을 세기 전에 어떤 단계가 필요하고, 그 단계를 건너뛰면 어떻게 될까요?
예시 답 펼쳐 보기

구분 기호를 기준으로 메뉴를 낱개로 나누고, 메뉴 뒤 괄호 속 알레르기 번호를 떼는 다듬기(전처리)가 필요하다. 건너뛰면 하루 식단 전체("친환경현미밥|오징어무국|…")가 통째로 한 메뉴로 세어져, 같은 배추김치라도 그날의 식단 조합이 다르면 모두 다른 값이 되므로 등장 횟수를 셀 수 없다.

🎒 오늘의 체크

  • KOBIS와 나이스의 같은 점과 다른 점을 설명할 수 있다.
  • 완성 주소를 열어 급식 JSON에서 메뉴와 칼로리를 확인할 수 있다.
  • 팀에서 아이디어 세 개 이상 제시하고 하나를 고른 이유를 설명할 수 있다.
  • 공식 문서를 붙이고 문제를 설명한 프롬프트로 팀 앱을 제작했다.
  • 필수 조건 세 가지를 충족했다.
  • 팀 앱 주소를 갤러리에 게시하고 다른 팀에 피드백 두 줄을 남겼다.
  • 개인 미션 설문을 제출하고 메뉴 짝 세 개 예상을 포함했다.
