두 번째 API — 우리 학교 급식

"물고기를 주면 하루를 먹이고, 잡는 법을 가르치면 평생을 먹인다."
속담 · 오늘은 새로운 API의 사용 방법을 스스로 확인합니다.

오늘은 나이스(NEIS) 급식 API로 학교 급식을 조회하는 앱을 새로 만듭니다. 2차시에서 익힌 순서에 따라 공식 문서를 읽고, 요청 주소를 열어 응답을 확인합니다. 그다음 팀이 알아보고 싶은 질문을 정하고, 문서와 요구 사항을 담은 프롬프트로 앱을 제작합니다.

🎯 오늘 하는 것
  • API 비교 — KOBIS와 나이스의 공통점과 차이점을 확인한다
  • 인증키 — 조회 범위에 따라 인증키가 필요한지 판단한다
  • 팀 미션 — 팀의 질문을 정하고 공식 문서를 붙인 프롬프트로 앱을 만든다

0. 왜 배우나

API마다 요청 방법과 응답 구조는 다릅니다. 공식 문서 확인 → 응답 확인 → 앱 제작의 순서를 익히면, 팀 프로젝트에서도 필요한 API를 찾아 활용할 수 있습니다.

1. 두 API 비교 — 같은 순서, 다른 규칙

KOBIS에서 밟은 순서는 나이스에서도 통합니다. 그러나 규칙은 API마다 다릅니다. 가장 큰 차이는 인증키입니다.

KOBIS 박스오피스 (2차시)나이스 급식 (오늘)
인증키필요 — Secrets 설정에 보관키 없이 부를 수 있으나 한 번에 받는 건수에 상한이 있고, 인증키를 발급하면 상한이 완화된다
데이터가 없는 경우조회 날짜의 박스오피스가 아직 집계되지 않았을 수 있습니다.급식이 없거나 식단이 아직 등록되지 않았을 수 있습니다. 응답의 안내를 확인합니다.
분석 전 처리문자열로 받은 관객 수를 숫자로 바꿉니다.하루 식단을 개별 메뉴로 나누고, 분석용 메뉴 이름을 정리합니다.
⚠️ 전체 건수와 실제로 받은 건수는 다를 수 있다

교재 작성 당시 2025년 9월부터 2026년 9월까지의 중식을 조회하니 전체 건수는 184건으로 표시되었지만, 인증키 없이 받은 목록에는 5건만 있었습니다. 오류가 표시되지 않아도 일부 데이터만 받았을 수 있습니다. 한 번에 받을 행 수를 늘리는 항목도 인증키가 없으면 무시되어 언제나 첫 5건만 옵니다. 응답의 전체 건수와 목록 길이를 비교하고, 더 많은 데이터가 필요하면 3절의 인증키 안내를 따릅니다.

2. 요청 주소를 열고 급식 JSON 읽기

📖 더 알아보기 — 포털과 문서까지 가는 길

나이스 교육정보 개방 포털은 교육행정정보시스템(NEIS)의 일부 데이터를 공개하는 사이트입니다. 학교 기본 정보, 급식 식단, 학사 일정 등을 조회할 수 있습니다. 다른 학교를 조회할 때는 해당 학교의 교육청 코드와 학교 코드를 확인합니다.

포털에서 데이터셋 → 급식식단정보 → Open API를 엽니다. 신청주소는 요청 주소, 신청인자는 요청에 넣을 조건, 출력값은 응답에 들어 있는 항목을 설명합니다. 이 세 부분을 읽고 필요한 내용을 프롬프트에 첨부합니다. 4절에 정리한 문서 요약을 사용해도 됩니다.

앱을 만들기 전에 요청 주소를 새 탭에서 열어 JSON 응답을 확인합니다. 아래 예시는 인증키 없이 당곡고등학교의 하루 중식을 요청하는 주소입니다.

요청 주소의 구성 — 인증키 없는 요청
https://open.neis.go.kr/hub/mealServiceDietInfo   ← 어디에 — 요청 주소
?Type=json                                        ← 응답 형식 — 이 줄이 빠지면 XML로 온다
&ATPT_OFCDC_SC_CODE=B10                           ← 조건 — 교육청(서울)
&SD_SCHUL_CODE=7010073                            ← 조건 — 학교(당곡고)
&MMEAL_SC_CODE=2                                  ← 조건 — 식사(중식)
&MLSV_FROM_YMD=20260602&MLSV_TO_YMD=20260602      ← 조건 — 기간(하이픈 없는 여덟 자리)
&MLSV_YMD=20260602                                ← 하루 조회 시 위 기간 조건 대신 사용
요청 주소와 조건은 2차시 KOBIS와 같은 구조인데, 인증키만 없다. 날짜 값을 바꾸면 응답이 그 날짜 것으로 바뀐다.

당곡고등학교 2026년 6월 2일 중식 응답 열기를 눌러 아래 예시와 비교합니다. Type=json은 JSON 형식으로 응답해 달라는 지정입니다. 이를 생략하면 XML 형식으로 응답합니다. 실제 응답은 등록 정보의 수정에 따라 달라질 수 있습니다.

실제 응답 (일부 발췌 · 2026-06-02)
{
  "mealServiceDietInfo": [
    { "head": [ { "list_total_count": 1 } ] },
    { "row": [
        {
          "SCHUL_NM": "당곡고등학교",
          "MLSV_YMD": "20260602",
          "DDISH_NM": "친환경현미밥 <br/>오징어무국 (5.6.13.17)<br/>두부조림 (5.6.13)<br/>찜닭(당면) (5.6.13.15)<br/>얼갈이무침 <br/>배추김치 (9)<br/>초코맛아이스크림 (2)",
          "CAL_INFO": "941.7 Kcal",
          "ORPLC_INFO": "닭고기 : 국내산 ..."
        }
    ] }
  ]
}
  • 값 꺼내기는 2차시와 같다 — KOBIS의 boxOfficeResult → dailyBoxOfficeList와 이름만 다를 뿐, 상자에서 상자를 꺼내는 읽기는 같습니다.
  • 👀 눈여겨볼 것 — 메뉴 일곱 개가 한 칸에 들어 있다. DDISH_NM에는 그날 메뉴 전체가 <br/>라는 구분 기호로 이어진 한 덩어리 글자로 옵니다. 메뉴 뒤 괄호 속 숫자는 알레르기 유발 식품 번호입니다. 이대로는 "배추김치가 며칠 나왔나"를 셀 수 없습니다. 원본은 보존하고, 집계용 데이터에서 메뉴를 나누고 알레르기 번호를 정리합니다.
📖 교과서의 정의 『데이터 과학』 20쪽

"이러한 반정형 데이터는 데이터 구조를 쉽게 변경할 수 있고, 필요한 경우 표 형태로도 쉽게 변환할 수 있어 데이터 공유에 많이 활용된다." (20쪽)

→ 급식 JSON의 row 목록에서 날짜와 메뉴 등 필요한 항목을 꺼내면 표로 정리할 수 있습니다.

3. 인증키 — 없어도 되지만, 넓게 보려면 팀당 하나

조회할 급식일이 적으면 인증키 없이 시작할 수 있습니다. 여러 달의 데이터가 필요하면 팀당 인증키 한 개를 준비해 사용합니다. 인증키를 붙이면 이 기간의 184건이 한 번에 옵니다. 다만 한 번에 받을 수 있는 행 수에는 상한이 있으므로, 그보다 많은 데이터를 물을 때는 전체 건수와 받은 개수를 비교해 나눠 받습니다.

  1. ① 회원 가입
    나이스 교육정보 개방 포털에 회원 가입을 합니다.
  2. ② 인증키 신청
    인증키 신청 화면에서 신청하며, 무료이고 신청 즉시 발급됩니다.
  3. ③ Secrets 설정에 넣기
    2차시에 KOBIS 인증키를 넣은 곳과 같은 스트림릿 앱 설정의 Secrets 칸에 한 줄을 입력한 뒤 저장합니다. 코드에서 값을 꺼내는 방법은 st.secrets["NEIS_API_KEY"]이며, 꺼낸 값을 요청의 KEY 항목으로 전달합니다. 키를 코드에 직접 적어 커밋하면 저장소를 여는 누구나 그 키를 사용할 수 있습니다.
    Secrets에 넣을 한 줄
    NEIS_API_KEY = "발급받은 인증키"
인증키를 붙인 요청 — 넓은 기간을 한 번에
https://open.neis.go.kr/hub/mealServiceDietInfo   ← 어디에 — 요청 주소
?KEY=발급받은_인증키                            ← 인증키 — Secrets 설정에서 꺼내 붙인다
&Type=json                                    ← 응답 형식
&ATPT_OFCDC_SC_CODE=B10&SD_SCHUL_CODE=7010073 ← 조건 — 교육청·학교
&MLSV_FROM_YMD=20250901&MLSV_TO_YMD=20260930  ← 조건 — 2025년 9월~2026년 9월
&pSize=1000                                   ← 한 번에 받을 행 수
인증키는 Secrets 설정에서 읽어 KEY 항목으로 전달합니다. pSize는 한 번에 요청할 행 수이고 상한은 1000입니다. 키가 없으면 pSize와 pIndex가 무시되어 언제나 첫 5건만 온다(실측). 전체 건수가 pSize보다 많을 때만 다음 쪽을 이어서 요청합니다.
💡 선생님 키

수업용 키를 준비했으며, 키 값은 클래스룸 게시글에 올립니다. 받은 키도 코드에 적지 않고 Secrets 설정에 입력합니다.

4. 팀 미션 — 급식 데이터로 무엇을 알아낼까

이제 팀별로 급식 데이터에서 알아보고 싶은 질문을 정합니다. 질문 선정, 앱 제작, 결과 해석의 순서로 작은 프로젝트를 진행합니다. 아래 예시는 출발점이며, 팀의 질문에 맞게 바꾸어도 됩니다.

  1. ① 아이디어 발산 — 최소 세 개
    급식 데이터로 알아낼 수 있는 새로운 사실과 해결할 수 있는 문제를 세 개 이상 나열합니다. 좋고 나쁨을 따지기 전에 먼저 적습니다.
    • 올해 3월부터 현재까지 우리 학교와 근처 학교의 칼로리는 얼마나 차이 날까?
    • 각 학교별로 가장 많이 나온 반찬은?
    • 각 학교별 칼로리가 제일 높았던 날 나온 반찬은?
  2. ② 아이디어 수렴 — 하나를 고른다
    판단 기준은 데이터로 답할 수 있는지와 결과가 누구에게 어떻게 도움이 되는지입니다. 분석 가능성은 급식 API가 실제로 주는 값으로 답할 수 있는 질문인지를 뜻합니다. API가 주지 않는 값의 예로는 맛 평가와 잔반량이 있으며, 이 두 기준은 1차시 질문 카드에서 사용한 것과 같습니다.
  3. ③ 프롬프트 작성 — 문서를 붙이고, 우리 문제를 설명한다
    이 순서는 2차시부터 반복해 온 것입니다. 공식 문서를 첨부하면 AI가 실제 필드 이름과 응답 구조를 참고하도록 도울 수 있습니다. 생성된 코드가 문서와 일치하는지도 확인합니다. 팀이 풀려는 문제를 말로 설명하며, 문서는 포털 상세 화면에서 직접 복사할 수 있고 아래 인쇄된 발췌를 사용해도 됩니다.
    프롬프트 끝에 붙일 문서 발췌
    ──── 아래는 나이스 교육정보 개방 포털 문서에서 복사한 부분 ────
[학교기본정보] 요청 주소: https://open.neis.go.kr/hub/schoolInfo
요청변수: Type=json · SCHUL_NM(학교 이름, 일부만 적어도 검색된다)
응답 구조: schoolInfo의 두 번째 상자 안 row 목록에 학교별로
  SCHUL_NM(학교명) · ATPT_OFCDC_SC_CODE(교육청 코드) · SD_SCHUL_CODE(학교 코드) · LCTN_SC_NM(지역)
  ※ 조회 데이터가 없으면 RESULT의 CODE가 INFO-200이다. 인증키 없이 한 번에 5건까지 온다.
[급식식단정보] 요청 주소: https://open.neis.go.kr/hub/mealServiceDietInfo
요청변수: Type=json · ATPT_OFCDC_SC_CODE, SD_SCHUL_CODE(위에서 찾은 두 코드) · MMEAL_SC_CODE=2(중식) ·
  MLSV_FROM_YMD, MLSV_TO_YMD(조회 시작일과 끝일, 하이픈 없는 여덟 자리) ·

응답 구조: mealServiceDietInfo의 첫 번째 상자 head의 list_total_count에 조건에 맞는 전체 건수가 오고,
  두 번째 상자 안 row 목록에 날짜별로
  MLSV_YMD(급식일) · DDISH_NM(메뉴 전체 - <br/>로 구분되고, 메뉴 뒤 괄호 숫자는 알레르기 번호) · CAL_INFO(칼로리)
  ※ 조회 데이터가 없으면 RESULT의 CODE가 INFO-200이다. 인증 오류 등 다른 CODE와 구분한다.
  ※ 인증키가 없으면 pSize와 pIndex가 무시되어 언제나 첫 5건만 온다.
  4. ④ 만들고, 다른 팀이 쓸 수 있게 공개한다
    조건 세 가지는 모든 팀 공통이며, 나머지는 팀 재량입니다.
    ✔️ 필수 조건 셋
    • 그래프 작성 — 3차시와 4차시에 사용한 plotly로 그래프를 그립니다.
    • 학교 선택과 비교 — 당곡고등학교를 기본값으로 두고 학교를 세 곳 이상 한 번에 고를 수 있게 하고, 고른 학교를 함께 비교하는 화면을 적어도 하나 만듭니다. 모든 화면이 비교일 필요는 없습니다.
    • 앱 주소 정리 — 앱 주소를 알아보기 쉽게 정리하여 다른 학생이 그대로 열어 사용할 수 있게 합니다.
    🏫 다른 학교를 넣으려면 — 학교 코드를 찾아 확정한다

    다른 학교를 불러오려면 교육청 코드와 학교 코드 두 가지가 필요합니다. AI가 제시한 학교 코드가 실제 코드와 다를 수 있으므로, 공식 응답에서 직접 확인합니다. 코드를 찾는 방법은 학교기본정보 API에 학교 이름을 넣어 조회하는 것입니다. 주소는 https://open.neis.go.kr/hub/schoolInfo?Type=json&SCHUL_NM=학교이름이며, 줄임말은 검색되지 않아 정식 명칭이 필요하고 같은 이름이 여러 지역에 있으면 교육청 코드로 좁혀야 합니다. 확인한 코드는 프롬프트에 직접 적어 주며, 예를 들어 서울시교육청은 B10, 수도여자고등학교는 7010090, 당곡고등학교는 7010073입니다. 교육청 코드는 아래 표에서 확인할 수 있습니다. 학교 코드는 학교마다 다르고 수가 많아 표로 정리할 수 없습니다.

가장 재미있고 독창적인 아이디어를 낸 팀을 시상합니다. 기준은 완성도가 아니라 질문입니다.

🧰 막힐 때 여는 예시 — 선생님이 실행해 확인한 프롬프트와 코드

팀의 질문이 정해지기 전이거나 진행이 막혔을 때 여는 출발점입니다. 그대로 따라 만드는 정답이 아니며, 첫 예시인 학교 검색 화면은 학교를 세 곳 이상 고르는 조건의 기준점입니다.

예시 1 — 학교를 검색해 고르면 그 학교의 급식을 보여 주는 첫 화면. 학교를 세 곳 이상 한 번에 고르는 조건을 여기서 출발시킬 수 있습니다.

① 프롬프트
스트림릿 앱(main.py)을 새로 만들어 줘. 제목은 '학교 급식 찾아보기'.
아래에 나이스 교육정보 개방 포털 문서에서 복사한 내용을 붙였어. 두 API 모두 인증키가 없어도 돼.

- 학교 이름을 입력하면 학교 정보 API로 그 이름이 들어간 학교를 찾아 목록에서 고를 수 있게 해 줘.
  같은 이름의 학교가 여러 지역에 있으니 지역도 함께 보여 줘.
- 날짜를 달력에서 고르면, 고른 학교의 그날 중식 메뉴를 보여 줘.
- 날짜의 기본값은 한국 시간 기준 오늘로 해 줘(배포 서버 시계는 한국 시간이 아니야).
  원래 메뉴와 알레르기 번호를 보여 주고, 칼로리도 함께 표시해 줘.
- '수도여고'처럼 줄여 적은 이름은 정식 이름('수도여자고등학교')의 일부가 아니라서 못 찾아.
  못 찾으면 '여고'는 '여자고등학교', '고'는 '고등학교'로 풀어서 한 번 더 찾아 줘.
- 학교를 못 찾거나 그날 급식이 없으면 오류 대신 안내 문구를 보여 줘.
- 필요한 라이브러리 목록(requirements.txt)도 같이 줘. 버전 숫자 없이 이름만.

  두 번째 상자 안 row 목록에 날짜별로
  MLSV_YMD(급식일) · DDISH_NM(메뉴 전체 - <br/>로 구분되고, 메뉴 뒤 괄호 숫자는 알레르기 번호) · CAL_INFO(칼로리)
  ※ 조회 데이터가 없으면 RESULT의 CODE가 INFO-200이다. 인증 오류 등 다른 CODE와 구분한다.
  ※ 인증키가 없으면 pSize와 pIndex가 무시되어 언제나 첫 5건만 온다.

# main.py — 학교를 검색해 고르면 그 학교의 급식을 보여 주는 첫 화면
import datetime
import re

import requests
import streamlit as st

st.set_page_config(page_title="학교 급식 찾아보기", layout="wide")
st.title("🍚 학교 급식 찾아보기")
st.write("학교 이름을 검색해 고르면 그 학교의 그날 중식을 보여 줍니다. 왼쪽 메뉴에는 우리 학교만 보는 페이지가 있습니다.")

name = st.text_input("학교 이름", value="당곡고등학교")
picked = st.date_input("날짜를 고르세요", value=(datetime.datetime.utcnow() + datetime.timedelta(hours=9)).date())  # 한국 시간 기준 오늘

# 1) 학교 이름으로 교육청 코드와 학교 코드를 찾는다 (인증키 없이, 한 번에 5건까지)
def search_schools(query):
    info = requests.get(
        "https://open.neis.go.kr/hub/schoolInfo",
        params={"Type": "json", "SCHUL_NM": query},
        timeout=10,
    ).json()
    if "schoolInfo" in info:
        return info["schoolInfo"][1]["row"]
    result = info.get("RESULT", {})
    if result.get("CODE") == "INFO-200":
        return []
    st.error("학교 조회에 실패했습니다. " + result.get("MESSAGE", "응답을 확인해 주세요."))
    st.stop()


schools = search_schools(name)
if not schools:
    # '수도여고'처럼 줄여 적은 이름은 정식 이름의 일부가 아니라 못 찾는다 — 풀어서 다시 찾는다
    for short, full in [("여고", "여자고등학교"), ("고", "고등학교"), ("중", "중학교"), ("초", "초등학교")]:
        if name.endswith(short):
            schools = search_schools(name[: -len(short)] + full)
            break
if not schools:
    st.warning("그 이름의 학교를 찾지 못했습니다. 정식 이름으로 적어 보세요. (예: 수도여자고등학교)")
    st.stop()

labels = [f"{s['SCHUL_NM']} ({s['LCTN_SC_NM']})" for s in schools]
chosen = schools[labels.index(st.selectbox("학교 고르기", labels))]

# 2) 고른 학교의 그날 중식을 불러온다
ymd = picked.strftime("%Y%m%d")
meal = requests.get(
    "https://open.neis.go.kr/hub/mealServiceDietInfo",
    params={
        "Type": "json",
        "ATPT_OFCDC_SC_CODE": chosen["ATPT_OFCDC_SC_CODE"],
        "SD_SCHUL_CODE": chosen["SD_SCHUL_CODE"],
        "MMEAL_SC_CODE": "2",
        "MLSV_FROM_YMD": ymd,
        "MLSV_TO_YMD": ymd,
    },
    timeout=10,
).json()

st.subheader(chosen["SCHUL_NM"] + " · " + picked.strftime("%Y년 %m월 %d일") + " 중식")
if "mealServiceDietInfo" not in meal:
    result = meal.get("RESULT", {})
    if result.get("CODE") == "INFO-200":
        st.info("조회한 날짜의 급식 정보가 없습니다.")
    else:
        st.error("급식 조회에 실패했습니다. " + result.get("MESSAGE", "요청 조건을 확인해 주세요."))
else:
    row = meal["mealServiceDietInfo"][1]["row"][0]
    for dish in row["DDISH_NM"].split("<br/>"):
        # 조회 화면에서는 메뉴와 알레르기 정보를 함께 보여 준다
        st.write(dish.strip())
    st.metric("칼로리", row["CAL_INFO"])

# pages/1_달력별_급식.py — 나이스 급식 API로 그날 식단을 카드로 보여 주는 페이지
import datetime
import re

import requests
import streamlit as st

st.title("🍚 우리 학교 급식")

# 날짜와 알레르기 스위치를 나란히 놓는다
left, right = st.columns([2, 1])
picked = left.date_input("날짜를 고르세요", value=(datetime.datetime.utcnow() + datetime.timedelta(hours=9)).date())  # 한국 시간 기준 오늘
show_allergy = right.toggle("알레르기 정보 보기", value=True)
ymd = picked.strftime("%Y%m%d")

# 나이스 급식 API — 인증키 없이 호출한다 (조회 기간은 하루)
url = "https://open.neis.go.kr/hub/mealServiceDietInfo"
params = {
    "Type": "json",                # 응답을 JSON으로
    "ATPT_OFCDC_SC_CODE": "B10",   # 서울시교육청
    "SD_SCHUL_CODE": "7010073",    # 당곡고등학교
    "MMEAL_SC_CODE": "2",          # 중식
    "MLSV_FROM_YMD": ymd,
    "MLSV_TO_YMD": ymd,
}
data = requests.get(url, params=params, timeout=10).json()

weekday = "월화수목금토일"[picked.weekday()]
st.subheader(picked.strftime("%Y년 %m월 %d일") + f" ({weekday}) 중식")

if "mealServiceDietInfo" not in data:
    result = data.get("RESULT", {})
    if result.get("CODE") == "INFO-200":
        st.info("조회한 날짜의 급식 정보가 없습니다.")
    else:
        st.error("급식 조회에 실패했습니다. " + result.get("MESSAGE", "요청 조건을 확인해 주세요."))
else:
    row = data["mealServiceDietInfo"][1]["row"][0]
    # 메뉴 전체가 한 덩어리 글자로 온다 — <br/>로 잘라 낱개 메뉴로
    dishes = [d.strip() for d in row["DDISH_NM"].split("<br/>") if d.strip()]
    if not show_allergy:

        dishes = [re.sub(r"\s*\([0-9.]+\)", "", d) for d in dishes]

    # 큰 숫자 카드 — 메뉴 가짓수와 칼로리
    m1, m2 = st.columns(2)
    m1.metric("메뉴", f"{len(dishes)}가지")
    m2.metric("칼로리", row["CAL_INFO"])

    # 메뉴를 카드 세 칸씩 나란히
    cols = st.columns(3)
    for i, dish in enumerate(dishes):
        with cols[i % 3].container(border=True):
            st.write(dish)

# pages/2_메뉴별_급식.py — 인증키로 두 학기를 한 번에 받아 최다 등장 메뉴 TOP N
import re

import pandas as pd
import plotly.express as px
import requests
import streamlit as st

st.title("🥇 조회 기간의 최다 등장 메뉴")


@st.cache_data
def load_lunch(frm, to, api_key):
    days = {}
    page = 1
    received = 0
    while True:
        response = requests.get(
            "https://open.neis.go.kr/hub/mealServiceDietInfo",
            params={
                "Type": "json", "KEY": api_key,
                "pSize": 1000, "pIndex": page,
                "ATPT_OFCDC_SC_CODE": "B10", "SD_SCHUL_CODE": "7010073",
                "MMEAL_SC_CODE": "2", "MLSV_FROM_YMD": frm, "MLSV_TO_YMD": to,
            }, timeout=20,
        )
        response.raise_for_status()
        res = response.json()
        if "mealServiceDietInfo" not in res:
            result = res.get("RESULT", {})
            if result.get("CODE") == "INFO-200" and page == 1:
                return {}
            raise ValueError("급식 데이터를 모두 받지 못했습니다. " + result.get("MESSAGE", "응답을 확인해 주세요."))
        head = res["mealServiceDietInfo"][0]["head"]
        total = next(item["list_total_count"] for item in head if "list_total_count" in item)
        rows = res["mealServiceDietInfo"][1]["row"]
        if not rows:
            raise ValueError(f"전체 {total}건인데 받은 행이 없습니다. 인증키를 확인해 주세요.")
        for row in rows:
            # 원본은 유지하고, 빈도 집계용 메뉴 이름에서만 알레르기 번호를 제거한다.
            dishes = [re.sub(r"\s*\([0-9.]+\)", "", d).strip() for d in row["DDISH_NM"].split("<br/>")]
            days.setdefault(row["MLSV_YMD"], set()).update(d for d in dishes if d)
        received += len(rows)
        if received >= total:
            return days
        if len(rows) < 1000:
            # 더 받을 쪽이 없는데 전체 건수에 못 미친다 — 인증키 없이 부른 경우다
            raise ValueError(
                f"전체 {total}건 가운데 {received}건만 받았습니다. 인증키를 확인해 주세요."
            )
        page += 1


try:
    api_key = st.secrets["NEIS_API_KEY"]
except Exception:
    st.error("Secrets 설정에 NEIS_API_KEY가 없습니다. 3절의 인증키 안내를 확인해 주세요.")
    st.stop()

try:
    meals = load_lunch("20250901", "20260930", api_key)
except (requests.RequestException, ValueError) as error:
    st.error(str(error))
    st.stop()
if not meals:
    st.info("조회 기간의 급식 정보가 없습니다.")
    st.stop()
days = len(meals)

counts = (pd.Series([d for dishes in meals.values() for d in dishes])
          .value_counts().rename_axis("메뉴").reset_index(name="일수"))
counts["비율(%)"] = (counts["일수"] / days * 100).round(0).astype(int)

# 몇 위까지 볼지 슬라이더로 고른다
top_n = st.slider("몇 위까지 볼까요?", min_value=5, max_value=20, value=10)
top = counts.head(top_n).copy()
top.insert(0, "순위", range(1, len(top) + 1))

# 큰 숫자 카드 셋 — 집계 일수, 1위 메뉴, 1위 비율
first = top.iloc[0]
c1, c2, c3 = st.columns(3)
c1.metric("집계한 날", f"{days}일")
c2.metric("1위 메뉴", first["메뉴"])
c3.metric("1위 등장 비율", f"{first['비율(%)']}% ({first['일수']}일)")

# 막대는 1위가 맨 위, 값이 클수록 진한 색, 막대마다 일수와 비율
top["표시"] = top["일수"].astype(str) + "일 (" + top["비율(%)"].astype(str) + "%)"
fig = px.bar(
    top.sort_values("일수"), x="일수", y="메뉴", orientation="h",
    text="표시", color="일수", color_continuous_scale="Oranges",
    title=f"중식 {days}일 중 가장 자주 나온 메뉴 TOP {top_n}",
)
fig.update_layout(coloraxis_showscale=False, xaxis_title="등장 일수", yaxis_title="")
st.plotly_chart(fig, width="stretch")

st.dataframe(top[["순위", "메뉴", "일수", "비율(%)"]], hide_index=True, width="stretch")
st.caption(f"중식 {days}일 기준 · 이 그래프로 알 수 있는 것: (한 문장으로 적어 보세요)")

화면이 둘 이상이 되면 한 파일에 덮어쓰지 말고 pages 폴더로 나눕니다. main.py 옆에 pages 폴더를 두면 그 안의 파일 하나하나가 왼쪽 메뉴의 페이지가 됩니다. 폴더 이름은 소문자 pages여야 하고, 위치는 main.py와 나란한 곳이며, 파일 이름은 .py로 끝나야 합니다.

규칙내용
폴더 이름pages로 고정 — 다른 이름은 메뉴로 인식되지 않는다
메뉴 순서파일 이름 앞의 숫자가 정하고, 숫자가 같으면 이름 순서다 (1_달력별_급식.py → 2_메뉴별_급식.py). 여기서 앞 숫자는 페이지의 표시 순서입니다
첫 화면main.py가 첫 화면이 되어 메뉴 맨 위에 놓인다. 파일 이름에서 앞 숫자와 밑줄을 뗀 것이 메뉴 이름이다
오늘이 끝나면
내 저장소/
├── main.py              ← 첫 화면: 학교를 골라 급식 보기
├── requirements.txt     ← 저장소에 하나. 앱 전체에 적용된다
└── pages/
    ├── 1_달력별_급식.py    ← 우리 학교, 날짜를 골라 보기 (API)
    └── 2_메뉴별_급식.py    ← 우리 학교, 조회 기간의 최다 메뉴 (API·인증키)

5. 발견 — 184일의 1위

메뉴별 등장 빈도를 알아보려면 조회 기간 전체의 급식을 모아야 합니다. 아래는 교재 작성 당시 2025년 9월~2026년 9월을 조회해 얻은 중식 184일을 집계한 예시입니다. 메뉴 이름을 정리해 세었을 때 고유 메뉴는 498개, 하루 평균 메뉴 수는 6.8개였습니다. 실시간 API의 등록·수정 상황에 따라 여러분이 얻은 건수와 결과는 달라질 수 있습니다.

6. 확인 문제

문제 1 일요일 날짜로 급식 API를 불렀더니 식단 없이 "해당하는 데이터가 없습니다"라는 안내만 왔습니다. 가장 알맞은 해석은 무엇일까요?
해당 조건에 등록된 급식 데이터가 없다는 뜻입니다. 급식이 없거나 식단이 아직 등록되지 않았을 수 있으므로, 앱에는 "조회한 날짜의 급식 정보가 없습니다"라고 안내합니다. 인증 오류나 요청 실패와는 구분해야 합니다.
문제 2 KOBIS와 나이스 급식 API의 차이를 인증키를 중심으로 두 가지 써 보세요.
예시 답 펼쳐 보기

① KOBIS는 요청에 인증키가 필요하지만, 나이스 급식 API는 인증키 없이도 호출할 수 있다. ② 나이스는 인증키가 없으면 한 번에 받는 건수가 제한되고 pSize와 pIndex도 무시된다. 넓은 기간을 조회할 때는 인증키를 사용하고 전체 데이터를 받았는지 확인한다. 두 API 모두 발급받은 키는 코드에 직접 쓰지 않고 Secrets에 저장한다.
