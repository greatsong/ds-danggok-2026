데이터베이스와 SQL · 앱 뒤에서 벌어지는 일

"버튼을 누르면 데이터베이스에서 SQL 문장이 실행된다."
인스타그램·카카오톡·게임이 데이터를 다루는 방식을 SQL 문장으로 읽습니다.

피드를 불러오고, 메시지를 보내고, 게임 랭킹을 확인할 때 앱은 데이터를 다룹니다. 어떤 동작은 저장된 기록을 가져오고, 어떤 동작은 새 기록을 넣거나 기존 값을 바꿉니다. 오늘은 익숙한 앱의 동작을 테이블의 행과 열을 다루는 일로 바꾸어 살펴봅니다. 그리고 그 일을 표현하는 언어인 SQL을 읽어 봅니다.

이 수업의 앱 화면과 SQL은 원리를 설명하기 위한 가상 예시입니다. 실제 서비스의 내부 구조를 재현한 것은 아닙니다. 문장을 외우기보다, 어느 데이터를 대상으로 무엇을 하는지 읽는 데 집중합니다.

🎯 오늘 하는 것
  • 저장 구조 이해하기 — 데이터셋·데이터베이스·테이블을 구분하고, 파일을 주고받는 방식과 데이터베이스를 사용하는 방식을 비교한다.
  • SQL 읽기 — 조회·추가·갱신·삭제와 집계를 표현하는 문장을 읽는다.
  • 앱 기능과 연결하기 — 피드, 메시지, 게임 전적 화면의 동작을 SQL과 연결한다.

0. 오늘의 목표

12차시에는 모델의 예측 결과를 평가했습니다. 이번에는 분석할 데이터가 어디에, 어떤 구조로 저장되는지 살펴봅니다.

여러 사람이 함께 사용하는 앱에서는 새 기록을 계속 저장하면서 필요한 기록을 골라 읽어야 합니다. 오늘은 이러한 작업을 데이터베이스에서 어떻게 표현하는지 익힙니다.

  • 데이터셋·데이터베이스·테이블을 실습의 예와 연결해 구분할 수 있다.
  • SQL 문장을 읽고 조회·추가·갱신·삭제 중 어떤 동작인지, 어느 테이블의 어떤 행이 대상인지 설명할 수 있다.
  • WHERE·COUNT·GROUP BY의 역할을 설명하고 앱의 기능과 연결할 수 있다.

1. 데이터셋·데이터베이스·테이블 이해하기

📖 교과서의 설명 『데이터 과학』 27쪽

"데이터베이스의 각 테이블에 저장된 데이터들은 공통적인 속성을 기반으로 서로 연결될 수 있다." (27쪽)

교과서는 도서관의 책 목록과 대출 기록을 예로 듭니다. 게시물과 댓글도 같은 방식으로 설계할 수 있습니다. 게시물은 게시물 테이블에, 댓글은 댓글 테이블에 저장하고, 게시물 번호로 두 테이블을 연결하는 것입니다.

📖 교과서의 정의 『데이터 과학』 25~27쪽

"데이터셋(dataset)이란 하나의 주제에 대한 여러 데이터들이 모인 집합(set)을 말한다." (25쪽)

"데이터베이스(database)는 여러 사람이 공유하여 사용하기 위해 통합 관리되는 데이터의 집합으로, 데이터베이스 시스템을 사용하면 대규모의 데이터를 효율적으로 저장하고 검색하며, 업데이트하고 관리할 수 있다." (26쪽)

"데이터베이스에는 여러 종류의 데이터셋이 들어가는데, 이때 각각의 데이터셋은 표 형태로 저장되며 이를 테이블(table)이라고 한다." (27쪽)

이번 수업에서는 데이터를 표 형태로 관리하는 관계형 데이터베이스를 다룹니다. 급식 기록을 CSV 파일에 담을 수도 있고, 데이터베이스의 테이블에 저장할 수도 있습니다. 데이터베이스 안에는 여러 테이블을 둘 수 있으며, 공통된 정보를 기준으로 테이블을 연결할 수 있습니다.

🧩 세 용어를 우리 실습에 연결하기

세 용어는 단순히 크기로 구분하지 않습니다. 무엇에 초점을 두느냐가 다릅니다.

데이터셋은 한 주제로 모은 데이터입니다. 10차시에서 사용한 급식 기록이 한 예이며, CSV는 그 데이터를 담는 파일 형식입니다.

데이터베이스는 데이터를 함께 사용하도록 통합 관리하는 저장소입니다. 15차시에 사용할 수파베이스(Supabase) 프로젝트에는 PostgreSQL 데이터베이스가 제공되며, 그 안에 여러 테이블을 만들 수 있습니다.

테이블은 데이터를 행과 열로 관리하는 구조입니다. 게시물 테이블에서는 게시물 한 건이 한 행이고, 메시지 테이블에서는 메시지 한 건이 한 행입니다. 같은 기록을 테이블에 저장했다가 CSV로 내려받더라도, 데이터셋이라는 성격이 달라지는 것은 아닙니다.

그림에는 게시물과 댓글 테이블의 일부 열만 표시했습니다. 실제 댓글 테이블에는 어느 게시물에 달린 댓글인지 나타내는 게시물 번호 열이 있어야 두 테이블을 연결할 수 있습니다. 어떤 정보를 열로 둘지는 앱에서 무엇을 기록하고 활용할지에 따라 정합니다.

파일 사본을 주고받는 방식도 사용할 수 있습니다. 다만 여러 사람이 동시에 수정하거나 기록이 계속 쌓이면, 변경 사항을 합치고 충돌을 처리할 방법이 필요합니다. 데이터베이스는 이런 작업을 관리하는 기능을 제공합니다.

동시에 쓰기같은 원본의 사본을 각자 수정해 덮어쓰면 한쪽 변경이 사라질 수 있다.여러 입력을 처리하고 각 기록을 저장하는 기능을 사용할 수 있다.
계속 쌓기새 기록을 추가하고 충돌을 처리할 프로그램이 필요하다.추가 명령으로 기록을 누적하고 정해 둔 제약을 검사한다.

데이터베이스를 사용한다고 문제가 저절로 해결되는 것은 아닙니다. 동시 처리 방식, 데이터의 제약, 접근 권한을 목적에 맞게 설정해야 합니다.

🔬 움직여 보기 — 파일과 데이터베이스의 동시 저장 비교하기

그림을 클릭하면 한 단계씩 진행됩니다. A가 기록을 추가하는 동안 B도 같은 원본을 바탕으로 기록을 추가한 뒤, 두 사람이 차례로 저장하는 상황입니다.

파일을 통째로 덮어쓰는 경우와 새 기록을 각각 추가하는 경우에, A와 B의 메시지가 어떻게 남는지 비교합니다.

이 그림은 파일 사본을 따로 수정한 뒤 같은 원본에 덮어쓰는 상황을 단순화한 것입니다. CSV를 사용하면 언제나 기록이 사라진다는 뜻은 아닙니다. 어떤 방식으로 저장하고 충돌을 처리하는지가 중요합니다.

데이터를 추가(Create)하고, 조회(Read)하고, 갱신(Update)하고, 삭제(Delete)하는 네 동작을 CRUD라고 합니다. 다음 절에서는 이 동작을 SQL로 표현하고, 시뮬레이터에서 결과를 확인합니다.

2. SQL 문장 읽기

SQL은 데이터베이스에 어떤 데이터를 가져오고, 넣고, 바꾸고, 지울지 표현하는 언어입니다.

이번에는 DG창체부의 동아리 지원 시스템을 통해 SQL 문법을 먼저 익힙니다. 그다음 피드, 메신저, 게임 전적 앱에서 동일한 동작을 살펴봅니다. 피드에서는 조회를, 메신저에서는 추가·갱신·삭제를, 게임 전적에서는 집계를 다룹니다.

SQL 문장의 기본 구조 읽기

처음부터 긴 조회문을 한 번에 읽으면 이해하기 어렵습니다. 가장 짧은 문장부터 시작하여 단계별로 절을 하나씩 덧붙입니다. 예시는 DG창체부가 만든 동아리 지원 웹앱입니다. 창체부는 이 앱으로 지원서를 한꺼번에 접수합니다. 각 동아리는 지원자를 평가하며, 자기 동아리의 최종 합격자를 실시간으로 확인합니다.

학생 30명이 방송부, 과학부, 수리정보영재반, 댄스부, 미술부 다섯 동아리 가운데 한 곳에 지원하였습니다. 평가가 끝나 지원서마다 자기소개서 점수와 면접 점수가 입력되어 있습니다. 이 기록은 지원 테이블에 지원자 한 명이 한 행으로 저장되어 있습니다. 합격자 명단은 따로 저장하지 않고 조회할 때마다 계산하므로, 점수가 바뀌면 명단도 곧바로 바뀝니다.

조회가 아니라 데이터를 바꾸는 문장은 첫 부분부터 다릅니다. 동아리 지원 테이블도 지원서가 새로 들어오거나, 점수를 고치거나, 지원을 취소하면 내용이 바뀝니다.

INSERT INTO어느 테이블의 어느 열에 새 행을 넣을까 — INSERT INTO 테이블 (열, 열) VALUES (값, 값);
UPDATE어느 행의 어느 값을 바꿀까 — UPDATE 테이블 SET 열 = 값 WHERE 조건;
DELETE FROM어느 행을 지울까 — DELETE FROM 테이블 WHERE 조건;

VALUES 뒤 괄호 안의 값은 앞에 적은 열의 순서대로 적습니다. 열 목록을 생략하고 INSERT INTO 테이블 VALUES (값, 값, …);처럼 적을 수도 있습니다. 이때는 테이블에 정의된 모든 열의 순서대로 값을 적어야 합니다. 예를 들어 서다온의 지원서를 점수까지 한 번에 넣으면 다음과 같습니다. INSERT INTO 지원 VALUES (20133, '서다온', '미술부', 40, 44, '2026-10-05 21:30');

파이썬 대신 SQL을 사용하는 이유

앞 차시에서는 CSV 파일을 파이썬으로 읽어 분석하였습니다. 방송부 지원자를 골라 면접 점수가 높은 순으로 정렬하는 작업을 파이썬과 SQL로 각각 작성하여 비교합니다.

파이썬 · 찾는 절차를 직접 작성
result = []
for row in rows:
    if row["지원동아리"] == "방송부":
        result.append(row)
result.sort(key=lambda r: r["면접"], reverse=True)
SQL · 원하는 결과만 작성
SELECT 이름
FROM 지원
WHERE 지원동아리 = '방송부'
ORDER BY 면접 DESC;

파이썬은 반복, 조건 확인, 정렬 같은 절차를 직접 작성합니다. 반면 SQL은 원하는 결과만 기술하면 되며, 그 결과를 찾는 방법은 데이터베이스가 결정합니다.

SQL을 사용하는 이유설명
필요한 행만 받아 온다게시물이 수억 개에 달하더라도 데이터베이스 서버는 조건에 맞는 행만 골라 전송합니다. 파이썬으로 처리하려면 먼저 전체 데이터를 가져와야 합니다. 검색에 사용하는 열에 색인(인덱스)을 만들어 두면, 데이터베이스는 전체를 훑지 않고도 조건에 맞는 행을 빠르게 찾습니다.
여러 사람이 동시에 읽고 쓴다1절에서 살펴보았듯이 파일 사본을 덮어쓰면 변경 사항이 사라질 수 있습니다. 데이터베이스는 여러 사용자의 요청이 동시에 들어와도 서로의 변경을 덮어쓰지 않도록 처리 순서를 조정하며, 권한 관리와 기본 키 중복 방지 기능도 제공합니다.
어느 프로그램에서나 사용한다앱이 자바로, 웹이 자바스크립트로 만들어졌더라도 데이터베이스에는 SQL로 요청합니다. 파이썬 코드 안에서 SQL 문장을 전송하여 사용하는 경우도 많습니다. 우리 갤러리가 활용하는 수파베이스 역시 SQL 데이터베이스(PostgreSQL)입니다.

두 언어는 역할이 다릅니다. SQL은 데이터를 저장하고 필요한 만큼 꺼내는 일을, 파이썬은 꺼낸 데이터로 그래프를 그리고 모델을 만드는 일을 담당합니다.

① 게시물 조회하기 — 인스타그램형 피드와 SELECT

피드에서 최근 게시물을 불러오는 동작을 SQL로 표현해 봅니다. 게시물 테이블에서 필요한 열을 고르고, 최근 순으로 정렬한 뒤, 일부 행만 가져오는 방식입니다.

아래 posts는 게시물 한 건을 한 행으로 저장하는 연습용 테이블입니다. 실제 인스타그램의 테이블 구조나 조회 방식을 나타내지는 않습니다.

SQL · 읽기
-- 피드를 연다: 최근 게시물 20개의 작성자, 해시태그, 올린 시각을 가져온다
SELECT 작성자, 해시태그, 올린시각
FROM posts
ORDER BY 올린시각 DESC
LIMIT 20;

-- #고양이를 검색한다: 해시태그에 '#고양이'가 들어 있는 게시물만 가져온다
SELECT * FROM posts WHERE 해시태그 LIKE '%#고양이%';
명령어·표현역할피드 예시에서의 뜻
SELECT가져올 열을 고른다. *는 모든 열을 뜻한다.작성자·해시태그·올린 시각을 가져온다.
FROM대상 테이블을 지정한다.게시물 테이블에서 가져온다.
WHERE조건에 맞는 행을 고른다.검색 조건을 만족하는 게시물을 찾는다.
ORDER BY정렬 기준을 지정한다.최근 게시물부터 정렬한다.
LIMIT가져올 행 수의 상한을 정한다.우선 20개까지 가져온다.
LIKE '%#고양이%'문자열에 해당 문구가 포함되는지 확인한다.다른 태그와 함께 적혀 있어도 #고양이가 들어 있으면 찾는다.

첫 문장은 최근 게시물 20개까지의 작성자·해시태그·올린 시각을 가져옵니다. 두 번째 문장은 해시태그 열에 #고양이라는 문자열이 포함된 게시물을 찾습니다.

LIKE에서 %는 글자 수가 0개 이상인 아무 문자열을 뜻합니다. 따라서 '%#고양이%'는 앞뒤에 다른 내용이 있더라도 #고양이가 포함된 값을 찾습니다. 다만 #고양이용품처럼 같은 문자열을 포함한 다른 태그도 함께 찾습니다.

피드 위젯의 더 보기는 게시물을 두 개씩 추가로 보여 줍니다. 가져올 수는 LIMIT 2로 두고, 이미 본 게시물 수만큼 OFFSET을 늘립니다. 예를 들어 LIMIT 2 OFFSET 4는 앞의 네 행을 건너뛴 뒤 최대 두 행을 가져옵니다.

② 메시지 추가·갱신·삭제하기 — 카카오톡형 메신저

메시지를 보내는 일과 읽음 표시를 바꾸는 일은 데이터베이스에서 서로 다른 동작입니다.

이 예시에서는 메시지를 보내면 새 행이 추가됩니다. 읽음 표시를 바꾸면 기존 행의 값이 갱신되고, 메시지를 지우면 해당 행이 삭제됩니다.

messages는 이 차이를 살펴보기 위한 연습용 테이블입니다. 실제 메신저의 전송·저장·삭제 방식을 그대로 재현한 것은 아닙니다.

SQL · 추가 · 갱신 · 삭제
-- 추가(INSERT): 메시지를 보내면 테이블에 새 행이 하나 생긴다
INSERT INTO messages (방id, 보낸사람, 내용, 읽음)
VALUES (12, '석리송', '오늘 급식 뭐야?', false);

-- 갱신(UPDATE): 상대가 읽으면 그 행의 '읽음'이 true가 되고, 숫자 1이 사라진다
UPDATE messages SET 읽음 = true WHERE id = 305;

-- 삭제(DELETE): 내가 보낸 메시지를 지운다
DELETE FROM messages WHERE id = 305 AND 보낸사람 = '석리송';
명령어·표현역할메신저 예시에서의 동작
INSERT INTO … VALUES새 행을 넣는다.메시지를 전송한다.
UPDATE … SET기존 행의 값을 바꾼다.읽음 표시를 변경한다.
DELETE FROM행을 지운다.메시지를 삭제한다.
WHERE처리할 행을 조건으로 고른다.특정 번호이면서 지정한 사람이 보낸 메시지만 대상으로 삼는다.

뒤의 SQL 시뮬레이터 쓰기 탭에는 ‘WHERE 없이 DELETE’ 버튼이 있습니다. 이 버튼을 실행하고 남은 댓글 수를 활동지에 기록한 뒤, 다음 설명을 읽습니다.

⚠️ UPDATE·DELETE의 대상과 권한 확인하기

이 버튼이 실행하는 DELETE FROM comments;에는 대상을 제한하는 WHERE가 없습니다. 테이블 전체를 삭제할 권한이 있고 다른 제한이 없다면, comments의 모든 행이 삭제됩니다. 특정 게시물의 댓글이나 내가 작성한 댓글만 대상으로 삼는 문장이 아닙니다.

안전하게 데이터를 다루려면 대상 조건과 접근 권한을 함께 확인해야 합니다. WHERE는 “어떤 행을 처리할 것인가”를 표현합니다. 접근 권한은 “이 사용자가 어떤 작업을 할 수 있는가”를 제한합니다. 실제 서비스에서는 로그인한 사용자와 서버·데이터베이스의 권한 설정을 연결해야 합니다.

따라서 WHERE가 있다는 이유만으로 안전하다고 판단하지 않습니다. 조건이 의도한 대상을 가리키는지, 그 작업을 수행할 권한이 적절한지 확인합니다.

게임 전적 화면에는 판수, 승률, 캐릭터별 평균 점수처럼 기록을 요약한 값이 표시됩니다. 이번에는 이런 값을 전적 테이블의 행을 집계해 구하는 방식으로 살펴봅니다.

matches에서는 대전 기록 한 판이 한 행입니다. 판수는 해당하는 행의 개수이고, 승률은 대상으로 삼은 경기 중 이긴 경기의 비율입니다. 따라서 숫자를 읽을 때는 누구의 경기인지, 어느 기간의 기록인지, 어떤 경기를 포함했는지 함께 확인해야 합니다.

아래 첫 문장은 테이블에 있는 기록 중 '석리송'이 이긴 판을 셉니다. 시즌 조건은 포함되어 있지 않습니다. 두 번째 문장은 캐릭터별로 기록을 묶고, 각 묶음의 판수와 평균 점수를 계산합니다. 그 결과를 평균 점수가 높은 순으로 정렬해 세 행까지 가져옵니다.

SQL · 세기와 묶기
-- 석리송이 이긴 판은 모두 몇 판인가
SELECT COUNT(*) FROM matches WHERE 플레이어 = '석리송' AND 결과 = '승';

-- 캐릭터별로 묶어 판수와 평균 점수를 구하고, 평균이 높은 캐릭터부터 세 줄만
SELECT 캐릭터, COUNT(*) AS 판수, AVG(점수) AS 평균점수
FROM matches
GROUP BY 캐릭터
ORDER BY 평균점수 DESC
LIMIT 3;
명령어·표현역할전적 화면에서의 뜻
COUNT(*)대상 행의 개수를 센다.조건에 맞는 경기의 판수를 구한다.
GROUP BY지정한 열의 값이 같은 행끼리 묶는다.캐릭터별 또는 플레이어별로 집계한다.
COUNT · SUM · AVG · MAX · MIN개수·합계·평균·최댓값·최솟값을 구한다.판수·평균 점수·최고 점수 등을 계산한다.
AS결과 열에 이름을 붙인다.집계 결과를 ‘판수’, ‘평균점수’라는 이름으로 표시한다.

COUNT(*)는 행 수를 세고, AVG(점수)는 대상 점수의 평균을 구합니다. 무엇을 집계하는지에 따라 사용하는 함수가 달라집니다.

GROUP BY에서 먼저 확인할 것은 묶는 기준입니다. 20판의 기록을 네 종류의 캐릭터로 묶으면, 캐릭터별 집계 결과는 네 행이 됩니다.

한 캐릭터의 묶음 안에는 점수가 여러 개 들어 있습니다. 따라서 캐릭터별 결과 한 행에 점수를 표시하려면, 평균·합계·최댓값처럼 어떤 값으로 요약할지 정해야 합니다. 이번 예제에서는 AVG(점수)로 평균을 구합니다.

⑤ 테이블 설계하기 — 설계표와 CREATE TABLE

테이블을 사용하려면 먼저 무엇을 한 행으로 기록하고, 어떤 정보를 열로 둘지 정해야 합니다.

교과서 31쪽에서는 속성명·설명·데이터형·조건으로 설계표를 작성합니다. 속성은 테이블의 열을 가리키며, 속성명은 곧 열 이름입니다. SQL은 이 설계를 데이터베이스에 표현하는 방법입니다.

AI에게 설계안을 제안받을 수는 있습니다. 다만 무엇을 기록할지, 어떤 값은 허용하지 않을지, 나중에 무엇을 분석할지는 직접 정하고 검토해야 합니다.

    🔎 심화 — 외래 키와 JOIN
    
    
      
    교과서의 쇼핑몰 설계에서 장바구니에는 어느 사용자가 어떤 제품을 담았는지를 기록합니다. 사용자와 제품의 상세 정보를 매번 다시 적는 대신, 각 테이블의 id를 참조할 수 있습니다.
    
  
    이 예시에서 다른 테이블의 id를 참조하는 열이 외래 키입니다. 이렇게 연결된 정보를 함께 조회할 때 JOIN을 사용할 수 있습니다.
    
      
    SQL · JOIN
    -- 장바구니에 담긴 제품의 이름과 수량을, 장바구니 테이블과 제품 테이블을 제품 id로 이어서 가져온다
SELECT 장바구니.사용자id, 제품.제품명, 장바구니.수량
FROM 장바구니
JOIN 제품 ON 장바구니.제품id = 제품.id;
    
      
    이 문장은 장바구니의 제품 번호와 제품 테이블의 id가 같은 행을 연결해, 제품명과 수량을 함께 가져옵니다.
    
  
    이번에는 서로 연결할 정보를 어떤 열에 기록하는지 이해하면 됩니다. JOIN 문장을 직접 작성하는 연습은 팀 프로젝트에서 여러 테이블을 함께 사용할 때 이어 갑니다.
    
    
    
  
    

  
    3. 정리 — 앱의 동작을 데이터 처리로 읽기
    
  
    피드를 불러오는 일은 조회, 메시지를 보내는 일은 추가, 읽음 표시를 바꾸는 일은 갱신, 메시지를 지우는 일은 삭제로 표현했습니다. 게임 전적에서는 조건에 맞는 기록을 세고, 같은 값끼리 묶어 집계했습니다.
    
  
    문장을 읽을 때는 어떤 동작인지, 어느 테이블이 대상인지, 어떤 조건을 적용하는지 확인합니다. 조회문이라면 가져올 열과 정렬 기준, 행 수 제한도 함께 봅니다.
    
  
    오늘의 중심 표현은 다음과 같습니다.
    
  
    
    
    확인할 내용SQL
    
    
      
    무엇을, 어디에서 가져오는가SELECT·FROM
    
      
    어떤 행을 대상으로 하는가WHERE
    
      
    어떤 순서로, 몇 행까지 가져오는가ORDER BY·LIMIT
    
      
    새로 넣는가, 값을 바꾸는가, 지우는가INSERT·UPDATE·DELETE
    
      
    몇 개인가, 무엇을 기준으로 묶는가COUNT·GROUP BY
    
        
  
    
  
    DESC·ASC·LIKE·AND·AS·AVG·MAX·MIN·SUM은 문장 안에서 만났을 때 역할을 찾아 설명할 수 있으면 됩니다.
    
  
    SQL을 읽는 목적은 명령어를 많이 외우는 데 있지 않습니다. AI가 작성한 문장이 내가 의도한 데이터를 대상으로 작동하는지 확인하는 것이 중요합니다. 특히 일부 기록만 바꾸거나 지우려는 문장에서는 대상 조건과 권한을 주의 깊게 살펴야 합니다.
    
  
    다음 시간에는 데이터를 수집·분석·공개할 때의 윤리적 기준을 생각합니다. 15차시에는 오늘 살펴본 대결 기록 테이블을 실제로 만들고, 학급의 선택을 데이터베이스에 저장합니다.
    

  
    4. 확인 문제
    
  
    
    
    문제 1 모둠 과제의 CSV 파일을 메신저로 주고받는 방식과 비교해, 데이터베이스를 사용할 때의 이점을 두 가지 적습니다. 답을 쓴 뒤 예시와 비교합니다.
    
    
    예시 답 펼쳐 보기
      
    여러 사람이 보낸 기록을 한곳에 저장하고, 조건에 따라 조회·집계할 수 있습니다. 동시 입력, 데이터의 제약, 접근 권한을 관리하는 기능도 사용할 수 있습니다. 다만 이러한 기능이 목적에 맞게 작동하도록 설정해야 합니다. 파일을 사용하는 방식에서도 별도의 프로그램으로 비슷한 작업을 구현할 수 있습니다.
    
    
    
  
    
  
    
    
    문제 2 다음 중 실습에서 테이블에 해당하는 것은 무엇입니까?
    
    
    
      
    우리 실습에서 테이블에 해당하는 것은?
    
      
    
        
        
        
      
    
      
    matches는 전적 한 판을 한 행으로 저장하는 테이블입니다. 급식 CSV는 데이터셋을 담은 파일의 한 형태입니다. 관계형 데이터베이스에서는 여러 테이블을 저장하고 관리할 수 있습니다.
    
    
    
    
    세 용어의 관계 펼쳐 보기
      
    데이터셋은 모아 놓은 데이터에, 데이터베이스는 데이터를 통합 관리하는 데, 테이블은 데이터를 행과 열로 저장하는 구조에 초점을 둔 말입니다.
    
    
    
  
    
  
    SQL 문장 고르기. 화면에서 벌어지는 일을 읽고 알맞은 문장을 고릅니다. 답을 누르면 해설이 나옵니다.
    
  
    
    
    문제 3 메신저 예시에서 석리송이 보낸 메시지 id = 305를 상대가 읽었습니다. 메시지는 그대로 있고 노란 숫자 1만 사라졌다면, 어떤 문장이 이 동작에 대응합니까?
    
    
    
      
    
        
        
        
      
    
      
    기존 메시지의 읽음 값만 바꾸므로 UPDATE입니다. DELETE는 행을 삭제하고, INSERT는 새 행을 추가하는 동작입니다.
    
    
    
  
    
  
    
    
    문제 4 게임 전적 화면에 캐릭터별 평균 점수를 표시하려고 합니다. 알맞은 문장을 고릅니다.
    
    
    
      
    
        
        
        
      
    
      
    GROUP BY 캐릭터로 기록을 묶고, AVG(점수)로 각 묶음의 평균을 구합니다. ①은 개별 경기 기록을 점수가 높은 순으로 세 행까지 가져옵니다. 캐릭터별 평균을 구하지는 않습니다. ②의 WHERE 캐릭터는 이 예제의 문자열 열 이름만 적은 것으로, 필요한 조건을 제대로 표현하지 못했습니다.
    
    
    
  
    
  
    
    
    문제 5 AI에게 “내가 보낸 메시지를 지워 줘”라고 요청했습니다. 다음 중 요청보다 넓은 범위의 데이터를 지울 수 있어 실행 전에 반드시 고쳐야 할 문장은 무엇입니까?
    
    
    
      
    
        
        
        
      
    
      
    대상을 제한하는 조건이 없어, 권한과 다른 제한이 허용하는 범위에서 테이블 전체가 삭제 대상이 됩니다. ①은 메시지 번호와 보낸 사람이라는 두 조건을 모두 만족하는 행을 삭제합니다. ③은 조회문이므로 데이터를 지우지 않습니다. 다만 삭제 요청을 수행한 문장도 아닙니다.
    
    
    
  
    
  
    
    더 풀어 보기 — SQL 문장 고르기 세 문제(LIKE · ORDER BY와 LIMIT의 순서 · COUNT)
    
    
  
    
    
    더 풀기 1 해시태그 열에 #고양이 #박스처럼 여러 태그가 함께 저장되어 있습니다. #고양이라는 문자열이 포함된 게시물을 찾는 문장을 고릅니다. 어느 문장이 맞습니까?
    
    
    
      
    
        
        
        
      
    
      
    =는 열의 값 전체가 '#고양이'와 같은 행을 찾습니다. 따라서 '#고양이 #박스'는 ①의 조건에 맞지 않습니다. LIKE '%#고양이%'는 앞뒤에 다른 내용이 있어도 해당 문자열이 포함되면 찾습니다. 다만 #고양이용품처럼 같은 문자열을 포함한 값도 찾을 수 있으므로, 정확한 태그 하나를 구분하는 검색과는 차이가 있습니다.
    
    
    
  
    
  
    
    
    더 풀기 2 가장 최근 게시물 다섯 개까지 가져오는 문장을 고릅니다.
    
    
    
      
    
        
        
        
      
    
      
    올린 시각을 내림차순으로 정렬한 결과에서 앞의 다섯 행까지 가져옵니다. 이번 문장 구조에서는 ORDER BY 뒤에 LIMIT을 작성합니다. ②는 작성 순서가 맞지 않습니다. ③의 조건은 “최근 다섯 개”라는 뜻을 표현하지 못합니다.
    
    
    
  
    
  
    
    
    더 풀기 3 어떤 계정의 프로필에 ‘게시물 27’이라고 표시되어 있습니다. 작성자가 '석리송'인 게시물의 수를 구하는 문장을 고릅니다.
    
    
    
      
    
        
        
        
      
    
      
    COUNT(*)는 조건에 맞는 행의 개수를 셉니다. ①은 게시물별 작성자와 올린 시각을 조회합니다. ②는 게시물 번호 중 가장 큰 값을 구합니다. 게시물 번호에는 다른 계정의 기록이나 삭제된 기록의 영향이 있을 수 있으므로, 가장 큰 번호를 게시물 수로 볼 수는 없습니다.

    📚 오늘의 용어
    
  
    
    
    용어뜻
    
    
    데이터셋하나의 주제로 모은 데이터의 집합. CSV 파일은 이를 담는 한 가지 형식이다.
    
    
    데이터베이스데이터를 함께 사용하도록 통합 관리하는 저장소. 이번 수업에서는 관계형 데이터베이스를 다룬다.
    
    
    테이블관계형 데이터베이스에서 데이터를 행과 열로 관리하는 구조.
    
    
    수파베이스PostgreSQL 데이터베이스와 API·인증 등의 기능을 제공하는 서비스. 15차시에 사용한다.
    
    
    데이터 무결성정해 둔 규칙에 맞게 데이터의 정확성과 일관성을 유지하는 성질. 제약 조건은 이를 지키는 방법 중 하나다.
    
    
    SQL데이터베이스를 정의하고 데이터를 조회·추가·갱신·삭제하는 데 사용하는 언어.
    
    
    기본 키각 행을 유일하게 구분하는 열 또는 열의 조합. 이 수업의 대결 기록 테이블에서는 id를 사용한다.
    
    
    WHERE처리할 행의 조건을 지정하는 부분. 일부 행만 수정·삭제하려는 문장에서는 특히 주의해서 확인한다.
    
    
    ORDER BY · LIMIT결과의 정렬 기준과 가져올 행 수의 상한을 지정하는 부분.
    
    
    GROUP BY지정한 열의 값이 같은 행끼리 묶는 부분. COUNT·AVG 등의 함수와 함께 묶음별 집계를 구할 수 있다.
