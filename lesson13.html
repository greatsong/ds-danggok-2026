데이터베이스와 SQL · 앱 뒤에서 벌어지는 일

"버튼 하나를 누르면, 어딘가에서 한 줄의 문장이 실행된다."
오늘은 그 문장을 읽습니다 — 인스타그램·카카오톡·게임이 데이터를 다루는 방식

인스타그램에서 피드를 내리고, 카카오톡에서 메시지를 보내고, 게임에서 랭킹을 확인할 때마다 어딘가의 테이블에서 행을 가져오거나 새 행을 넣는 일이 일어납니다. 그 일을 시키는 말이 SQL입니다. 오늘은 여러분이 매일 쓰는 앱의 화면을 SQL 문장으로 바꿔 읽어 봅니다.

SQL 문장을 직접 외워 쓰는 것이 목표가 아닙니다. 화면에서 벌어지는 일과 문장이 어떻게 대응하는지 읽을 수 있으면 됩니다. 그래야 AI가 써 준 코드가 무엇을 하는 코드인지 알아볼 수 있습니다.

🎯 오늘 하는 것
  • 개념 — 데이터셋 · 데이터베이스 · 테이블, 그리고 CSV로 부족해지는 세 순간
  • SQL 읽기 — 조회 · 추가 · 갱신 · 삭제 · 묶어서 세기, 다섯 가지 동작
  • 실생활 앱 — 인스타그램 · 카카오톡 · 게임의 화면을 문장으로 바꿔 읽는다

0. 오늘의 목표

여러 사람이 함께 쓰는 서비스는 데이터를 파일 하나가 아니라 데이터베이스에 담습니다. 동시에 들어오는 입력을 각각 저장하고, 쌓인 기록에서 원하는 것만 골라 읽어야 하기 때문입니다. 그 저장소에 말을 거는 언어가 SQL이고, 오늘은 그 문장을 읽는 법을 익힙니다.

  • 데이터셋·데이터베이스·테이블을 실제 예에 각각 대응해 구분할 수 있다.
  • SQL 문장을 읽고 조회·추가·갱신·삭제 중 어느 동작인지, 어느 테이블의 어느 행이 대상인지 말할 수 있다.
  • WHERE·COUNT·GROUP BY가 각각 무엇을 하는지 설명하고, 앱 화면의 기능과 짝지을 수 있다.

1. 개념 이해 — 데이터셋, 데이터베이스, 테이블

📖 교과서의 설명 『데이터 과학』 27쪽

"데이터베이스의 각 테이블에 저장된 데이터들은 공통적인 속성을 기반으로 서로 연결될 수 있다." (27쪽)

→ 교과서는 도서관의 책 목록·대출 기록 테이블로 설명합니다. 인스타그램의 게시물 테이블와 댓글 테이블도 같은 구조이며, 게시물 번호로 서로 이어집니다.

📖 교과서의 정의 『데이터 과학』 25~27쪽

"데이터셋(dataset)이란 하나의 주제에 대한 여러 데이터들이 모인 집합(set)을 말한다." (25쪽)

"데이터베이스(database)는 여러 사람이 공유하여 사용하기 위해 통합 관리되는 데이터의 집합으로, 데이터베이스 시스템을 사용하면 대규모의 데이터를 효율적으로 저장하고 검색하며, 업데이트하고 관리할 수 있다." (26쪽)

"데이터베이스에는 여러 종류의 데이터셋이 들어가는데, 이때 각각의 데이터셋은 표 형태로 저장되며 이를 테이블(table)이라고 한다." (27쪽)

→ 급식 CSV는 데이터셋을 담은 한 가지 형태입니다. 관계형 데이터베이스는 같은 데이터를 테이블로 관리합니다. 하나의 데이터베이스가 여러 테이블을 담고, 테이블끼리는 공통된 열로 이어집니다.

🧩 데이터셋 · 데이터베이스 · 테이블 — 우리 실습에 대응하면

세 낱말은 크기가 아니라 담는 자격이 다릅니다. 데이터셋은 한 주제로 모인 데이터의 집합입니다. 12차시에 사용한 급식 CSV 파일 하나가 데이터셋을 담은 한 가지 형태입니다.

데이터베이스는 여러 사람이 함께 쓰도록 통합 관리되는 데이터의 집합입니다. 오늘 준비하는 Supabase 프로젝트 안의 저장소가 여기에 해당하며, 그 안에는 여러 개의 표가 들어갈 수 있습니다.

테이블은 그 안에 표 형태로 저장된 데이터셋 하나입니다. 인스타그램의 게시물 테이블, 카카오톡의 메시지 테이블, 게임의 전적 테이블가 모두 테이블입니다. 파일이냐 데이터베이스냐가 데이터셋의 자격을 정하지는 않습니다. 같은 대결 기록을 CSV로 내려받아도 그것은 여전히 같은 데이터셋입니다.

위 그림의 두 표는 일부 열만 보여 줍니다. 실제 서비스는 사진·해시태그·좋아요 수처럼 훨씬 많은 열을 함께 저장합니다.

여러 사람이 파일 사본을 주고받거나 파일 전체를 덮어쓰는 방식은 아래와 같은 문제가 생길 수 있습니다. 데이터베이스는 동시 처리, 조건 검색, 제약과 접근 권한을 관리하는 기능을 제공합니다. 이 기능들도 앱과 데이터베이스에 올바르게 설정해야 합니다.

파일 사본을 각각 수정해 덮어쓰는 상황을 단순화한 모식도입니다. 실습에서는 두 사람이 각각 대결을 마친 뒤 새로 조회해 두 기록이 모두 저장되었는지 확인합니다.

교과서 26쪽의 무결성 유지·보안 강화·체계적 관리 등의 이점을 실습과 연결해 봅니다. 기록의 변경 이력을 보존하려면 별도의 이력 관리나 백업 설정도 필요합니다. 데이터를 생성·읽기·갱신·삭제하는 네 동작을 CRUD라고 합니다. 아래 2절에서 이 네 동작을 문장 하나씩으로 읽어 보고, SQL 시뮬레이터에서 직접 실행해 봅니다.

파일은 형식이 정한 크기 한도를 넘으면 기록이 조용히 사라집니다. 데이터베이스는 행을 계속 추가하고 제약을 어기면 오류로 알립니다. 반찬 월드컵 앱에서 저장 결과를 확인하지 못했을 때 재선택을 잠그도록 만든 처리도 같은 이유에서 필요합니다.

2. SQL — 테이블을 다루는 언어

데이터베이스에 "무엇을 가져와라", "이걸 넣어라"라고 말하는 언어가 SQL입니다. 여러분이 쓰는 앱은 화면 뒤에서 하루에도 수없이 이 문장을 실행합니다. 오늘은 세 앱을 하나씩 맡아, 각각 다른 동작을 읽어 봅니다 — 인스타그램으로 읽기, 카카오톡으로 쓰기, 게임으로 묶어 세기입니다.

먼저 — SQL 문장을 읽는 법

SQL은 영어 문장처럼 생겼지만 외울 것이 많지 않습니다. 낱말이 앉는 자리가 정해져 있기 때문입니다. 아래 한 문장만 제대로 읽으면 오늘 나오는 모든 문장을 읽을 수 있습니다.

SELECT 작성자, 해시태그 FROM posts WHERE 작성자 = '석리송' ORDER BY 올린시각 DESC LIMIT 5;
SELECT무엇을 가져올까 — 작성자와 해시태그, 이 두 열만. *를 쓰면 모든 열입니다.
FROM어디서 가져올까 — 게시물 테이블(posts)에서.
WHERE어떤 행만 남길까 — 작성자가 '석리송'인 행만. 이 줄이 없으면 테이블의 모든 행이 대상입니다.
ORDER BY어떤 순서로 늘어놓을까 — 올린 시각 기준. DESC는 큰 것부터(최근부터), ASC는 작은 것부터입니다.
LIMIT몇 개만 가져올까 — 앞에서 다섯 줄만.

자리 순서는 바뀌지 않습니다 SELECT→FROM→WHERE→GROUP BY→ORDER BY→LIMIT

필요 없는 자리는 통째로 비웁니다. 조건이 없으면 WHERE를 쓰지 않고, 정렬이 필요 없으면 ORDER BY를 쓰지 않습니다. 그래서 짧은 문장은 SELECT * FROM posts;처럼 두 자리만 채워집니다.

가져오는 문장이 SELECT라면, 넣고·바꾸고·지우는 문장은 첫 낱말이 각각 INSERT·UPDATE·DELETE입니다. 이 셋도 자리가 정해져 있습니다.

INSERT INTO어느 테이블의 어느 열에 새 행을 넣을까 — INSERT INTO 테이블 (열, 열) VALUES (값, 값);
UPDATE어느 행의 어느 값을 바꿀까 — UPDATE 테이블 SET 열 = 값 WHERE 조건;
DELETE FROM어느 행을 지울까 — DELETE FROM 테이블 WHERE 조건;

기억할 것 — UPDATE와 DELETE에 WHERE를 빠뜨리면 테이블의 모든 행이 대상이 됩니다.

아래 세 위젯에서는 앱을 만질 때마다 실행된 문장이 오른쪽에 나타나고, 낱말마다 무슨 뜻인지 함께 표시됩니다. 문장을 외우지 말고, 자리마다 무엇이 들어갔는지 읽어 보십시오.

① 인스타그램으로 읽기 — SELECT 한 문장의 네 낱말

인스타그램을 열면 피드가 뜹니다. 그 순간 게시물 테이블에서 최근 글 몇 개를 가져오는 문장이 실행됩니다. 어느 테이블에서(FROM) 어느 열을(SELECT) 가져올지 말하고, 필요하면 조건(WHERE)과 정렬(ORDER BY)을 덧붙입니다. 대문자로 쓴 낱말이 명령어이고 나머지가 테이블 이름과 열 이름입니다.

아래 posts는 게시물 한 건이 한 행인 테이블입니다. 이 수업에서 원리를 설명하려고 단순하게 만든 예시이며, 실제 인스타그램의 테이블 구조는 아닙니다.

SQL · 읽기
-- 피드를 연다: 최근 게시물 20개의 작성자와 올린 시각을 가져온다
SELECT 작성자, 해시태그, 올린시각
FROM posts
ORDER BY 올린시각 DESC
LIMIT 20;

-- #고양이를 검색한다: 해시태그에 '#고양이'가 들어 있는 게시물만 가져온다
SELECT * FROM posts WHERE 해시태그 LIKE '%#고양이%';
낱말뜻인스타그램에서는
SELECT가져올 열을 고른다. *는 모든 열"작성자와 올린 시각을"
FROM어느 테이블에서 가져올지"게시물 테이블에서"
WHERE조건에 맞는 행만 남긴다"해시태그가 #고양이인 것만"
ORDER BY정렬 기준. DESC는 내림차순, ASC는 오름차순"최근 것부터"
LIMIT앞에서 몇 행만 가져온다"우선 20개만" — 나머지는 더 내리면 가져온다
LIKE '%#고양이%'문자열 안에 그 말이 들어 있는 행을 찾는다. %는 '무엇이든'"#고양이가 섞여 있으면"

피드를 아래로 내릴 때마다 앱은 같은 문장을 LIMIT만 바꿔 다시 실행합니다. 한 번에 전부 가져오지 않는 이유는 게시물이 수십억 건이기 때문입니다. 필요한 만큼만 골라 오는 것이 데이터베이스를 쓰는 첫째 이유입니다.

② 카카오톡으로 쓰기 — 추가·갱신·삭제

읽기만으로는 앱이 되지 않습니다. 메시지를 보내면 테이블에 행이 하나 추가되고, 상대가 읽으면 그 행의 값이 갱신되며, 메시지를 지우면 행이 삭제됩니다. 세 동작이 각각 한 문장입니다.

아래 messages도 원리를 보이기 위한 예시 테이블입니다. 실제 메신저는 암호화·전송 확인 등 훨씬 많은 처리를 함께 합니다.

SQL · 추가 · 갱신 · 삭제
-- 추가(INSERT): 메시지를 보내면 테이블에 새 행이 하나 생긴다
INSERT INTO messages (방id, 보낸사람, 내용, 읽음)
VALUES (12, '보리', '오늘 급식 뭐야?', false);

-- 갱신(UPDATE): 상대가 읽으면 그 행의 '읽음'이 true가 된다 — 숫자 1이 사라지는 순간
UPDATE messages SET 읽음 = true WHERE id = 305;

-- 삭제(DELETE): 내가 보낸 메시지를 지운다
DELETE FROM messages WHERE id = 305 AND 보낸사람 = '보리';
낱말뜻카카오톡에서는
INSERT INTO … VALUES테이블에 새 행을 하나 넣는다메시지 전송
UPDATE … SET이미 있는 행의 값을 바꾼다읽음 표시 · 프로필 상태메시지 수정
DELETE FROM행을 지운다메시지 삭제
WHERE어느 행이 대상인지 좁힌다"305번 메시지, 그중에서도 내가 보낸 것만"
⚠️ WHERE가 없는 UPDATE·DELETE

세 문장 가운데 UPDATE와 DELETE에는 WHERE가 반드시 필요합니다. WHERE를 빠뜨리면 그 권한으로 건드릴 수 있는 모든 행이 대상이 됩니다. DELETE FROM messages; 한 줄이면 테이블의 메시지가 전부 사라집니다. 실제 서비스가 이런 사고를 막는 방법은 두 가지입니다. 하나는 문장에 WHERE를 꼭 넣는 것이고, 다른 하나는 애초에 지울 권한을 주지 않는 것입니다. 여러분의 앱이 남의 메시지를 지울 수 없는 것은 착해서가 아니라 권한이 없기 때문입니다.

③ 게임으로 묶어 세기 — COUNT와 GROUP BY

게임을 끝내면 전적 화면이 뜹니다. "이번 시즌 120판, 승률 58%", "캐릭터별 평균 점수" 같은 숫자입니다. 이 숫자는 어딘가에 저장되어 있던 값이 아니라, 테이블에 쌓인 행을 그 자리에서 세어 만든 값입니다. 대전 기록 한 판이 matches 표의 한 행이라고 해 봅시다.

SQL · 세기와 묶기
-- 내가 이번 시즌에 몇 판 이겼나
SELECT COUNT(*) FROM matches WHERE 플레이어 = '보리' AND 결과 = '승';

-- 캐릭터별로 묶어 판수와 평균 점수를 구하고, 평균이 높은 캐릭터부터 세 줄만
SELECT 캐릭터, COUNT(*) AS 판수, AVG(점수) AS 평균점수
FROM matches
GROUP BY 캐릭터
ORDER BY 평균점수 DESC
LIMIT 3;
낱말뜻게임 화면에서는
COUNT(*)조건에 맞는 행의 개수를 센다"이번 시즌 120판"
GROUP BY같은 값끼리 한 묶음으로 접는다"캐릭터별로"
COUNT · SUM · AVG · MAX · MIN묶음마다 개수 · 합계 · 평균 · 최댓값 · 최솟값
AS결과 열에 붙일 이름화면에 표시될 항목 이름

GROUP BY의 핵심은 "접는다"입니다. 20판의 기록이 캐릭터 네 종류로 묶이면 결과는 네 줄이 됩니다. 그래서 묶은 열이 아닌 열은 그대로 가져올 수 없습니다. 네 줄로 접힌 칸에 스무 개의 점수를 한꺼번에 넣을 수 없기 때문입니다. 그런 열은 COUNT·AVG 같은 집계 함수로 감싸 하나의 값으로 줄여야 합니다. 아래에서 직접 해 보면 금방 보입니다.

표를 읽는 법을 익혔으니 이번에는 표를 만드는 쪽을 봅니다. 교과서 31쪽의 속성명·설명·데이터형·조건 양식으로 설계하면, 그 표가 그대로 SQL 문장이 됩니다. 아래 설계표는 15차시에 실제로 만들 대결 기록 테이블입니다. 어떤 열을 어떤 자료형으로 둘지 정하는 일은 AI가 대신해 주지 않습니다. 무엇을 기록할지 아는 사람이 정해서 말해 주어야 합니다.

  

    
속성명설명데이터형조건

    
      
id기록 번호정수자동 증가 · 기본 키

      
game_id한 판을 묶는 번호문자열NULL·빈 값 불가

      
round대결 라운드문자열8강·4강·결승 중 하나

      
left_menu · right_menu겨룬 두 반찬문자열여덟 후보 중 서로 다른 반찬. NULL 불가

      
winner이긴 반찬문자열겨룬 두 반찬 중 하나. NULL 불가

      
created_at저장 시각날짜·시각현재 시각을 기본값으로 사용합니다.

    
  

  
이 설계표를 실제 SQL 문장으로 옮겨 테이블을 만드는 일은 15차시에 합니다. 만드는 문장(CREATE TABLE)은 한 학기에 한 번, 준비 담당자가 실행하므로 준비 안내에 따로 정리해 두었습니다.

조건NOT NULL(NULL 불가), PRIMARY KEY(기본 키), UNIQUE(중복 불가), DEFAULT(기본값)이메일은 UNIQUE

    
  

  
기본 키는 행을 유일하게 구분하는 열 또는 열의 조합입니다. 이 표에서는 자동으로 부여되는 id가 기본 키입니다. 같은 반찬이 여러 번 이겨도 각 행의 id는 다릅니다. NOT NULL은 NULL을 막지만 빈 문자열까지 막지는 않습니다. 그래서 판 번호는 빈 값을 막고, 두 반찬은 서로 다른 후보이며 승자는 그 둘 중 하나인지 CHECK 제약으로 검사합니다. 이 제약만으로 대진표 전체의 올바름이나 실제 참여자를 확인할 수는 없습니다.

    🔎 심화 — 테이블과 테이블을 잇는 열(외래 키)과 JOIN
    
    
      
    교과서 31쪽 쇼핑몰 설계에서 장바구니 테이블는 사용자 테이블의 id와 제품 테이블의 id를 열로 가집니다. 다른 표의 기본 키를 가리키는 이 열을 외래 키라 하고, 두 테이블을 이 열로 이어 붙이는 문장이 JOIN입니다. 같은 정보를 두 테이블에 중복해서 적지 않아도 되는 것이 데이터베이스가 표를 여러 개로 나누는 까닭입니다.

    -- 장바구니에 담긴 제품의 이름과 수량을, 장바구니 테이블와 제품 테이블를 제품 id로 이어서 가져온다
SELECT 장바구니.사용자id, 제품.제품명, 장바구니.수량
FROM 장바구니
JOIN 제품 ON 장바구니.제품id = 제품.id;

    3. 개념 정리 — 화면 뒤의 문장
    
  
    오늘 배운 SQL 낱말은 아홉 개입니다. 가져오는 SELECT, 어디서 가져올지 정하는 FROM, 행을 좁히는 WHERE, 줄을 세우는 ORDER BY, 몇 개만 자르는 LIMIT, 넣고 바꾸고 지우는 INSERT·UPDATE·DELETE, 그리고 세고 묶는 COUNT·GROUP BY입니다.
    
  
    인스타그램의 피드, 카카오톡의 읽음 표시, 게임의 랭킹은 모두 이 낱말들의 조합입니다. 화면에서 벌어지는 일이 표의 행에 무슨 일을 하는지 — 가져오는지, 넣는지, 바꾸는지, 지우는지, 세는지 — 를 구분할 수 있으면 됩니다. 그래야 AI가 써 준 코드가 무엇을 하는 코드인지 알아볼 수 있습니다. 특히 WHERE 없는 UPDATE·DELETE처럼 되돌릴 수 없는 문장을 알아보는 것이 중요합니다.
    
  
    다음 시간에는 이런 데이터를 다룰 때의 기준을 세웁니다. 그리고 15차시에는 오늘 설계한 표를 실제로 만들어, 학급이 함께 쓰는 데이터베이스에 우리 손으로 행을 쌓아 봅니다.

    문제 2 데이터셋, 데이터베이스, 테이블 — 세 용어를 우리 실습의 예에 대응해 봅니다.
    
    
    
      
    우리 실습에서 테이블에 해당하는 것은?
    
      
    
        
        
        
      
    
      
    matches는 전적 한 판을 한 행으로 저장하는 테이블입니다. 게임 회사의 데이터베이스는 이런 테이블을 여러 개 담고 있고, 급식 CSV는 데이터셋을 담은 파일 형태입니다.
    
    
    
    
    세 용어의 관계 펼쳐 보기
      
    데이터셋은 분석할 데이터의 집합이며 급식 CSV는 이를 담는 한 가지 형태입니다. 데이터베이스는 여러 테이블을 담는 저장소이고, 그 안의 matches는 전적을 저장하는 테이블입니다. 테이블은 관계형 데이터베이스에서 데이터를 행과 열로 관리하는 구조입니다.
    
    
    
  
    
  
    SQL 문장 고르기 — 상황을 읽고 알맞은 문장을 고릅니다. 답을 누르면 해설이 나옵니다.
    
  
    
    
    문제 3 인스타그램 검색창에 #고양이를 넣었습니다. 게시물의 해시태그 열에는 #고양이 #박스처럼 여러 태그가 한 칸에 들어 있습니다. 어느 문장이 맞습니까?
    
    
    
      
    
        
        
        
      
    
      
    한 칸에 태그가 여러 개 들어 있으므로 =로는 찾지 못합니다. 정확히 '#고양이' 한 글자만 들어 있는 행만 걸리기 때문입니다. LIKE '%#고양이%'는 앞뒤로 무엇이 오든 그 말이 들어 있으면 찾습니다. GROUP BY는 묶어서 세는 낱말이라 검색에 쓰지 않습니다.
    
    
    
  
    
  
    
    
    문제 4 내가 보낸 메시지(id 305)를 상대가 읽어서 노란 숫자 1이 사라졌습니다. 이때 실행된 문장은?
    
    
    
      
    
        
        
        
      
    
      
    메시지는 그대로 있고 읽음 값만 바뀌었으므로 UPDATE입니다. DELETE였다면 말풍선이 사라졌을 것이고, INSERT였다면 새 메시지가 하나 더 생겼을 것입니다.
    
    
    
  
    
  
    
    
    문제 5 게임 랭킹 화면에 캐릭터별 평균 점수를 높은 순으로 띄우려고 합니다.
    
    
    
      
    
        
        
        
      
    
      
    "캐릭터별"이라는 말이 곧 GROUP BY 캐릭터입니다. 첫 번째 문장은 묶지 않아 스무 판이 스무 줄로 그대로 나옵니다. 두 번째 문장의 WHERE 캐릭터는 조건이 아니라 열 이름만 적어 둔 것이라 문장이 되지 않습니다.
    
    
    
  
    
  
    
    
    문제 6 피드를 열 때 가장 최근 게시물 다섯 개만 가져오려고 합니다.
    
    
    
      
    
        
        
        
      
    
      
    먼저 줄을 세우고(ORDER BY) 그다음 앞에서 자릅니다(LIMIT). 순서를 바꿔 쓰면 문장이 되지 않습니다. 세 번째는 올린 시각이 5인 게시물을 찾는 조건이라 뜻이 전혀 다릅니다.
    
    
    
  
    
  
    
    
    문제 7 AI에게 "내가 보낸 메시지를 지워 줘"라고 했더니 아래 세 문장을 주었습니다. 실행하면 안 되는 문장은?
    
    
    
      
    
        
        
        
      
    
      
    WHERE가 없는 DELETE는 테이블의 모든 행을 지웁니다. 단톡방의 메시지가 전부 사라집니다. 첫 번째 문장은 조건 두 개를 모두 만족하는 한 행만 지우고, 세 번째는 가져오기만 하므로 아무것도 바뀌지 않습니다.
    
    
    
  
    
  
    
    
    문제 8 석리송 프로필에 "게시물 27"이라고 떠 있습니다. 이 숫자를 만드는 문장은?
    
    
    
      
    
        
        
        
      
    
      
    COUNT(*)는 조건에 맞는 행이 몇 개인지 셉니다. 첫 번째는 계정 이름이 27줄 나올 뿐 숫자가 되지 않고, MAX(id)는 가장 큰 게시물 번호라서 27이 아닐 수 있습니다. 중간에 지운 게시물이 있으면 번호와 개수가 어긋납니다.
    
    
    
  
    

  
    🎒 오늘의 체크
    
  
      
    
    • CSV 파일로 부족해지는 세 순간(동시에 쓰기·계속 쌓기·골라 읽기)을 말할 수 있다.
      • 
    
    • 데이터셋·데이터베이스·테이블을 실제 앱의 예에 대응해 구분할 수 있다.
      • 
    
    • SQL 문장 하나를 읽고 네 동작(조회·추가·갱신·삭제) 중 어느 것인지, 어느 테이블의 어느 행이 대상인지 말할 수 있다.
      • 
    
    • WHERE·COUNT·GROUP BY가 각각 무엇을 하는지 설명하고, 앱 화면의 기능과 짝지을 수 있다.
      • 
    
    • WHERE 없는 UPDATE·DELETE가 왜 위험한지 한 문장으로 말할 수 있다.
      • 
  
    

  
    📚 오늘의 용어
    
  
    
    
    용어뜻
    
    
    데이터셋하나의 주제에 대한 여러 데이터가 모인 집합 (예: CSV 파일 하나)
    
    
    데이터베이스여러 사람이 공유하여 사용하도록 통합 관리되는 데이터의 집합
    
    
    테이블데이터베이스 안에 표 형태로 저장된 데이터셋 하나
    
    
    수파베이스PostgreSQL 데이터베이스와 API·인증 등을 제공하는 서비스. 15차시에 직접 사용한다
    
    
    데이터 무결성잘못된 값이 들어오지 않도록 제약을 걸어 데이터의 올바름을 지키는 것
    
    
    SQL테이블에 데이터를 넣고(INSERT) 꺼내고(SELECT) 고치고(UPDATE) 지우는(DELETE) 언어이다. WHERE는 조건, ORDER BY는 정렬이다.
    
    
    기본 키행을 유일하게 구분하는 열 또는 열의 조합. 대개 자동으로 번호가 붙는 id를 사용
    
    
    WHERE조건에 맞는 행만 남기는 SQL 낱말. UPDATE·DELETE에서 빠뜨리면 모든 행이 대상이 된다
    
    
    ORDER BY · LIMIT정렬 기준(DESC 내림차순·ASC 오름차순)과 가져올 행 수. 피드를 20개씩 가져오는 것이 이것이다
    
    
    GROUP BY같은 값끼리 묶어 묶음마다 COUNT·AVG 같은 집계를 구하는 SQL 낱말이다. 묶은 열이 아닌 열은 집계 함수로 감싼다.
