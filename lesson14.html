Ⅰ. 데이터 과학의 이해 · 14차시

데이터 윤리 · 내 앱에서 쟁점 찾기

"데이터를 쓰는 사람은, 그 데이터가 누구의 것이고 누구에게 영향을 주는지 먼저 묻는다."
오늘은 숫자가 아니라 판단을 점검합니다

우리는 한 학기 동안 남이 모은 데이터를 불러와, AI가 짠 코드로 분석하고, 결과를 인터넷에 공개했습니다. 이 문장 어디에 윤리 문제가 끼어 있을까요? 오늘은 교과서의 세 가지 윤리 문제를 익힌 뒤, 그 눈으로 내 포트폴리오 앱을 다시 점검합니다.

🎯 오늘 하는 것
  • 교과서의 세 문제 — 편향성 · 혐오 표현 · 소유권
  • 내 실습 되짚기 — 인증키 · 데이터 민감도 · 모델이 배우는 편향 · AI 코드의 책임
  • 모둠 토론 — 내가 겪은 윤리 사례 · SDGs와 데이터

0. 왜 배우나

데이터 윤리라고 하면 흔히 기업의 개인 정보 유출 뉴스처럼 먼 이야기를 떠올립니다. 그런데 이번 학기 우리의 실습을 돌아보면, 인증키를 어디에 두는가, 데이터의 출처를 표기했는가, 그 데이터에 누군가의 정보가 들어 있는가 — 전부 이미 우리가 내린 윤리적 판단이었습니다. 데이터로 무엇을 만들 줄 아는 사람일수록, 그 결과가 누구에게 어떤 영향을 주는지 판단할 책임도 함께 커집니다. 팀 프로젝트에서 데이터를 직접 고르기 전, 오늘이 그 판단 기준을 세우는 시간입니다.

1. 개념 이해 — 교과서의 세 가지 윤리 문제

📖 교과서의 정의 『데이터 과학』 38·39쪽

"수집된 데이터의 분포가 고르지 못하고, 특정한 지역, 연령, 성별 등에 치우쳐 있을 경우 데이터에 편향성이 있다고 한다." (38쪽)

"실제 현실을 대표하지 못하고 특정한 방향으로 치우쳐 있는 데이터를 가지고 모델을 만들면, 특정 대상에게 유리하거나 불리한 모델이 만들어질 수 있다." (38쪽)

"학교 수업 중에 생성된 데이터는 학생의 것일까? 학교의 것일까? 서비스를 만든 기업의 것일까?" (39쪽)

→ 데이터가 치우쳐 있으면 모델도 치우친다. 그리고 데이터가 자원이 된 시대에는 누구의 것인가부터가 쟁점이 된다.

교과서는 데이터 과학 속 윤리 문제를 세 갈래로 정리합니다. 셋 다 "데이터를 잘못 다루면 사람이 피해를 본다"는 공통 구조를 갖습니다.

문제무엇이 잘못되나우리 실습과의 접점
데이터 편향성치우친 데이터로 만든 모델이 특정 대상에게 불리하게 작동한다8차시 영화 모델의 스크린 수 변수 — 아래 2절
혐오 표현사람들이 쓴 잘못된 언어를 인공지능이 그대로 학습한다우리가 매일 쓰는 AI 챗봇의 학습 데이터
데이터 소유권내가 만든 데이터를 누가 소유하고 팔 수 있는지가 불분명하다수업 중 폼으로 제출한 우리 응답은 누구의 것인가

세 문제의 자세한 사례는 교과서 38~39쪽에서 함께 읽습니다. 이제 이 세 갈래를 들고, 남의 사례가 아니라 우리가 실제로 한 실습으로 돌아갑니다.

2. 내 실습 속 쟁점 — 네 장면 되짚기

한 학기 동안의 실습에서 윤리가 끼어 있던 네 장면입니다. 각 장면마다 "나는 어떻게 했더라?"를 떠올리며 읽습니다.

장면 1 — 인증키를 코드에 적어 공개하면

5차시에 급식 API의 인증키를 발급받았고, 영화 API 키는 공개 저장소에 올라가지 않도록 따로 보관했습니다. 이유가 있습니다. 인증키는 "이 요청을 보낸 사람이 누구인가"를 밝히는 서명이고, 영화 API는 하루 3,000회의 호출 한도가 키 단위로 걸려 있습니다. 키가 적힌 코드를 공개하면 다른 사람이 내 이름으로 요청을 보낼 수 있고, 한도 소진이든 오·남용이든 책임은 키의 주인에게 돌아옵니다. 키를 코드에 적지 않고 비밀값 보관함에 두는 습관은 기술 요령이 아니라 책임 관리입니다.

장면 2 — 급식 데이터는 되고, 위치 데이터는 왜 조심스러운가

우리가 분석한 급식 식단은 학교 단위의 공개 정보였습니다. 어느 학생이 무엇을 먹었는지는 어디에도 없으므로, 전량을 내려받아 공개 앱으로 만들어도 누구의 사생활도 다치지 않습니다. 그런데 같은 공공데이터라도 개인의 위치나 이동 기록이 담긴 데이터라면 이야기가 다릅니다. 한 건 한 건은 익명이라도, 시간대별로 이어 붙이면 특정 개인이나 집단의 동선이 드러날 수 있습니다. 같은 "공개 데이터"라도 민감도는 같지 않다 — 팀 프로젝트에서 데이터를 고를 때 가장 먼저 확인할 항목입니다.

장면 3 — 모델이 사회의 편향을 학습한다

8차시에서 영화 흥행 예측에 첫날 스크린 수 변수를 넣었습니다. 스크린을 많이 받은 영화가 관객도 많이 모으는 것은 사실이지만, 스크린 배정은 대형 배급사에 유리하게 이루어지는 사람의 결정입니다. 이 변수로 학습한 모델은 "스크린을 많이 받을 영화가 성공한다"고 예측하게 되고, 그 예측이 다시 스크린 배정의 근거가 되면 작은 영화는 더 밀려납니다. 교과서 38쪽의 정의 그대로 — 치우친 데이터로 만든 모델은 특정 대상에게 불리하게 작동합니다. 모델은 세상을 비추기만 하는 것이 아니라, 세상의 치우침을 되풀이하게 만들 수도 있습니다.

장면 4 — AI가 짠 코드의 책임은 누구에게

우리는 ①프롬프트를 쓰고 ②AI가 준 코드를 실행해 왔습니다. 그 코드가 잘못된 수치를 화면에 표시했다면 책임은 누구에게 있을까요? 이 수업의 답은 분명합니다. 앱에 이름을 걸고 공개한 사람, 곧 나입니다. 그래서 우리는 9·11·13차시에 손계산으로 AI의 결과를 검산하는 연습을 해 왔습니다. 검증할 수 있는 사람만이 책임질 수 있고, 책임질 수 있는 사람만이 도구를 믿고 쓸 수 있습니다.

3. 점검 활동 — 내 앱을 윤리의 눈으로

오늘은 새 페이지를 만들지 않습니다. 대신 자기 포트폴리오 앱을 열어, 네 장면의 눈으로 스스로 점검합니다.

✔️ 내 앱 셀프 점검 3항목
  • 키 — 인증키가 코드나 공개 저장소에 적혀 있지 않은가? (비밀값 보관함에 있는가)
  • 출처 — 사용한 데이터의 출처(제공 기관·수집 시점)가 앱 화면에 표기되어 있는가?
  • 사람 — 내 앱의 데이터에 특정 개인을 알아볼 수 있는 정보가 들어 있지 않은가?

세 항목 중 걸리는 것이 있다면 지금 고칩니다. 출처 표기 한 줄을 앱에 추가하는 일은 ③개선 프롬프트 한 번이면 됩니다.

4. 사례 토론 — 내 경험과 세계의 문제

이제 시야를 넓힙니다. 교과서 39쪽 해 보기 ③은 직접 겪었거나 간접적으로 들은 데이터 윤리 사례를 묻습니다. 뉴스에서 본 일반론보다, 게임·SNS·쇼핑에서 내가 실제로 겪은 일이 좋은 답입니다 — 맞춤 광고가 따라다녔던 경험, 동의한 기억이 없는 수집 안내문 같은 것들 말입니다.

📖 교과서의 정의 『데이터 과학』 36쪽

"세계 연합(UN)은 전 세계 빈곤을 종식시키고, 지구를 보호하며, 2030년까지 모든 사람들이 평화와 번영을 누릴 수 있는 지속 가능한 미래를 만들기 위한 17개의 지속 가능 발전 목표(SDGs: Sustainable Development Goals)를 제시하였다." (36쪽)

→ 데이터는 문제를 만들기도 하지만, 기후·건강·교통 같은 세계의 문제를 진단하고 푸는 도구이기도 하다.

교과서 37쪽 해 보기 ②는 지속 가능한 미래를 위해 데이터 과학이 활용되는 사례를 조사합니다. 오늘 수업이 "데이터는 위험하다"로 끝나지 않도록 — 같은 도구가 문제를 만들기도 하고 풀기도 한다는 양면을 모둠 발표로 확인합니다.

📮 오늘의 제출

교과서 폼 Ⅰ-04b(39쪽 해 보기 ③ 윤리 사례 — 수업 중 모둠 토론) · Ⅰ-04a(37쪽 해 보기 ② 지속가능 사례 — 과제 후 발표). 더 깊이 파고 싶은 사람은 Ⅱ-04d(99쪽 응급실 분석 — 선택 심화 과제)에 도전합니다.

5. 개념 정리 — 윤리는 별도 단원이 아니다

오늘 확인한 것을 한 줄로 줄이면 이렇습니다. 데이터 윤리는 교과서 속 남의 이야기가 아니라, 내 앱의 인증키 한 줄과 출처 표기 한 줄에 이미 들어와 있었다. 데이터가 치우치면 모델이 치우치고(편향), 데이터를 다루는 권한에는 책임이 따르고(키·소유권), AI가 짠 코드라도 공개한 사람이 책임진다 — 이것은 우리가 배워 온 판단 습관의 연장입니다. 좋은 질문을 세우고, 데이터를 감식하고, 결과를 해석하고, 한계를 아는 사람이 곧 윤리적으로 데이터를 다루는 사람입니다.

다음 시간에 팀 프로젝트의 도구인 데이터베이스를 만난 뒤, 팀이 데이터를 고를 때는 오늘의 눈으로 네 가지 — 개인정보 · 출처 · 이용 약관 · 편향 — 를 점검하게 됩니다.

6. 확인 문제

문제 1 — 급식 식단 데이터는 전량 내려받아 공개 앱으로 만들었지만, 개인 위치 데이터라면 같은 방식이 위험하다. 두 데이터의 민감도 차이를 설명하시오.

예시 답안 — 급식 식단은 학교 단위의 공개 정보로, 어떤 개인이 무엇을 했는지에 대한 정보가 전혀 들어 있지 않다. 반면 개인 위치 데이터는 한 건 한 건이 익명이라도 시간 순서로 이어 붙이면 특정 개인이나 집단의 동선·생활 패턴이 드러날 수 있어, 수집·공개 시 사생활 침해 위험이 있다. 데이터의 민감도는 "공개되어 있는가"가 아니라 "개인을 추적할 수 있는가"로 판단해야 한다.

문제 2 — API 인증키를 코드에 적은 채 공개 저장소에 올리면 안 되는 이유를 두 가지 서술하시오.

예시 답안 — ① 인증키는 요청을 보낸 사람을 식별하는 값이므로, 공개되면 다른 사람이 내 이름으로 API를 호출할 수 있다. ② 호출 한도(예: 영화 API 일 3,000회)가 키 단위로 관리되므로, 남이 내 키를 쓰면 한도가 소진되고 오·남용의 책임도 키 주인에게 돌아온다. 따라서 키는 코드와 분리해 비밀값 보관함에 두어야 한다.

문제 3 — 영화 흥행 예측 모델에 첫날 스크린 수 변수를 넣으면 예측에 도움이 된다. 그런데 이 모델을 "좋은 영화를 가려내는 모델"이라고 소개하면 왜 문제가 되는지 서술하시오.

예시 답안 — 스크린 수는 영화의 완성도가 아니라 배급사의 결정, 곧 사람이 만든 배정 구조를 담은 변수다. 이 변수로 학습한 모델은 "스크린을 많이 받는 영화가 성공한다"는 기존의 치우침을 그대로 학습하며, 그 예측이 다시 스크린 배정의 근거로 쓰이면 작은 영화에 불리한 구조가 강화된다. 치우친 데이터로 만든 모델은 특정 대상에게 불리하게 작동할 수 있다는 데이터 편향성 문제에 해당한다.

🎒 오늘의 체크

  • 데이터 편향성·혐오 표현·소유권 문제를 각각 예를 들어 설명할 수 있다.
  • 내 앱에서 키·출처·개인정보 3항목을 점검하고 필요한 것을 고쳤다.
  • 급식 데이터와 개인 위치 데이터의 민감도 차이를 설명할 수 있다.
  • 내가 겪은 데이터 윤리 사례 하나를 모둠에서 이야기했다.
