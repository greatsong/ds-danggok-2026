이름은 사람이 붙인다

🎯 오늘 만드는 것
  • 동네 성격 찾기 앱 — 역 이름을 검색하면 소속 묶음과 그 묶음의 시간대 리듬, 내가 붙인 이름을 보여 주는 앱 (배포까지)

0. 왜 배우나

밤하늘의 별은 그저 흩어진 점입니다. 그 점들을 이어 국자 모양을 알아보고 북두칠성이라는 이름을 붙인 것은 사람입니다. 이름이 붙고 나서야 별들은 방향을 찾는 길잡이가 됐습니다. 지난 두 시간 동안 컴퓨터는 지하철역을 리듬이 닮은 묶음으로 나눠 줬습니다. 그런데 컴퓨터가 건넨 것은 묶음 0·1·2라는 번호뿐입니다. 이 번호에 "주거형", "번화가형" 같은 이름을 붙여야 비로소 쓸모 있는 발견이 됩니다. 오늘은 그 이름을 근거와 함께 붙이고, 누구나 써 볼 수 있는 검색 앱으로 만들어 배포합니다.

1. 개념 이해 — 이름을 붙이는 책임

컴퓨터가 주는 것과 주지 않는 것

k-means가 끝나고 우리 손에 들어오는 것은 "이 역은 묶음 0, 저 역은 묶음 2"라는 번호표가 전부입니다. 번호는 순서일 뿐 뜻이 없습니다. 컴퓨터는 점 사이의 가깝고 먼 구조만 다룰 뿐, 그 구조가 세상에서 무엇을 의미하는지는 알지 못합니다. 아침에 봉우리가 솟는 리듬이 "출근길에 나서는 주거지"라는 사실은 데이터 안이 아니라 우리의 생활 지식에서 나옵니다. 그래서 일이 나뉩니다. 패턴을 찾는 일은 기계가 하고, 의미를 주는 일은 사람이 합니다.

이름은 해석이고, 해석에는 책임이 따른다

"주거형"이라는 이름을 붙이는 순간, 우리는 데이터에 없던 주장을 하나 얹은 셈입니다. 이름이 그럴듯하면 읽는 사람은 그대로 믿습니다. 그래서 이름에는 근거가 따라붙어야 합니다. "이 묶음은 아침 7~9시에 승차가 몰리니 주거형"처럼 그래프의 모양을 근거로 대면, 다른 사람이 그 근거를 확인하고 다르게 판단할 수도 있습니다. 근거 없는 이름은 맞는지 따져 볼 방법조차 없습니다. 이름이 서로 다르더라도 근거가 또렷하면 둘 다 좋은 해석입니다.

세 트랙이 남긴 하나의 물음

회귀·분류·군집, 세 가지 도구를 지나며 우리는 매번 같은 물음 앞에 섰습니다. 이 결과를 언제, 얼마나 믿을 수 있을까. 회귀에서는 관측 범위 밖의 예측을 의심했고, 분류에서는 높은 정확도 뒤에서 무엇을 놓쳤는지 확인했고, 군집에서는 정답이 없는 자리를 사람의 판단으로 채웠습니다. 도구가 달라도 마지막 확인은 늘 사람이 했습니다. 이 물음은 곧 시작하는 팀 프로젝트에서 여러분 자신의 데이터로 다시 만나게 됩니다.

트랙도구가 준 것사람이 한 확인
회귀직선과 점수(R²)관측 밖 예측은 의심한다 (외삽)
분류정확도기준선과 견주고 무엇을 놓쳤는지 본다
군집번호 붙은 묶음근거를 대며 이름을 붙인다

2. 컴퓨터는 묶기만 한다

  • 지난 두 시간, 컴퓨터는 역을 리듬이 비슷한 묶음으로 나눴다.
  • 그런데 컴퓨터가 준 건 묶음 0, 묶음 1, 묶음 2라는 번호뿐이다. 그 번호엔 뜻이 없다.
  • 이 묶음이 "출근하는 동네"인지 "번화가"인지 읽어내는 건 사람의 몫이다. 오늘의 마지막 한 걸음.
⚠️ 묶음 번호는 실행마다 바뀐다
  • k-means의 묶음 번호(0·1·2)는 돌릴 때마다 순서가 달라질 수 있다.
  • 그러니 번호를 외우지 말고, 리듬 그래프의 모양을 보고 이름을 붙인다.

3. 묶음의 리듬 읽기

  • 각 묶음의 평균 시간대 승차 곡선을 그리면 성격이 보인다.
  • 아침에 봉우리가 솟으면 집에서 나서는 동네, 저녁에 솟으면 일하고 노는 동네다.
리듬 모양무슨 동네일까이름 후보
아침(7~9시)에 승차 봉우리아침에 집을 나서는 주거지주거형
저녁(18~20시)에 승차 봉우리일·놀이를 마치고 나오는 곳출근형·번화가형
하루 종일 고른 편사람이 계속 오가는 혼합 지역혼합형
💡 이름의 근거를 말로
  • "강남은 저녁에 승차가 몰리니 번화가형"처럼, 그래프의 모양을 근거로 붙인다.
  • 이름은 정답이 아니라 해석이다. 근거만 또렷하면 다르게 불러도 된다.

4. 검색 앱 만들고 배포하기 (①②③)

  • 만들 것 = 역 이름을 넣으면 소속 묶음 + 묶음 리듬 곡선 + 내가 붙인 이름이 뜨는 앱
  • requirements.txt에는 scikit-learn·plotly만 (기본 설치 제외 · 버전 없이).
① 샘플 프롬프트
지하철역 군집 앱을 배포용으로 정리해 줘. 스트림릿 클라우드에 올릴 거야. 조건:

- 앞서처럼 최신월 데이터를 역별 시간대 '승차 비율'로 바꿔서
  k-means 3묶음으로 나눠 줘.
- 각 묶음의 '평균 시간대 승차 곡선'을 하나의 선 그래프로 겹쳐 그려 줘
  (가로축 시간대, 세로축 평균 승차 비율).
- 위에 역 이름을 입력하는 검색창을 둬. 역을 넣으면 그 역이
  어느 묶음인지 알려 주고, 그 묶음 곡선을 강조해서 보여줘.
- 묶음마다 이름을 붙일 수 있게 해줘. 예: 주거형, 번화가형, 혼합형.
- 한국어 라벨, 따뜻한 톤, 초보자용 한국어 주석. main.py 전체 코드를 한 번에 줘.
- 필요한 라이브러리 목록(requirements.txt)도 버전 없이 같이 줘.
② AI가 준 코드 예시
import streamlit as st
import pandas as pd
import plotly.express as px
from sklearn.cluster import KMeans

st.title("🚇 우리 동네 성격 찾기")

@st.cache_data
def load():
    url = "https://raw.githubusercontent.com/greatsong/modudata/main/data/subway_time.csv"
    return pd.read_csv(url)

df = load()

# 전처리 — 최신월, 역별 승차, 시간대 비율
latest = df[df["사용월"] == df["사용월"].max()]
ride_cols = [c for c in df.columns if "승차" in c]
station = latest.groupby("지하철역")[ride_cols].sum()
ratio = station.div(station.sum(axis=1), axis=0).fillna(0)

# 3묶음으로
ratio["묶음"] = KMeans(n_clusters=3, random_state=42, n_init=10).fit_predict(ratio)

# 내가 붙인 이름 — 리듬 곡선을 보고 정한다(번호는 실행마다 바뀔 수 있음)
이름 = {0: "묶음 0", 1: "묶음 1", 2: "묶음 2"}

# 역 검색
q = st.text_input("역 이름을 입력하세요", "강남")
if q in ratio.index:
    cl = int(ratio.loc[q, "묶음"])
    st.subheader(f"{q} → {이름[cl]}")
else:
    st.info("그 역을 찾지 못했어요. 이름을 다시 확인해 주세요.")

# 묶음별 평균 시간대 곡선
시간 = [c.replace(" 승차인원", "") for c in ride_cols]
평균 = ratio.groupby("묶음")[ride_cols].mean().T
평균.index = 시간
긴표 = 평균.reset_index().melt(id_vars="index", var_name="묶음", value_name="평균승차비율")
fig = px.line(긴표, x="index", y="평균승차비율", color="묶음",
              labels={"index": "시간대"})
st.plotly_chart(fig, use_container_width=True)
✔️ 실행하면 이렇게 나온다 (이 달 기준)
  • 강남·홍대입구를 검색하면 저녁에 승차가 몰리는 묶음(번화가형)에 들어간다.
  • 신림·사당을 검색하면 아침에 승차가 몰리는 묶음(주거형)에 들어간다.
  • 곡선을 보고 이름을 주거형·번화가형·혼합형으로 바꿔 붙이면 완성.

7. 해보기 — 개인 또는 팀

✏️ 개인 미션 — 이름의 근거 (10분)
  • 내가 붙인 묶음 이름 세 개와, 각 이름을 붙인 근거(리듬 그래프의 모양)를 한 줄씩 적는다.
  • 배포한 앱 주소를 갤러리에 올린다.
🗣️ 팀 미션 — 이름이 다르면 누가 맞나 (2~3인 토의, 7분)
  • 짝 팀과 묶음 이름을 비교한다. 같은 묶음에 다른 이름을 붙였다면, 각자 그래프의 어느 모양을 근거로 들었는지 서로 설명한다.
  • 토의 질문: "근거가 다 또렷하다면, 이름이 달라도 둘 다 맞다고 할 수 있는가?" 입장을 한 문장으로 적는다.
  • 근거를 대지 못하는 이름이 있었다면, 곡선을 다시 보고 근거부터 채운다.
🧾 이 기록이 수행평가 재료가 된다
  • 배포한 앱 주소(URL)와 갤러리 게시는 세 번째 배포 증빙으로 수행평가 기록에 남는다. 이름의 근거 한 줄들은 팀 프로젝트 발표 3줄(질문·데이터·발견)의 연습 재료다.

8. 확인 문제

지필 문항과 같은 유형입니다. 먼저 스스로 답을 적고 나서 펼쳐 보세요.

문제 1 — "군집의 이름은 사람이 붙인다"가 뜻하는 바를 서술하시오.

예시 답안 — 컴퓨터가 주는 것은 묶음 0·1·2라는 번호뿐이고 번호에는 뜻이 없다. 그 묶음이 주거형인지 번화가형인지 읽어내는 데는 데이터 밖의 생활 지식이 필요하므로, 패턴 발견은 기계가 해도 의미 부여는 사람이 한다는 뜻이다.

문제 2 — "0번 묶음은 주거형"이라고 번호로 외우면 안 되는 이유와, 대신 무엇을 보고 이름을 붙여야 하는지 서술하시오.

예시 답안 — k-means의 묶음 번호는 실행마다 순서가 바뀔 수 있어, 번호로 외우면 다음 실행에서 어긋난다. 번호가 아니라 묶음의 평균 시간대 곡선 모양(아침 봉우리인지 저녁 봉우리인지)을 보고 이름을 붙여야 한다.

문제 3 — 강남이 든 묶음을 "번화가형"이라 부를 수 있는 근거를 데이터에서 들어 한 문장으로 서술하시오.

예시 답안 — 강남이 든 묶음은 저녁(18~20시)에 승차가 몰리는 곡선 모양을 보이므로, 일과와 놀이를 마친 사람들이 지하철을 타고 나서는 번화가형이라 부를 근거가 있다.
