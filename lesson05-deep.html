두 번째 API — 우리 학교 급식

속담 — 오늘은 두 번째 API를 여러분 손으로 붙입니다
🔎 자세한 판

이 페이지는 내용을 줄이지 않은 판입니다. 수업은 기본판으로 진행하고, 더 깊이 보고 싶을 때 이 판을 읽습니다.

오늘은 나이스(NEIS) 급식 API로 우리 학교 점심을 내 앱에 불러옵니다. 나이스는 교육행정정보시스템(National Education Information System)의 약자로, 전국 학교의 학사·행정 정보를 다루는 시스템입니다 — 여러분의 성적표와 생활기록부도 이 시스템에 있습니다. 방법은 2차시의 KOBIS와 같습니다. 공식 문서 발췌를 읽고, 완성 주소로 응답을 먼저 확인한 뒤, 문서를 프롬프트에 붙입니다. 다른 점이 하나 있습니다. 이번 API는 인증키가 필요 없습니다.

🎯 오늘 하는 것
  • 두 API 비교 — KOBIS와 나이스, 무엇이 같고 무엇이 다른가
  • 페이지로 나누기 — 급식 화면 셋을 한 파일에 덮어쓰지 않고 main.py와 pages 폴더로
  • 바이브 코딩 — 학교를 골라 보는 첫 화면 + 우리 학교 달력별 + 메뉴별(두 학기 154일 최다 메뉴 TOP 10)
  • 기록 — 함께 자주 나올 것 같은 메뉴 짝 3개 (12차시에 다시 꺼냅니다)

0. 왜 배우나

세상의 API는 수천 개가 넘고, 수업이 그것을 전부 소개할 수는 없습니다. 그래서 오늘 배우는 것은 급식 API 하나가 아니라, 처음 보는 API에 다가가는 순서입니다. 문서 발췌를 읽고, 완성 주소를 맨눈으로 확인하고, 문서를 붙여 부탁한다 — 이 순서가 손에 붙으면 날씨·대중교통·도서관 등 어떤 API든 공식 문서만 있으면 여러분 앱의 재료가 됩니다. 2학기 후반의 팀 프로젝트에서 팀이 고른 데이터가 API로 온다면, 오늘 연습한 순서가 그대로 쓰입니다.

1. 두 API 비교 — 같은 순서, 다른 규칙

KOBIS에서 밟은 순서는 나이스에서도 통합니다. 그러나 규칙은 API마다 다릅니다. 가장 큰 차이는 인증키입니다.

KOBIS 박스오피스 (2차시)나이스 급식 (오늘)
인증키필요 — 비밀 금고(secrets)에 보관불필요 — 대신 한 번에 오는 건수 제한
빈 응답의 정체오늘 것은 아직 집계 전주말·방학은 급식이 없는 날 — 오류가 아니다
받자마자 다듬을 것숫자가 따옴표 친 글자로 온다메뉴 전체가 한 덩어리 글자로 온다 — 구분 기호와 알레르기 괄호를 떼야 표가 된다
⚠️ 건수 제한의 실물 — 조회 기간은 짧게

키 없이 다섯 달치(2026-03-01~07-31)를 한 번에 요청하면, 응답은 "전체 82건"이라고 알려 주면서 목록에는 앞의 5건만 담아 보냅니다(실측). 오류도 나지 않아서 알아채기 어렵습니다. 그래서 오늘 실습의 날짜 조회는 하루~한 주 단위로 짧게 잡고, 기간 전체가 궁금할 때는 미리 쌓아 둔 표 danggok_meals.csv(③에서 등장)를 씁니다.

2. 완성 주소 맨눈 보기 — 급식 JSON 해부

🔎 이런 사이트예요 — 나이스 교육정보 개방 포털

open.neis.go.kr은 나이스의 학교 데이터 일부를 누구나 사용할 수 있도록 공개한 곳입니다. 급식 식단 말고도 학교 기본 정보·학사 일정·시간표 API가 있고, 우리 학교만이 아니라 전국 어느 학교든 학교 코드만 바꾸면 조회됩니다 — "우리 학교와 옆 학교의 급식은 얼마나 다를까" 같은 질문의 재료가 됩니다.

✔️ 문서까지 가는 길 — 2차시에 KOBIS에서 했던 그대로

포털 첫 화면에서 데이터셋 메뉴로 들어가 급식식단정보를 찾아 열고, 상세 화면의 Open API 항목을 펼치면 오늘의 문서가 나옵니다. 볼 곳 세 곳의 이름이 KOBIS와 조금 다릅니다 — 신청주소(요청 주소) · 신청인자 표(요청변수 — 교육청·학교 코드 등) · 출력값 표(응답 구조). 이름이 달라도 하는 일은 같아서, 세 곳을 긁어 프롬프트 끝에 붙이면 됩니다. 아래 ①의 발췌가 바로 그 결과물입니다.

2차시와 같은 순서입니다. 코드를 쓰기 전에 완성 주소를 새 탭에서 열어, 응답 JSON을 맨눈으로 확인합니다. 먼저 주소를 해부해 봅니다. KOBIS 주소에 있던 key=가 여기에는 없습니다.

요청 주소의 해부 — 인증키 없는 요청
https://open.neis.go.kr/hub/mealServiceDietInfo   ← 어디에 — 요청 주소
?Type=json                                        ← 응답 형식 — 이 줄이 빠지면 XML로 온다
&ATPT_OFCDC_SC_CODE=B10                           ← 조건 — 교육청(서울)
&SD_SCHUL_CODE=7010073                            ← 조건 — 학교(당곡고)
&MMEAL_SC_CODE=2                                  ← 조건 — 식사(중식)
&MLSV_FROM_YMD=20260602&MLSV_TO_YMD=20260602      ← 조건 — 기간(하이픈 없는 여덟 자리)
요청 주소와 조건은 2차시 KOBIS와 같은 구조인데, 인증키만 없다. 날짜 두 값을 바꾸면 응답이 그 기간 것으로 바뀐다.

3. 급식 앱은 화면 셋 — 페이지로 나눈다

오늘 급식 데이터로 만드는 화면은 셋입니다. 첫 화면은 학교를 검색해 고르면 그 학교의 그날 급식을 불러오는 화면입니다. 페이지 1은 우리 학교만 달력에서 날짜를 골라 식단·알레르기·칼로리를 보는 화면입니다. 페이지 2는 미리 쌓아 둔 두 학기 154일 표로 가장 자주 나온 메뉴 TOP 10을 세는 화면입니다. 셋은 종류가 다릅니다. 여러 학교 실시간 조회, 우리 학교 날짜별 조회, 우리 학교 메뉴별 집계로 나뉩니다. 한 파일에 차례로 덮어쓰면 먼저 만든 화면이 사라집니다. 첫 화면은 main.py로 만들고, 나머지 둘은 pages 폴더에 파일 하나씩 넣습니다. 스트림릿은 main.py 옆에 pages 폴더를 두면 그 안의 파일 하나하나가 왼쪽 메뉴의 페이지가 됩니다. 설정 파일이나 메뉴 코드는 필요하지 않습니다.

규칙내용
폴더 이름pages로 고정 — 다른 이름은 메뉴로 인식되지 않는다
메뉴 순서파일 이름 앞의 숫자가 정한다 (1_달력별_급식.py → 2_메뉴별_급식.py)
첫 화면main.py가 첫 화면이 되어 메뉴 맨 위에 놓인다. 파일 이름에서 앞 숫자와 밑줄을 뗀 것이 메뉴 이름이다
오늘이 끝나면
내 저장소/
├── main.py              ← 첫 화면: 학교를 골라 급식 보기
├── requirements.txt     ← 저장소에 하나. 앱 전체에 적용된다
└── pages/
    ├── 1_달력별_급식.py    ← 우리 학교, 날짜를 골라 보기 (API)
    └── 2_메뉴별_급식.py    ← 우리 학교, 두 학기 최다 메뉴 (쌓아 둔 표)
⚠️ 메뉴에 페이지가 안 보일 때 볼 곳
  • 폴더 이름이 pages인지. Pages·page는 인식되지 않는다.
  • 폴더 위치가 저장소 맨 위, main.py와 나란한 곳인지.
  • 파일 이름이 .py로 끝나는지. 확장자를 빼면 페이지가 되지 않는다.

4. 실습 — 화면 셋을 차례로 만든다

첫 화면(main.py)부터 만듭니다. 2차시에는 프롬프트를 쓰기 전에 키를 비밀 금고(secrets)에 넣는 단계가 있었지만, 오늘은 넣을 키가 없으므로 그 단계가 통째로 없습니다. 프롬프트 끝에 공식 문서 발췌를 붙이는 요령은 그대로입니다 — AI가 필드 이름을 지어내지 못하게 막는 안전장치입니다.

  1. ① 샘플 프롬프트 — 첫 화면(main.py): 학교를 골라 급식 보기
    ① 프롬프트
    스트림릿 앱(main.py)을 새로 만들어 줘. 제목은 '학교 급식 찾아보기'.
아래에 나이스 교육정보 개방 포털 문서에서 복사한 내용을 붙였어. 두 API 모두 인증키가 없어도 돼.

- 학교 이름을 입력하면 학교 정보 API로 그 이름이 들어간 학교를 찾아 목록에서 고를 수 있게 해 줘.
  같은 이름의 학교가 여러 지역에 있으니 지역도 함께 보여 줘.
- 날짜를 달력에서 고르면, 고른 학교의 그날 중식 메뉴를 보여 줘.
  메뉴 뒤 괄호 속 숫자는 알레르기 번호니까 떼고 보여 주고, 칼로리도 함께.
- '수도여고'처럼 줄여 적은 이름은 정식 이름('수도여자고등학교')의 일부가 아니라서 못 찾아.
  못 찾으면 '여고'는 '여자고등학교', '고'는 '고등학교'로 풀어서 한 번 더 찾아 줘.
- 학교를 못 찾거나 그날 급식이 없으면 오류 대신 안내 문구를 보여 줘.
- 필요한 라이브러리 목록(requirements.txt)도 같이 줘. 버전 숫자 없이 이름만.

  2. ② AI가 준 코드 — 실행하고 관찰한다
    아래는 이 프롬프트로 받은 코드의 한 예입니다. 여러분 화면이 이런 모습이면 성공이고, 글자까지 같지 않아도 됩니다.
    ② AI가 준 코드 예시 — 
    # main.py — 학교를 검색해 고르면 그 학교의 급식을 보여 주는 첫 화면

# 1) 학교 이름으로 교육청 코드와 학교 코드를 찾는다 (인증키 없이, 한 번에 5건까지)
def search_schools(query):
    info = requests.get(
        "https://open.neis.go.kr/hub/schoolInfo",
        params={"Type": "json", "SCHUL_NM": query},
        timeout=10,
    ).json()
    # 못 찾으면 row 없이 RESULT 상자만 온다 — 오류가 아니다
    return info["schoolInfo"][1]["row"] if "schoolInfo" in info else []


schools = search_schools(name)
if not schools:

import requests
import streamlit as st

    "Type": "json",                # 응답을 JSON으로

    "MLSV_TO_YMD": ymd,

    # pages/2_메뉴별_급식.py — 두 학기 급식 기록에서 최다 등장 메뉴 TOP N
import streamlit as st
import pandas as pd
import plotly.express as px

DATA_URL = "https://raw.githubusercontent.com/greatsong/modudata/main/data/danggok_meals.csv"

st.title("🥇 두 학기 최다 등장 메뉴")


@st.cache_data
def load_meals():
    df = pd.read_csv(DATA_URL)
    return df[df["식사"] == "중식"]          # 석식이 섞여 있으므로 중식만 고른다


meals = load_meals()
days = meals["날짜"].nunique()

# 한 칸에 붙어 있는 메뉴를 낱개로 나눠 등장 일수를 센다
items = meals["메뉴"].str.split("|").explode().str.strip()
counts = items.value_counts().reset_index()
counts.columns = ["메뉴", "일수"]
counts["비율(%)"] = (counts["일수"] / days * 100).round(0).astype(int)

# 몇 위까지 볼지 슬라이더로 고른다
top_n = st.slider("몇 위까지 볼까요?", min_value=5, max_value=20, value=10)
top = counts.head(top_n).copy()
top.insert(0, "순위", range(1, len(top) + 1))

# 큰 숫자 카드 셋 — 집계 일수, 1위 메뉴, 1위 비율
first = top.iloc[0]
c1, c2, c3 = st.columns(3)
c1.metric("집계한 날", f"{days}일")
c2.metric("1위 메뉴", first["메뉴"])
c3.metric("1위 등장 비율", f"{first['비율(%)']}% ({first['일수']}일)")

# 막대는 1위가 맨 위, 값이 클수록 진한 색, 막대마다 일수와 비율
top["표시"] = top["일수"].astype(str) + "일 (" + top["비율(%)"].astype(str) + "%)"
fig = px.bar(
    top.sort_values("일수"), x="일수", y="메뉴", orientation="h",
    text="표시", color="일수", color_continuous_scale="Oranges",
    title=f"중식 {days}일 중 가장 자주 나온 메뉴 TOP {top_n}",
)
fig.update_layout(coloraxis_showscale=False, xaxis_title="등장 일수", yaxis_title="")
st.plotly_chart(fig, width="stretch")

st.dataframe(top[["순위", "메뉴", "일수", "비율(%)"]], hide_index=True, width="stretch")
st.caption(f"중식 {days}일 기준 · 이 그래프로 알 수 있는 것: (한 문장으로 적어 보세요)")

  • 궁금한 것 하나 — "이 날짜를 고르면 어떻게 되나요?" 같은 물음.

8. 개념 정리

오늘 배운 것을 한 줄로 줄이면 이렇습니다. API마다 규칙(키·빈 응답·응답 모양)은 다르지만, 다가가는 순서는 같다. 문서 발췌를 읽고, 완성 주소를 맨눈으로 확인하고, 프롬프트에 문서를 붙여 부탁한다. 이 순서를 KOBIS와 나이스에서 두 번 밟았으니, 세 번째 API는 여러분 혼자서도 만날 수 있습니다. 그리고 받은 데이터가 바로 셀 수 있는 모양이 아닐 때가 많다는 것도 확인했습니다 — 한 덩어리 글자를 낱개로 나누는 다듬기(전처리)를 거쳐야 "154일 중 86일" 같은 숫자가 나옵니다.

9. 확인 문제

문제 1 일요일 날짜로 급식 API를 불렀더니 식단 없이 "해당하는 데이터가 없습니다"라는 안내만 왔습니다. 가장 알맞은 해석은 무엇일까요?
주말·방학은 급식이 없는 날이므로 돌려줄 데이터가 없습니다. 오류가 아니라 정상 응답이고, 좋은 앱은 이 경우를 "급식이 없는 날입니다"로 안내합니다. 주소가 틀리면 다른 오류가 나고, 서버 고장이면 응답 자체가 오지 않거나 500번대 상태코드가 옵니다.
문제 2 KOBIS와 나이스 급식 API의 차이를 인증키를 중심으로 두 가지 써 보세요.
예시 답 펼쳐 보기

① KOBIS는 인증키가 요청에 실려 가야 하고 키는 비밀 금고(secrets)에 보관하지만, 나이스 급식 API는 키 없이 부를 수 있다. ② 대신 나이스는 키가 없으면 한 번에 오는 건수에 제한이 있어 조회 기간을 짧게 잡는다.

문제 3 메뉴 열은 한 날의 메뉴 여러 개가 구분 기호로 이어진 한 덩어리 글자입니다. "가장 자주 나온 메뉴 TOP 10"을 세기 전에 어떤 단계가 필요하고, 그 단계를 건너뛰면 어떻게 될까요?
예시 답 펼쳐 보기

구분 기호를 기준으로 메뉴를 낱개로 나누고, 메뉴 뒤 괄호 속 알레르기 번호를 떼는 다듬기(전처리)가 필요하다. 건너뛰면 하루 식단 전체("친환경현미밥|오징어무국|…")가 통째로 한 메뉴로 세어져, 같은 배추김치라도 그날의 식단 조합이 다르면 모두 다른 값이 되므로 등장 횟수를 셀 수 없다.

🎒 오늘의 체크

  • KOBIS와 나이스 급식 API의 같은 점(다가가는 순서)과 다른 점(키·빈 응답·응답 모양)을 말할 수 있다.
  • 완성 주소를 주소창에 열어 급식 JSON에서 메뉴·칼로리 값을 찾았다.
  • 첫 화면(학교 검색)과 페이지 둘(달력별·메뉴별)이 main.py와 pages 폴더로 나뉘어 왼쪽 메뉴에 나타났다.
  • 급식 페이지를 내 앱에 추가했고, 급식이 없는 날의 안내 문구를 확인했다.
  • 두 학기 154일 최다 메뉴 TOP 10을 만들고 1위와 등장 일수를 확인했다.
  • 함께 자주 나올 것 같은 메뉴 짝 3개를 기록해 제출했다.
