두 번째 API — 우리 학교 급식

"물고기를 주면 하루를 먹이고, 잡는 법을 가르치면 평생을 먹인다."
속담 — 오늘은 두 번째 API를 여러분 손으로 붙입니다
🔎 자세한 판

이 페이지는 내용을 줄이지 않은 판입니다. 수업은 기본판으로 진행하고, 더 깊이 보고 싶을 때 이 판을 읽습니다.

오늘은 나이스(NEIS) 급식 API로 우리 학교 점심을 내 앱에 불러옵니다. 나이스는 교육행정정보시스템(National Education Information System)의 약자로, 전국 학교의 학사·행정 정보를 다루는 시스템입니다 — 여러분의 성적표와 생활기록부도 이 시스템에 있습니다. 방법은 2차시의 KOBIS와 같습니다 — 공식 문서의 발췌를 읽고, 완성 주소로 응답을 먼저 확인하고, 문서를 프롬프트에 붙입니다. 다른 점이 하나 있습니다. 이번 API는 인증키가 필요 없습니다.

🎯 오늘 하는 것
  • 두 API 비교 — KOBIS와 나이스, 무엇이 같고 무엇이 다른가
  • 바이브 코딩 — 내 포트폴리오 앱에 급식 페이지 추가 + 학기 154일 최다 메뉴 TOP 10
  • 기록 — 함께 자주 나올 것 같은 메뉴 짝 3개 (12차시에 다시 꺼냅니다)

0. 왜 배우나

세상의 API는 수천 개가 넘고, 수업이 그것을 전부 소개할 수는 없습니다. 그래서 오늘 배우는 것은 급식 API 하나가 아니라, 처음 보는 API에 다가가는 순서입니다. 문서 발췌를 읽고, 완성 주소를 맨눈으로 확인하고, 문서를 붙여 부탁한다 — 이 순서가 손에 붙으면 날씨·대중교통·도서관 등 어떤 API든 공식 문서만 있으면 여러분 앱의 재료가 됩니다. 2학기 후반의 팀 프로젝트에서 팀이 고른 데이터가 API로 온다면, 오늘 연습한 순서가 그대로 쓰입니다.

1. 두 API 비교 — 같은 순서, 다른 규칙

KOBIS에서 밟은 순서는 나이스에서도 통합니다. 그러나 규칙은 API마다 다릅니다. 가장 큰 차이는 인증키입니다.

KOBIS 박스오피스 (2차시)나이스 급식 (오늘)
인증키필요 — 비밀 금고(secrets)에 보관불필요 — 대신 한 번에 오는 건수 제한
빈 응답의 정체오늘 것은 아직 집계 전주말·방학은 급식이 없는 날 — 오류가 아니다
받자마자 다듬을 것숫자가 따옴표 친 글자로 온다메뉴 전체가 한 덩어리 글자로 온다 — 구분 기호와 알레르기 괄호를 떼야 표가 된다
⚠️ 건수 제한의 실물 — 조회 기간은 짧게

키 없이 다섯 달치(2026-03-01~07-31)를 한 번에 물어보면, 응답은 "전체 82건"이라고 알려 주면서 목록에는 앞의 5건만 담아 보냅니다(실측). 오류도 나지 않아서 알아채기 어렵습니다. 그래서 오늘 실습의 날짜 조회는 하루~한 주 단위로 짧게 잡고, 학기 전체가 궁금할 때는 미리 쌓아 둔 표 danggok_meals.csv(③에서 등장)를 씁니다.

2. 완성 주소 맨눈 보기 — 급식 JSON 해부

🔎 이런 사이트예요 — 나이스 교육정보 개방 포털

open.neis.go.kr은 나이스의 학교 데이터 일부를 누구나 쓸 수 있게 공개한 곳입니다. 급식 식단 말고도 학교 기본 정보·학사 일정·시간표 API가 있고, 우리 학교만이 아니라 전국 어느 학교든 학교 코드만 바꾸면 조회됩니다 — "우리 학교와 옆 학교의 급식은 얼마나 다를까" 같은 질문의 재료가 됩니다.

✔️ 문서까지 가는 길 — 2차시에 KOBIS에서 했던 그대로

포털 첫 화면에서 데이터셋 메뉴로 들어가 급식식단정보를 찾아 열고, 상세 화면의 Open API 항목을 펼치면 오늘의 문서가 나옵니다. 볼 곳 세 곳의 이름이 KOBIS와 조금 다릅니다 — 신청주소(요청 주소) · 신청인자 표(요청변수 — 교육청·학교 코드 등) · 출력값 표(응답 구조). 이름이 달라도 하는 일은 같아서, 세 곳을 긁어 프롬프트 끝에 붙이면 됩니다. 아래 ①의 발췌가 바로 그 결과물입니다.

2차시와 같은 순서입니다. 코드를 쓰기 전에 완성 주소를 새 탭에서 열어, 응답 JSON을 맨눈으로 확인합니다. 먼저 주소를 해부해 봅니다. KOBIS 주소에 있던 key=가 여기에는 없습니다.

요청 주소의 해부 — 인증키 없는 요청
https://open.neis.go.kr/hub/mealServiceDietInfo   ← 어디에 — 요청 주소
?Type=json                                        ← 응답 형식 — 이 줄이 빠지면 XML로 온다
&ATPT_OFCDC_SC_CODE=B10                           ← 조건 — 교육청(서울)
&SD_SCHUL_CODE=7010073                            ← 조건 — 학교(당곡고)
&MMEAL_SC_CODE=2                                  ← 조건 — 식사(중식)
&MLSV_FROM_YMD=20260602&MLSV_TO_YMD=20260602      ← 조건 — 기간(하이픈 없는 여덟 자리)
요청 주소와 조건은 2차시 KOBIS와 같은 구조인데, 인증키만 없다. 날짜 두 값을 바꾸면 응답이 그 기간 것으로 바뀐다.

키가 필요 없으니 완성 주소를 그냥 눌러서 열 수 있습니다 → 2026년 6월 2일 당곡고 중식, 새 탭에서 열어 보기. 아래는 그 실제 응답입니다.

  • 값 꺼내기는 2차시와 같다 — KOBIS의 boxOfficeResult → dailyBoxOfficeList와 이름만 다를 뿐, 상자에서 상자를 꺼내는 읽기는 같습니다.
  • 👀 눈여겨볼 것 — 메뉴 일곱 개가 한 칸에 들어 있다. DDISH_NM에는 그날 메뉴 전체가 <br/>라는 구분 기호로 이어진 한 덩어리 글자로 옵니다. 메뉴 뒤 괄호 속 숫자는 알레르기 유발 식품 번호입니다. 이대로는 "배추김치가 며칠 나왔나"를 셀 수 없습니다 — 구분 기호로 낱개를 나누고 괄호를 떼는 다듬기가 필요합니다.
  • 급식이 없는 날을 골라 보면 — 일요일 날짜로 바꿔 다시 접속하면 식단 없이 "해당하는 데이터가 없습니다"라는 안내만 옵니다. 고장이 아니라 그날 급식이 없다는 정상 응답입니다.

3. 실습 — 급식 페이지를 내 앱에 추가한다

4차시에 완성한 포트폴리오 앱에 다섯 번째 페이지를 답니다. 2차시에는 프롬프트를 쓰기 전에 키를 비밀 금고(secrets)에 넣는 단계가 있었지만, 오늘은 넣을 키가 없으므로 그 단계가 통째로 없습니다. 프롬프트 끝에 공식 문서 발췌를 붙이는 요령은 그대로입니다 — AI가 필드 이름을 지어내지 못하게 막는 안전장치입니다.

  1. ① 샘플 프롬프트 — 그대로 붙여 넣기
    ① 프롬프트
    내 포트폴리오 앱에 '우리 학교 급식' 페이지를 추가해 줘.
아래에 나이스 교육정보 개방 포털 문서에서 복사한 내용을 붙였어. 이 API는 인증키가 없어도 돼.

- 날짜를 달력에서 고르면 그날 당곡고등학교 중식 메뉴를 카드로 보여 줘.
- 메뉴 이름 뒤 괄호 속 숫자는 알레르기 번호야. 평소엔 떼고 보여 주되,
  '알레르기 정보 보기'를 켜면 번호와 함께 보이게 해 줘.
- 그날의 칼로리도 함께 보여 줘.
- 주말이나 방학처럼 급식이 없는 날은 오류 대신 "급식이 없는 날입니다"라고 안내해 줘.

  2. ② AI가 준 코드 — 실행하고 관찰한다
    아래는 이 프롬프트로 받은 코드의 한 예입니다. 여러분 화면이 이런 모습이면 성공이고, 글자까지 같지 않아도 됩니다.
    ② AI가 준 코드 예시 — 
    # pages/5_🍚_우리학교_급식.py — 나이스 급식 API로 그날 식단을 보여 주는 페이지
import datetime
import re

import requests
import streamlit as st

st.title("🍚 우리 학교 급식")

# 날짜 고르기 — 기본값은 오늘
picked = st.date_input("날짜를 고르세요", value=datetime.date.today())
ymd = picked.strftime("%Y%m%d")

# 알레르기 번호를 보일지 선택
show_allergy = st.toggle("알레르기 정보 보기")

# 나이스 급식 API — 인증키 없이 호출한다 (조회 기간은 하루)
url = "https://open.neis.go.kr/hub/mealServiceDietInfo"
params = {
    "Type": "json",                # 응답을 JSON으로
    "ATPT_OFCDC_SC_CODE": "B10",   # 서울시교육청
    "SD_SCHUL_CODE": "7010073",    # 당곡고등학교
    "MMEAL_SC_CODE": "2",          # 중식
    "MLSV_FROM_YMD": ymd,
    "MLSV_TO_YMD": ymd,
}
data = requests.get(url, params=params, timeout=10).json()

if "mealServiceDietInfo" not in data:
    # 급식이 없는 날은 row 없이 RESULT 상자만 온다 — 오류가 아니다
    st.info("급식이 없는 날입니다. (주말·방학·공휴일)")
else:
    row = data["mealServiceDietInfo"][1]["row"][0]
    st.subheader(picked.strftime("%Y년 %m월 %d일") + " 중식")
    # 메뉴 전체가 한 덩어리 글자로 온다 — <br/>로 잘라 낱개 메뉴로
    for dish in row["DDISH_NM"].split("<br/>"):
        dish = dish.strip()
        if not show_allergy:
            # 괄호 속 알레르기 번호 떼기
            dish = re.sub(r"\s*\([0-9.]+\)", "", dish)
        st.markdown("- " + dish)
    st.metric("칼로리", row["CAL_INFO"])
    실행되면 세 가지를 관찰합니다. 수업일을 고르면 그날 식단과 칼로리가 나오는지, '알레르기 정보 보기'를 켜면 괄호 숫자가 나타나는지, 그리고 일요일이나 방학 날짜를 골랐을 때 오류 화면 대신 안내 문구가 나오는지. 빈 응답을 앱이 어떻게 받아 내는지가 오늘의 관찰 대상입니다.
  3. ③ 개선 프롬프트 — 하루에서 학기 전체로
    달력 조회는 하루씩만 보여 줍니다. "한 학기 동안 무엇이 가장 자주 나왔나"에 답하려면, 건수 제한이 있는 API 대신 미리 쌓아 둔 표로 갈아탑니다. 3차시에 하루치 API에서 354일 표로 전환했던 것과 같은 장면입니다.

    좋아, 여기서 이어서 고쳐 줘.

5. 기록 — 함께 자주 나올 것 같은 메뉴 짝 3개

154일 표에는 "무엇이 자주 나왔나"만이 아니라 "무엇이 함께 나왔나"도 들어 있습니다. 카레라이스가 나오는 날의 국은 무엇이었을까요? 제육볶음 옆에는 무엇이 놓였을까요? 12차시에 이 표에서 함께 나오는 메뉴의 규칙을 데이터로 찾아봅니다. 오늘은 데이터를 열어 보기 전, 여러분의 직감을 먼저 기록해 둡니다.

  • 형식 — "○○가 나오는 날엔 △△도 나온다" 꼴의 짝을 3개 적습니다.
  • 제출 — 선생님이 안내하는 폼(또는 클래스룸 과제)에 기록합니다.
  • 주의 — 12차시에 오늘의 예상을 그대로 다시 꺼내 실제 규칙과 대조합니다. 무엇을 적었는지 기억해 두세요.
💡 예상을 고를 때 한 가지

위 표에서 봤듯 배추김치는 둘에 하루꼴로 나옵니다. 매일 나오다시피 하는 메뉴를 짝으로 적으면 맞을 수밖에 없겠지요. 그 "맞은 예상"이 과연 의미가 있는지도 12차시에 함께 따져 봅니다.

6. 갤러리 — 포트폴리오를 공개한다

여러분의 앱은 이제 다섯 페이지입니다 — 기온 분석, 어제의 박스오피스, 그래프 도감 1·2, 그리고 오늘의 급식 페이지. 포트폴리오 주소를 갤러리에 올리고(주소는 클래스룸 공지 참고), 짝의 앱을 열어 봅니다. 피드백은 두 줄이면 됩니다.

  • 좋았던 것 하나 — 내 앱에 없는 화면·문구·아이디어.
  • 궁금한 것 하나 — "이 날짜를 고르면 어떻게 되나요?" 같은 물음.

7. 개념 정리

오늘 배운 것을 한 줄로 줄이면 이렇습니다. API마다 규칙(키·빈 응답·응답 모양)은 다르지만, 다가가는 순서는 같다. 문서 발췌를 읽고, 완성 주소를 맨눈으로 확인하고, 프롬프트에 문서를 붙여 부탁한다 — 이 순서를 KOBIS와 나이스에서 두 번 밟았으니, 세 번째 API는 여러분 혼자서도 만날 수 있습니다. 그리고 받은 데이터가 바로 셀 수 있는 모양이 아닐 때가 많다는 것도 확인했습니다 — 한 덩어리 글자를 낱개로 나누는 다듬기(전처리)를 거쳐야 "154일 중 86일" 같은 숫자가 나옵니다.

8. 확인 문제

문제 1 일요일 날짜로 급식 API를 불렀더니 식단 없이 "해당하는 데이터가 없습니다"라는 안내만 왔습니다. 가장 알맞은 해석은 무엇일까요?
주말·방학은 급식이 없는 날이므로 돌려줄 데이터가 없습니다. 오류가 아니라 정상 응답이고, 좋은 앱은 이 경우를 "급식이 없는 날입니다"로 안내합니다. 주소가 틀리면 다른 오류가 나고, 서버 고장이면 응답 자체가 오지 않거나 500번대 상태코드가 옵니다.
문제 2 KOBIS와 나이스 급식 API의 차이를 인증키를 중심으로 두 가지 써 보세요.
예시 답 펼쳐 보기

① KOBIS는 인증키가 요청에 실려 가야 하고 키는 비밀 금고(secrets)에 보관하지만, 나이스 급식 API는 키 없이 부를 수 있다. ② 대신 나이스는 키가 없으면 한 번에 오는 건수에 제한이 있어 조회 기간을 짧게 잡는다.

문제 3 메뉴 열은 한 날의 메뉴 여러 개가 구분 기호로 이어진 한 덩어리 글자입니다. "가장 자주 나온 메뉴 TOP 10"을 세기 전에 어떤 단계가 필요하고, 그 단계를 건너뛰면 어떻게 될까요?
예시 답 펼쳐 보기

구분 기호를 기준으로 메뉴를 낱개로 나누고, 메뉴 뒤 괄호 속 알레르기 번호를 떼는 다듬기(전처리)가 필요하다. 건너뛰면 하루 식단 전체("친환경현미밥|오징어무국|…")가 통째로 한 메뉴로 세어져, 같은 배추김치라도 그날의 식단 조합이 다르면 전부 다른 값이 되므로 등장 횟수를 셀 수 없다.

🎒 오늘의 체크

  • KOBIS와 나이스 급식 API의 같은 점(다가가는 순서)과 다른 점(키·빈 응답·응답 모양)을 말할 수 있다.
  • 완성 주소를 주소창에 열어 급식 JSON에서 메뉴·칼로리 값을 찾았다.
  • 급식 페이지를 내 앱에 추가했고, 급식이 없는 날의 안내 문구를 확인했다.
  • 학기 154일 최다 메뉴 TOP 10을 만들고 1위와 등장 일수를 확인했다.
  • 함께 자주 나올 것 같은 메뉴 짝 3개를 기록해 제출했다.
