속담 — 함께 등장하는 메뉴를 찾고, 규칙의 방향과 등장 빈도를 비교합니다

“제육볶음이 나오는 날 배추김치도 나올까?” 지지도·신뢰도·향상도를 손으로 계산한 뒤 당곡고 급식 자료에서 메뉴의 동시 등장 패턴을 찾습니다. 세 지표의 차이를 이해하고, 표본에서 찾은 규칙을 어디까지 해석할 수 있는지 판단합니다.

  • 판정 — 신뢰도가 높아도 기본 등장률과 차이가 작을 수 있음을 확인한다

0. 왜 배우나

연관 분석은 함께 나타나는 항목의 패턴을 찾습니다. 자주 나오는 메뉴는 다른 여러 메뉴와도 자주 겹칩니다. 따라서 동시 등장 횟수뿐 아니라 각 메뉴의 기본 등장률도 함께 살펴야 합니다. 오늘은 하루 중식 식단을 한 건으로 보고, 두 메뉴의 관계를 비교합니다.

1. 개념 이해 — 교과서의 세 숫자

📖 교과서의 정의 『데이터 과학』 159·160쪽

"지지도는 두 개의 사건이 동시에 발생하는 비율이며 …" (159쪽)

"신뢰도는 규칙의 결과 부분이 발생할 가능성을 측정한다." (159쪽)

"두 사건 A와 B가 서로 영향을 주지 않고 독립적으로 발생한다면, 향상도는 1에 가까워진다." (160쪽)

→ 지지도는 전체에서 함께 나온 비율, 신뢰도는 A가 나온 경우 중 B도 나온 비율, 향상도는 그 신뢰도를 B의 전체 등장률로 나눈 값입니다. 향상도 1은 표본에서 두 비율이 같다는 뜻이며, 그것만으로 우연이나 독립을 증명하지는 않습니다.

숫자계산식 (N: 전체 일수)묻는 말
지지도A·B 동시 일수 ÷ N이 조합, 다룰 만큼 자주 나오는가
신뢰도A·B 동시 일수 ÷ A 등장 일수A가 나오면 B도 나오는가
향상도신뢰도 ÷ (B 등장 일수 ÷ N)A가 있을 때 B의 등장률은 전체 등장률의 몇 배인가

교과서의 {삼겹살} → {쌈채소} 규칙은 향상도가 1.67입니다. 삼겹살을 산 거래에서 쌈채소를 산 비율이 전체 거래의 쌈채소 구매 비율보다 약 1.67배 높다는 뜻입니다. 구매 원인이나 미래의 구매를 보장하는 값은 아닙니다.

2. 손 활동지 ① — 교과서 해 보기부터

✍️ 활동지 문제 1 (교과서 158·160쪽 해 보기 ①)

교과서 158쪽의 거래 목록 10건을 펴고, 활동지에서 {쌀} → {김치}와 {삼겹살, 쌈채소} → {고추장}의 세 지표를 계산합니다. 계산을 마치면 짝과 ③번 토의("영향이 가장 큰 규칙은?")의 답을 비교해 보세요.

⚠️ 계산이 끝나면 판단이 달라진다

두 규칙 모두 그럴듯해 보이지만, 향상도를 구하면 판단이 달라집니다. 교과서의 표는 이 판정 기준을 미리 준비해 둡니다. 이 기준을 가지고 우리 학교 급식으로 넘어갑니다.

3. 실습 — 급식 184일에서 규칙 찾기 (바이브 코딩)

분석 전에 함께 나올 것 같은 메뉴 쌍 세 개와 그 이유를 적습니다. 실습 후에는 예상과 결과를 대조합니다. 앱은 5차시의 인증키로 급식 API에서 2025년 9월 1일~2026년 9월 30일 중식을 조회합니다. 기간이 같아도 원자료의 수정·추가에 따라 결과가 달라질 수 있습니다. 본문 손계산은 184일 급식 저장본을 기준으로 합니다. 실행 결과와 다르면 조회 시점·일수·메뉴 정리 기준부터 확인합니다.

원본 — 급식 API가 준 하루

괄호가 두 가지 섞여 있습니다. 숫자는 알레르기 번호이고, (자율)·(대)·(소스)처럼 글자가 든 것도 있습니다. 이 실습에서는 괄호 내용을 제거한 이름으로 집계합니다. 용량·소스 등의 구분도 없어지므로, 이 기준이 분석 목적에 맞는지 확인합니다. 알레르기 안내에는 원래 식단을 사용합니다.
변환 — 장바구니 1건

하루 식단이 장바구니 1건, 메뉴 하나가 상품 하나. 하루가 장바구니 하나이므로 중식 184일이 곧 장바구니 184건입니다. 메뉴 종류 수는 정리 기준에 따라 달라집니다. 저장본에서 괄호를 제거하고 센 메뉴는 506종입니다.

- 기간은 2025년 9월 1일부터 2026년 9월 30일까지, 중식만. 조회된 모든 페이지를 받아 날짜별로 한 건씩 세어 줘.
- 조회 자료 없음과 인증·통신 오류를 구분하고, 일부만 받은 자료로 계산하지 않게 해 줘.
- 메뉴는 한 덩어리 글자로 오니까 <br/> 기준으로 나누고, 괄호는 전부 떼서 세 줘.
각 규칙마다 지지도, 신뢰도, 향상도를 표로 보여 주고,
동시에 나온 횟수가 5회 이상인 규칙만 보이게 해 줘.
필요한 라이브러리 목록(requirements.txt)도 같이 줘. 버전 숫자 없이 이름만.

    파일 하나로 저장합니다

    # app.py — 함께 자주 나오는 메뉴 쌍을 찾는다
import re
from collections import Counter
from itertools import combinations

import pandas as pd
import requests
import streamlit as st


@st.cache_data(ttl=3600)
def load_baskets(api_key):
    rows, page = [], 1
    params = {"Type": "json", "KEY": api_key,
              "pSize": 1000, "ATPT_OFCDC_SC_CODE": "B10",
              "SD_SCHUL_CODE": "7010073", "MMEAL_SC_CODE": "2",
              "MLSV_FROM_YMD": "20250901", "MLSV_TO_YMD": "20260930"}
    while True:
        response = requests.get("https://open.neis.go.kr/hub/mealServiceDietInfo",
                                params={**params, "pIndex": page}, timeout=20)
        response.raise_for_status()
        data = response.json()
        if "mealServiceDietInfo" not in data:
            result = data.get("RESULT", {})
            if result.get("CODE") == "INFO-200" and page == 1:
                return []
            raise ValueError("급식 조회 실패: " + result.get("MESSAGE", "응답 확인 필요"))
        blocks = data["mealServiceDietInfo"]
        head = next(block["head"] for block in blocks if "head" in block)
        total = next(item["list_total_count"] for item in head if "list_total_count" in item)
        chunk = next((block["row"] for block in blocks if "row" in block), [])
        if not chunk:
            raise ValueError("전체 자료를 받기 전에 빈 페이지가 반환되었습니다.")
        rows.extend(chunk)
        if len(rows) >= total:
            break
        if len(chunk) < params["pSize"]:
            raise ValueError("전체 건수보다 적게 받았습니다. 인증키를 확인하세요.")
        page += 1
    days = {}
    for row in rows:
        basket = days.setdefault(row["MLSV_YMD"], set())
        for dish in re.split(r"<br\s*/?>", row["DDISH_NM"], flags=re.I):
            name = re.sub(r"\([^)]*\)", "", dish).strip()
            if name:
                basket.add(name)
    return [sorted(basket) for basket in days.values() if basket]

try:
    api_key = st.secrets["NEIS_API_KEY"]
except Exception:
    st.error("비밀 금고에 NEIS_API_KEY를 설정하세요. 5차시 안내를 확인합니다.")
    st.stop()
if not api_key.strip():
    st.error("인증키가 비어 있습니다.")
    st.stop()
try:
    baskets = load_baskets(api_key)
except (requests.RequestException, ValueError, KeyError, StopIteration):
    st.error("급식을 모두 조회하지 못했습니다. 인증키·조회 조건·연결 상태를 확인하세요.")
    st.stop()
if not baskets:
    st.info("조회 기간에 분석할 중식 자료가 없습니다.")
    st.stop()
n = len(baskets)
single = Counter(item for b in baskets for item in b)
pair = Counter(c for b in baskets for c in combinations(b, 2))

rows = []
for (a, b), together in pair.items():
    if together < 5:                       # 동시에 나온 횟수가 5회 미만이면 뺀다
        continue
    for x, y in [(a, b), (b, a)]:
        rows.append({"조건": x, "결과": y, "동시": together,
                     "지지도": round(together / n, 3),
                     "신뢰도": round(together / single[x], 3),
                     "향상도": round((together / single[x]) / (single[y] / n), 2)})
rules = pd.DataFrame(rows, columns=["조건", "결과", "동시", "지지도", "신뢰도", "향상도"])
rules = rules.sort_values("향상도", ascending=False)
if rules.empty:
    st.info("동시 등장 5회 이상인 규칙이 없습니다.")

st.caption(f"급식 {n}일 · 규칙 {len(rules)}개 (동시 5회 이상)")
st.dataframe(rules, hide_index=True)
  2. ② AI가 준 코드 — 실행하고 표를 읽는다
    표가 나타나면 신뢰도 순으로 한 번, 향상도 순으로 한 번 정렬해 봅니다. 두 순위가 서로 다르다는 것이 오늘의 발견입니다.
  3. ③ 개선 프롬프트 — 판정 기준을 화면에 표시한다
    ③ 개선
    향상도가 높은 순서로 정렬하고, 향상도가 1에 가까운 규칙(0.9~1.1)은
"기본 등장률과 비슷함"이라고 표시해 줘. 이 구간은 관찰용 기준이며 통계 검정 결과가 아니라고 안내해 줘.
그리고 메뉴 이름을 고르면 그 메뉴가 낀 규칙만 모아 볼 수 있게 해 줘.

    # 향상도가 1 언저리인 규칙은 따로 표시하고, 메뉴로 좁혀 본다
rules["판정"] = rules["향상도"].apply(lambda v: "기본 등장률과 비슷함" if 0.9 <= v <= 1.1 else "")
메뉴 = st.selectbox("메뉴로 좁혀 보기", ["(전체)"] + sorted(single))

💡 프롬프트에 코드가 없다는 것

프롬프트에는 분석 대상, 메뉴 정리 기준, 원하는 결과를 명확히 적습니다. AI가 계산 코드를 작성하더라도 메뉴가 올바르게 나뉘었는지와 분모가 맞는지는 확인해야 합니다. 대표 규칙 몇 개를 직접 세어 보면 오류를 찾는 데 도움이 됩니다.

4. 결과 해석 — 기본 등장률과 비교하기

아래 값은 위에서 연결한 184일 저장본으로 검산했습니다. 등장 열은 앞 메뉴와 뒤 메뉴가 각각 나온 일수입니다. 마지막 행은 동시 0회이므로 “동시 5회 이상” 결과 표에 나오지 않습니다. 별도로 두 메뉴를 세어 비교한 사례입니다.

⚠️ 세 장면이 말하는 것
  • 신뢰도는 기본 등장률과 비교합니다. 0.60이 전체 등장률 약 0.55보다 얼마나 높은지 함께 봅니다.
  • 규칙에는 방향이 있다 — 순대국→석박지는 1.00이지만, 석박지→순대국은 0.25다.
  • 동시 0회도 관찰 결과입니다. 이 기간에 두 김치가 함께 나오지 않았다는 뜻입니다. 실제 운영 원칙인지는 별도로 확인해야 합니다.

분석 전에 적은 메뉴 쌍과 결과를 대조합니다. 동시 등장 횟수, 신뢰도, 기본 등장률, 향상도를 함께 적고 해석합니다. 결과 표에 없다고 반드시 관련이 없는 것은 아닙니다. 최소 횟수 기준 때문에 제외되었는지도 확인합니다. 이 기록을 Ⅲ-04d 과제에 활용합니다.

6. 개념 정리 — 교과서와 급식이 만난 자리

지지도는 조합의 빈도를, 신뢰도는 조건부 비율을, 향상도는 기본 등장률과의 비율을 나타냅니다. 세 지표를 함께 보고 관측 기간과 등장 횟수도 기록합니다. 동시 5회 이상이라는 기준은 드문 조합을 제외하는 실습 기준이며, 통계적으로 유의하거나 미래에도 유지되는 규칙을 보장하지 않습니다.

향상도 9.2는 순대국이 석박지의 등장을 일으킨다는 인과관계의 증명이 아닙니다. 식단 구성 방침 등 다른 요인이 두 메뉴에 함께 작용했을 수 있습니다. 신뢰도 1.00도 이 표본의 5일에서 관찰된 값으로, 다음 식단을 보장하지 않습니다.

7. 확인 문제

문제 1 당곡고 184일에서 제육볶음 10일, 배추김치 102일, 동시 6일이다. "제육볶음 → 배추김치"의 신뢰도와 향상도를 손으로 계산한 뒤, 판정을 골라 보세요.
신뢰도 = 6÷10 = 0.60, 향상도 = 0.60÷(102÷184) ≈ 1.08. 이 표본에서는 기본 등장률보다 약 8% 높은 비율입니다. 강한 연관이나 독립을 확정하려면 이 값만으로는 부족합니다.
계산 펼쳐 보기

신뢰도는 6÷10 = 0.60, 향상도는 0.60÷(102÷184) ≈ 1.08입니다. 중간 값을 반올림하지 않고 마지막에 반올림합니다. 향상도가 1에 가까워 기본 등장률과 차이가 작지만, 이를 우연의 증명으로 해석하지는 않습니다.

문제 2 "순대국 → 석박지"의 신뢰도는 1.00, "석박지 → 순대국"의 신뢰도는 0.25다. 급식실 게시판에 "석박지가 나오는 날은 순대국이 나온다"라고 써 붙여도 될까요?
규칙에는 방향이 있습니다. 석박지가 나온 20일 중 순대국은 5일뿐이므로, 그 기간의 식단 중 15일은 게시판 문장과 맞지 않습니다. 미래 식단도 보장하지 않습니다.
문제 3 어느 쌍의 향상도가 184로 나왔다(학기 전체에서 동시 등장 1회, 각자 등장도 1회씩). 향상도 9.2인 순대국·석박지보다 20배 강한 규칙이라 말할 수 있을까요?
동시 1회만으로 안정적인 패턴이라고 판단하기 어렵습니다. 동시 5회 이상은 이 실습의 최소 횟수 기준이며, 184일에서 최소 지지도 5÷184 ≈ 0.027에 해당합니다. 이 기준도 우연을 완전히 배제하지는 못합니다.

🎒 오늘의 체크

  • 지지도·신뢰도·향상도의 분모가 각각 무엇인지 말할 수 있다.
  • 교과서 해 보기 ①의 두 규칙을 손으로 계산하고 판정했다.
  • 급식 자료에서 향상도가 높은 규칙과 기본 등장률에 가까운 규칙을 비교했다.
  • 향상도만으로 인과관계나 미래의 식단을 보장할 수 없는 이유를 설명할 수 있다.
