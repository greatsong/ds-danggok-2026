13차시 준비 안내 · 표와 접속 정보

반찬 월드컵 앱이 학급의 대결 기록을 한곳에 모으려면 먼저 대결 기록 표와 접속 정보가 준비되어 있어야 합니다. 이 문서는 그 준비 절차만 모은 안내입니다. 준비는 교사 또는 모둠의 준비 담당자가 한 번만 합니다. 나머지 학생은 준비된 접속 정보와 배포된 앱 주소를 받아 13차시 교재 2절의 실습으로 바로 들어갑니다.

← 13차시 교재로

⚠️ 이 문서에서 지키는 두 가지
  • publishable 키만 사용합니다. secret·service_role 키와 DB 연결 문자열·DB 비밀번호는 앱에 넣지 않고 학생에게 배포하지도 않습니다.
  • 막혔다고 권한을 열지 않습니다. 오류가 나면 RLS를 끄거나 관리자 키를 넣어 넘어가지 않고, 표 이름·열 이름·접속 대상·허용 동작을 차례로 확인합니다.

1. 프로젝트와 대결 기록 표를 준비합니다

  1. 1. Supabase 프로젝트를 만듭니다
    Supabase 대시보드에 로그인합니다. 사용할 조직을 선택하고 New project로 연습용 프로젝트를 만듭니다. 프로젝트 이름·DB 비밀번호·지역 등 화면에서 요구하는 항목을 입력하고 준비가 끝날 때까지 기다립니다. 이 DB 비밀번호는 아래 앱에 넣을 API 키와 다른 값입니다.
  2. 2. 대결 기록 표와 권한을 준비합니다
    만든 프로젝트의 SQL Editor에서 새 쿼리를 엽니다. 13차시 교재 3절의 ‘SQL · 표 만들기’ 코드 전체를 복사해 붙여 넣고 Run을 누릅니다. 표 생성부터 권한 정책까지 한 번만 실행합니다. 이미 표가 있다는 오류가 나오면 반복 실행하거나 기존 표를 지우지 말고, 올바른 연습용 프로젝트를 열었는지 먼저 확인합니다.
  3. 3. 준비 결과를 확인합니다
    Table Editor에서 public 스키마의 menu_duels를 엽니다. id·game_id·round·left_menu·right_menu·winner·created_at 일곱 열과 RLS 활성화 상태를 확인합니다. 새로 만든 표는 0행입니다. SQL 실행 중 오류가 있었다면 그대로 앱 연결로 넘어가지 않습니다.
  4. 4. 같은 프로젝트의 주소와 키를 복사합니다
    프로젝트의 Connect에서 Project URL과 publishable 키를 확인합니다. 키는 Settings → API Keys에서도 찾을 수 있습니다. 사용할 값은 https://…supabase.co 형식의 프로젝트 주소와 sb_publishable_… 키입니다. DB 연결 문자열이나 DB 비밀번호를 넣지 않습니다. secret·service_role 키도 사용하지 않습니다. 준비 담당자가 직접 앱을 배포하거나, 앱을 만들 학생에게 이 두 값을 전달합니다.

화면 이름이나 위치가 달라졌다면 Supabase 프로젝트·SQL 준비 안내와 API 키 안내를 확인합니다.

2. 접속 정보 두 줄을 만듭니다

  1. 준비 — 비밀 금고(secrets)에 넣을 접속 정보 두 줄 만들기
    준비 담당자가 확인한 프로젝트 주소와 publishable 키로 아래 두 줄을 만듭니다. 코드 파일 대신 앱의 Secrets에 넣습니다. 처음 배포할 때는 Advanced settings → Secrets에 붙여 넣고 저장합니다. 이미 배포했다면 앱의 설정에서 Secrets를 수정합니다. 자세한 배포 순서는 아래 3절을 따릅니다.
    Secrets에 넣을 두 줄의 모양
    SUPABASE_URL = "준비한 프로젝트 주소를 여기에"
SUPABASE_KEY = "준비한 publishable 키를 여기에"
    🔐 두 줄 만들기 — 준비한 값을 붙여 넣으면 Secrets에 넣을 두 줄이 완성됩니다
    SUPABASE_URL = "…" SUPABASE_KEY = "…"
    스트림릿 클라우드 열기 ↗
    주소와 키는 이 화면 안에서만 쓰이고 어디에도 저장·전송되지 않습니다. 복사한 두 줄을 처음 배포할 때의 Advanced settings → Secrets 또는 배포된 앱의 Secrets 설정에 붙여 넣습니다. 연결 정보는 교사가 안내한 범위에서 사용합니다.
    ⚠️ 이름 세 곳 일치 — 하나라도 다르면 못 찾는다

    SUPABASE_URL과 SUPABASE_KEY는 비밀 금고와 코드에서 철자가 같아야 합니다. 이 실습에는 publishable 키 또는 기존 anon 키를 사용합니다. secret·service_role 키는 학생에게 배포하지 않습니다. 공개 가능한 키를 숨기는 것만으로 데이터를 보호할 수는 없으며, 실제 허용 동작은 데이터베이스의 권한과 RLS 정책으로 정합니다.

    어디어떤 모습
    ① 비밀 금고(Secrets)SUPABASE_URL = "…" · SUPABASE_KEY = "…" — 앞에서 만든 두 줄
    ② 프롬프트"접속 정보는 비밀 금고(secrets)의 SUPABASE_URL과 SUPABASE_KEY에서 읽어 줘"
    ③ AI가 준 코드st.secrets["SUPABASE_URL"] · st.secrets["SUPABASE_KEY"]

3. 앱 배포 — 같은 대결 기록을 함께 모읍니다

기본 실습은 모둠별 앱 하나로 진행합니다. 교사 또는 준비 담당자는 Supabase·GitHub·Streamlit Community Cloud 계정으로 준비하고, 친구들은 배포된 앱 주소를 엽니다. 각자 앱을 만들더라도 같은 프로젝트의 menu_duels 표에 연결해야 기록이 합쳐집니다.

  1. 1. 파일을 저장합니다
    이번 앱용 GitHub 저장소에 main.py와 requirements.txt를 같은 폴더에 올립니다. main.py에는 13차시 교재 2절의 ② 예시 코드와 ③ 분석 코드를 순서대로 넣습니다. requirements.txt에는 streamlit, supabase, pandas, plotly를 각각 한 줄씩 적습니다. SQL과 접속 정보는 이 파일에 넣지 않습니다.
  2. 2. 앱을 배포합니다
    Streamlit Community Cloud에 GitHub 계정으로 로그인하고 Create app에서 저장소·브랜치·실행 파일 main.py를 선택합니다. Advanced settings의 Secrets에 준비한 접속 정보 두 줄을 저장한 뒤 Deploy를 누릅니다.
  3. 3. 주소를 공유합니다
    두 반찬과 선택 단추가 나타나는지 확인합니다. 공유 설정에서 친구가 접근할 수 있게 하고 배포된 앱 주소를 전달합니다. Supabase 관리 화면이나 GitHub 코드 주소는 참여 주소가 아닙니다.

화면이 달라졌다면 Streamlit 배포 안내를 확인합니다.

4. 완료 확인 — 두 기기에서 한 판씩 마칩니다

  1. 다른 친구들의 참여를 잠시 멈추고 현재 대결 기록 수를 적습니다. 서로 다른 두 기기에서 같은 앱 주소를 엽니다.
  2. 각 기기에서 일곱 번을 골라 우승 반찬이 나타나는지 확인합니다. 두 판 번호도 적습니다. 저장 확인 안내가 나오면 성공으로 간주하지 않습니다.
  3. 두 화면에서 결과 새로 불러오기를 누릅니다. 대결 기록 수가 이전보다 14 늘었는지 확인합니다.
  4. 준비 담당자는 Table Editor에서 두 판 번호를 각각 찾아 일곱 행씩 있는지, 8강 네 행·4강 두 행·결승 한 행인지 확인합니다. 앱을 다시 열고 조회해도 기록이 유지되는지 확인합니다.

이 절차로 배포·공유 저장·조회 연결을 점검합니다. 같은 사람이 여러 판을 할 수 있으므로 참여 인원을 검증한 것은 아닙니다. 결과는 자동 갱신되지 않으며 다시 불러와 확인합니다.

막혔을 때 확인합니다

연결 오류는 같은 프로젝트의 주소·publishable 키와 Secrets 이름을 확인합니다. 표·권한 오류는 준비 SQL의 실행 결과를 확인하며, RLS를 끄거나 관리자 키를 넣어 해결하지 않습니다. 저장 결과가 불확실하면 반복 제출하지 말고 판 번호로 최근 기록을 확인합니다. 조회만 실패했다면 결과를 다시 불러옵니다. 라이브러리 오류는 requirements.txt의 네 줄을 확인합니다.

준비가 끝나면 13차시 교재 2절로 돌아갑니다.
