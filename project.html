팀 프로젝트 — 우리 팀의 질문에 답하기

"제1원칙은 자신을 속이지 않는 것이다. 가장 속이기 쉬운 상대가 자기 자신이다."
리처드 파인만 (칼텍 졸업 연설, 1974). 한 학기 동안 배운 검증의 습관이 가장 필요한 곳은 우리 팀의 분석입니다

중간고사가 끝나면 2~3인 팀이 관심 있는 데이터로 머신러닝 프로젝트를 진행합니다. 5주(15차시) 동안 질문을 세우고, 데이터를 모으고, 수업에서 배운 방법 하나로 분석한 뒤, 그 결과를 우리 팀의 말로 해석합니다. 15차시에 쓴 팀 주제 카드가 출발점입니다.

🎯 세 가지만 기억하면 됩니다
  • AI는 마음껏 사용합니다. 코드는 전부 AI가 써도 됩니다.
  • 주제를 고른 이유와 결과의 해석은 여러분의 것이어야 합니다. AI가 대신 쓸 수 없는 부분입니다.
  • 발표 때 해석 질문에 답하지 못하면 그 항목은 최하점입니다. 질문은 미리 공개합니다(5절).

1. 5주의 흐름

주차 운영은 학급 사정에 따라 조정됩니다. 선생님이 확인하는 지점은 세 번입니다. 1주차 끝의 데이터 승인, 3주차 끝의 중간 점검, 5주차의 발표입니다.

주하는 일AI의 역할우리 팀의 몫선생님 확인
1주팀을 정하고, 주제 카드의 질문을 데이터로 답할 수 있는 형태로 다듬고, 데이터를 확보합니다. 4차시에 팀 저장소를 만들어 README와 log를 시작합니다데이터 찾기 도움"왜 우리가 이 주제인가" 한 문단데이터 승인(3차시)
2주데이터의 구멍·이상값·표기 흔들림을 확인하고 전처리합니다코드 전부뺄 값과 남길 값의 기준없음
3주질문에 맞는 방법(회귀·분류·군집·연관) 하나를 고르고, 그 안에서 모델 종류 몇 가지(예: 로지스틱·k-NN·결정 트리·랜덤 포레스트·XGBoost)를 같은 조건에서 비교해 하나를 택합니다. 기준선과도 비교합니다코드 전부어느 방법·어느 모델을 쓸지, 왜 그것인지, 기준선은 무엇인지중간 점검(9차시, 결과 1개와 지표 1개를 2분 안에 설명)
4주결과를 더 들여다보고(구간·사례·상관·시기), 해석과 한계를 적고, README를 완성합니다코드·확인 질문해석과 찾아낸 것은 팀이 씁니다12차시에 저장소를 동결합니다
5주발표와 문답발표 자료 도움문답발표 6분 + 문답 3분

2. 질문과 데이터

주제는 거창할 필요가 없습니다. 1차시의 좋은 질문 조건(측정 가능 · 데이터로 답 가능 · 범위 명확)을 그대로 쓰고, 데이터 후보마다 교과서 176쪽의 세 가지 질문으로 판단합니다. 분석 방법은 수업에서 배운 것 가운데 하나면 됩니다.

물음확인할 것
충분히 있는가판단의 근거가 될 만큼 양이 있고, 한쪽으로 치우치지 않았는가
문제에 적합한가내 질문이 요구하는 기간·속성·형식을 갖췄는가
법적·윤리적으로 올바른가개인 단위 정보 금지 · 출처 명시 · 이용 약관 확인 · 편향 점검(14차시)
🔎 데이터는 어디서 찾는가

문서가 공개된 곳부터 찾습니다. 수업에서 이미 다녀온 곳은 공공데이터포털(전 분야) · 기상자료개방포털(날씨) · 나이스 개방 포털(학교) · KOBIS(영화) · KBO 기록실(야구) · modudata(수업 정리 사본)입니다. 데이터를 찾지 못한 팀은 3차시에 선생님이 데이터를 지정합니다.

주제를 넓게 탐색할 때는 다음 일곱 곳이 좋습니다. 국내는 공공데이터포털(정부·공공기관 CSV와 API), KOSIS 국가통계포털(공식 통계표, 출처가 분명함), 서울열린데이터광장(따릉이·지하철·대기질처럼 자주 갱신되는 서울 데이터), 해외는 Kaggle Datasets(양이 가장 많지만 원출처·라이선스 확인 필수), NYC Open Data(뉴욕시가 매일·매주 갱신하는 택시·자전거·민원·학교 데이터, CSV와 API), data.gov(미국 연방·주·시 공공데이터 통합 검색), Our World in Data(국가별·연도별 지표를 깨끗한 CSV로)입니다. 키워드로 한 번에 찾으려면 Google Dataset Search를 씁니다.

3. 팀 저장소 — 프로젝트의 기록은 모두 여기에

팀당 깃허브 저장소 1개를 공개로 만듭니다. 코드가 바뀐 과정, AI에게 보낸 프롬프트, 매 차시의 느낀 점이 모두 이 저장소에 남습니다. 저장소가 곧 평가의 근거입니다. 클래스룸에 따로 내는 것은 없습니다.

저장소 구조
README.md           팀원 · 질문 · 왜 이 주제인가 · 데이터 · 방법 · 결과 해석 · 한계
data/               사용한 데이터 파일 또는 출처 주소
code/main.py        실행 코드. 바꿀 때마다 커밋합니다
log/01.md ~ 12.md   차시별 기록. 팀원 각자 섹션을 씁니다

README 틀

아래 틀을 README.md에 붙여 넣고 채웁니다. 팀원은 학번과 이름으로 씁니다. "왜 이 주제인가", "결과 해석", "더 해 보고 싶은 것", "느끼고 배운 점"은 반드시 팀이 직접 씁니다. 발표 슬라이드도 이 순서를 따릅니다.

12차시 기록에는 각자 개인 해석문 3~5줄을 더합니다. 팀 결론에 동의하는지, 보완할 점이 있는지, 반대하는지 가운데 하나로 시작합니다.

⚠️ 기록 규칙 네 가지
  • 커밋은 본인 계정으로 합니다. 한 계정에 커밋이 몰리면 기여도를 따로 확인합니다. 커밋 메시지는 "무엇을 왜 바꿨는지" 한 줄입니다.
  • "고치거나 버린 것" 줄이 가장 중요합니다. AI가 준 것을 그대로 받아 적기만 한 차시는 기록으로 인정하지 않습니다.
  • 학번·이름 공개에 동의하지 않으면 닉네임으로 씁니다. 이때 어떤 닉네임을 쓰는지 별도 설문에 등록합니다. 등록한 닉네임과 다른 이름으로 기록하면 본인 기록으로 인정되지 않아 평가에 불이익이 생길 수 있습니다.
  • 저장소는 12차시에 동결합니다. 그 뒤의 커밋은 평가에 넣지 않습니다.

4. 4주차 — 해석은 팀이 씁니다

결과 해석과 결론을 AI에게 쓰게 하면 발표 문답에서 바로 드러납니다. 해석은 팀이 먼저 쓰고, 데이터를 더 들여다봅니다. 오차를 구간별로 나눠 보기, 틀린 사례를 하나씩 확인하기, 변수끼리의 상관을 보기, 시기별로 나눠 보기처럼 한 번 더 파고든 분석에서 "우리 팀이 찾아낸 것"이 나옵니다. AI는 코드와 확인 질문에 쓰되, 그 과정은 log/에 남기고 해석 본문에는 쓰지 않습니다.

5. 발표와 문답 — 질문은 미리 공개합니다

발표 슬라이드는 다음 열 항목을 이 순서로 담습니다. 문장으로 길게 쓰지 말고 키워드 중심으로, 필요한 곳에 그래프를 넣습니다.

  1. 우리 팀의 데이터셋
  2. 이 문제를 선택한 이유
  3. 어떤 과정으로 분석했는지(차시가 아니라 실제 분석 단계: 수집·변수 선택·전처리·분할·기준선·후보 모델 비교·선택·평가·해석·한계 점검)
  4. 어떤 모델을 고려했는지(실제 모델 종류를 같은 조건에서 비교한 표)
  5. 왜 이 모델을 선택했는지(점수만이 아니라 이유)
  6. 우리가 쓴 평가지표(이름과 뜻, 우리 수치, 기준선 수치, 고른 이유)
  7. 모델링 과정에서 우리 팀이 결정한 것
  8. 최종 분석 결과에 대한 우리 팀의 해석(지표 풀이가 아니라 데이터에서 새로 찾아낸 것 세 가지, 수치 근거와 함께)
  9. 이후 추가로 연구한다면 더 해 보고 싶은 것(교과 연계, 진로 분야)
  10. 프로젝트를 하면서 AI를 활용하고 데이터를 분석하며 느끼고 배운 점
🧩 연계 수행평가: 모델 소개

팀이 선택한 모델과 비교 모델 두 개를 골라 원리, 장점, 단점, 어떤 상황에 쓰면 좋은지를 비교 분석해 3분 동안 따로 발표합니다. 슬라이드 2부(모델별 1장 + 비교 요약 1장)로 넣어 제출하고, README에도 "모델 소개" 절을 둡니다.

🖼️ 마무리는 포스터 발표

프로젝트의 마지막은 A1 세로 포스터 한 장으로 발표합니다. 질문·동기·데이터·분석 과정·고려한 모델·모델 소개·평가지표·결정한 것·결과 해석·한계·더 해 보고 싶은 것·느끼고 배운 점과 저장소 QR을 담습니다. 포스터 앞에서 선생님이 팀원 전원에게 문답을 합니다. 슬라이드는 제출물입니다. 샘플 저장소의 poster.html·poster.pdf를 참고합니다.

발표는 팀당 6분, 문답은 3분입니다. 문답은 팀원 전원이 한 문제씩 답합니다. 질문은 두 종류입니다.

종류누가무엇을
① 지표 질문전원우리 팀이 쓴 평가지표의 뜻과 수치를 자기 말로 설명합니다. 수업에서 다룬 지표만 묻습니다(아래 표)
② 기록 질문팀당 1명선생님이 우리 팀의 log/를 읽고 만든 질문입니다. 예: "6차시에 이 값을 뺐다고 썼는데, 안 뺐으면 결과가 어떻게 달라졌을까요?"
방법수업에서 다룬 지표기준선
회귀R²(결정계수) · MAE평균 모델(7·8차시)
분류정확도 · 정밀도 · 재현율 · F1다수 범주 찍기(11·12차시)
군집실루엣 · 엘보(k 선택)k를 왜 그 값으로 했는가(9차시)
연관지지도 · 신뢰도 · 향상도향상도 1(10차시)
📋 공개 질문 은행 — 이 다섯 가지는 반드시 준비합니다
  • 이 그래프(또는 숫자)는 무엇을 뜻합니까.
  • 아무 모델도 쓰지 않았을 때(기준선)보다 얼마나 나아졌습니까.
  • 이 결과를 믿을 수 없는 이유를 하나 말해 보십시오.
  • 여러분 팀은 이 결과에서 무엇을 새로 알게 되었습니까.
  • 주제를 왜 이것으로 정했습니까.

지목된 사람이 답하지 못하면 다른 팀원에게 같은 질문을 한 번 더 합니다. 팀 점수는 유지되고, 답하지 못한 사람의 문답 점수만 최하점이 됩니다.

6. 평가표 — 20점

채점 대상은 코드가 아니라 한 학기 내내 반복한 네 가지 판단입니다. 질문 설정, 데이터 감식, 결과 해석, 한계 인식입니다. 팀 공통 10점, 개인 10점입니다. 세부 점수는 학교 평가계획에 따라 조정될 수 있습니다.

7. 샘플 프로젝트 다섯 — 완성본은 이렇게 생겼습니다
