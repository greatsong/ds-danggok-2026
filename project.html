팀 프로젝트 — 우리 팀의 질문에 답하기

"제1원칙은 자신을 속이지 않는 것이다 — 가장 속이기 쉬운 상대가 자기 자신이다."
리처드 파인만 (칼텍 졸업 연설, 1974) — 한 학기 동안 배운 검증의 습관이 가장 필요한 곳은 우리 팀의 분석입니다

공통 수업과 중간고사가 끝나면, 2~3인 팀이 스스로 고른 질문에 데이터로 답하는 5주(15차시) 프로젝트가 시작됩니다. 13·14차시에 쓴 팀 주제 카드가 출발점입니다. 한 학기 동안 배포·API·시각화·회귀·분류·군집·연관을 모두 익혔으니, 이제 도구 선택도 여러분이 합니다.

🎯 5주 뒤에 남는 것
  • 팀 저장소 — 질문·동기·데이터·코드·결정의 기록이 담긴 깃허브 저장소 1개
  • 발표 — 우리 팀의 질문, 데이터가 준 답, 그리고 그 답의 한계
  • 개인의 몫 — 팀 안에서 내가 맡은 분석과 나의 판단 기록

1. 흐름 — 5주의 지도

정확한 주차 운영은 학급 사정에 따라 조정되며, 아래는 기본 흐름입니다. 데이터 분석 6단계(1차시)가 그대로 5주의 뼈대가 됩니다.

주하는 일남기는 것
1주문제 정의 — 주제 카드의 질문을 데이터로 답할 수 있는 형태로 다듬고, 데이터를 확보한다 (교과서 Ⅳ-02a)팀 저장소 개설 · README 초안 · 데이터 승인서(1주차 셋째 시간의 데이터 심사를 통과해야 다음 주로 넘어갑니다)
2주전처리·탐색 — 데이터의 구멍·이상값·표기 흔들림을 확인하고 판단을 기록한다전처리 기록 · 탐색 그래프
3주모델링 — 질문에 맞는 틀(회귀·분류·군집·연관)을 고르고, 모델 오디션(4절)으로 여러 모델을 같은 시험에 세운다 — 군집·연관을 고른 팀은 모델 수 대신 k 후보나 향상도 1이라는 기준선과 비교한다분석 코드 · 모델 비교 표
4주검증·한계 — 결과를 스스로 반박해 보고, 모델의 문제점을 확인한다 (교과서 Ⅳ-02b)한계와 후속 제안 · 보고서 초안
5주발표 준비·발표 — 질문에서 한계까지 한 편의 이야기로발표 자료 (저장소는 4주 끝에 동결합니다)

2. 질문과 데이터 — 세 물음으로 고른다

주제는 거창할 필요가 없습니다. 1차시의 좋은 질문 조건(측정 가능 · 데이터로 답 가능 · 범위 명확)을 그대로 쓰고, 데이터 후보마다 교과서 176쪽의 세 물음으로 판단합니다.

물음확인할 것
충분히 있는가판단의 근거가 될 만큼 양이 있고, 한쪽으로 치우치지 않았는가
문제에 적합한가내 질문이 요구하는 기간·속성·형식을 갖췄는가
법적·윤리적으로 올바른가14차시의 점검 그대로 — 개인 단위 정보 금지 · 출처 명시 · 이용 약관 확인 · 편향 점검
🔎 데이터는 어디서 — 한 학기 동안 다닌 곳들부터

문서가 공개된 곳부터 찾는 것이 기본입니다. 수업에서 이미 다녀온 곳들 — 공공데이터포털(전 분야) · 기상자료개방포털(날씨) · 나이스 개방 포털(학교) · KOBIS(영화) · KBO 기록실(야구) · modudata(수업 정리 사본). 새 API를 만나면 2차시의 방법대로 — 문서에서 확인할 곳 세 곳을 찾아 프롬프트에 붙입니다.

3. 팀 저장소 — 무엇을 남기는가

팀당 깃허브 저장소 1개를 만들고, 다음을 필수로 담습니다. 저장소가 곧 프로젝트의 증거입니다.

항목내용
README팀의 질문 · 동기(팀 공동 동기 한 문단 + 팀원별 개인 계기 각 1~2줄) · 실행 방법 · 핵심 결정
데이터 카드데이터의 원출처·기간·열 설명·한계 — 수업 교재가 데이터를 소개하던 방식 그대로
역할·결정 로그누가 무엇을 맡았고, 갈림길에서 왜 그 길을 골랐는가 (이슈·커밋 활용)
실행 코드분석 코드(노트북 또는 스크립트). 스트림릿 배포는 선택 — 하면 갤러리에 게시
⚠️ 팀으로 내지만, 개인의 몫이 보여야 합니다

평가는 팀 산출물과 개인 증거를 함께 봅니다. 전원이 각자 남겨야 하는 것 — ①내가 맡은 그래프·분석 단계 1개 이상 ②내가 쓰고 고친 프롬프트 ③데이터에 대한 나의 판단 기록 ④커밋·이슈 등 작업 이력 ⑤팀 결론에 대한 나의 해석(동의든 보완이든 반대든). README의 개인 계기 1~2줄도 반드시 본인 말투로 씁니다.

4. 모델 오디션 — 하나의 문제, 여러 모델

모델은 하나만 학습시키고 끝내지 않습니다. 팀의 질문에 맞는 모델 2개 이상(권장 3개)을 같은 조건으로 학습시키고, 성적을 한 표에서 비교한 뒤 근거를 적어 고릅니다. 9차시에 로지스틱과 트리를 같은 문제에 적용해 본 것이 비교의 원형이고, 모델 도감 심화 페이지에서 다섯 모델로 미리 연습할 수 있습니다.

규칙내용
같은 시험같은 데이터, 같은 학습/시험 나누기, 같은 지표 — 조건이 다르면 비교가 아니다
기준선 첫 줄비교 표의 첫 줄은 언제나 기준선(평균 모델·다수 찍기) — 기준선을 못 넘는 모델부터 지운다
근거 기록점수만이 아니라 재현율·설명 가능성·안정성까지 — "왜 이 모델인가" 한 문단을 README의 핵심 결정에 남긴다

모델 비교 표는 발표 자료에 그대로 들어가고, "왜 이 모델을 골랐나"에 대한 답은 개인 증거 ③(데이터에 대한 나의 판단 기록)의 가장 좋은 재료가 됩니다.

5. 발표 전 최종 점검 — 여섯 가지 질문

파인만의 문장은 4주차(검증·한계)에서 실제로 적용합니다. 발표 전에 팀이 스스로 던질 여섯 물음 — 모두 한 학기 동안 실측으로 겪은 것들입니다.

  • 예측 시점에 알 수 없는 정보가 변수에 섞이지 않았나? (7·10차시 — 첫 주 관객 수의 누수)
  • 내 모델의 점수를 기준선과 비교했나? (8차시 평균 모델 · 10차시 다수 찍기 89%)
  • 여러 모델에 같은 시험을 치르게 하고, 그 성적표를 근거로 골랐나? (모델 오디션)
  • 결과가 달라지는 조건을 하나 이상 찾아 적었나? (6차시 창 3배 · 11차시 정규화)
  • 그럴듯한 규칙·상관을 우연·인과와 구분했나? (12차시 향상도 · 6차시 아이스크림)
  • 데이터의 한계(기간·결측·근사·출처)를 화면과 보고서에 밝혔나? (심화 페이지의 근삿값 표기처럼)

6. 평가는 무엇을 보나

채점 대상은 코드의 화려함이 아니라 한 학기 내내 반복한 네 가지 판단입니다 — 질문 설정 · 데이터 감식 · 결과 해석 · 한계 인식. 세부 배점과 일정은 학교 평가계획 안내를 따르며, 수업에서 별도로 공지합니다.

🎒 착수 체크

  • 팀 주제 카드의 질문을 세 조건(측정 가능·답 가능·범위 명확)으로 다듬었다.
  • 데이터 후보를 세 물음(충분·적합·윤리)으로 판정하고 원출처를 적었다.
  • 팀 저장소를 만들고 README에 질문·동기(개인 계기 포함)를 채웠다.
  • 역할을 나누고, 각자 맡을 분석 1개를 정했다.
