5차시 · 교사용

두 번째 API · 우리 학교 급식 — 교사 진행안

학생용 5차시 페이지 ↗를 화면에 띄운 채 진행합니다. 여기에는 시간표 · 멘트 · 예상 질문 · 예상 오류 · 이론 심화를 덧댔습니다. 이번 차시의 성격은 전이 검증입니다 — 2차시에 함께 밟은 순서(문서 발췌 → 주소창 맨눈 → 프롬프트에 문서 붙이기)를 학생이 다른 API에서 스스로 반복하는지 봅니다. 교사가 절차를 앞서 안내할수록 이 검증이 약해지므로, 오늘은 한 발 물러나 진행합니다.

⏱️ 50분 진행 시간표

시간블록핵심
0~8′두 API 비교비교표(키·실패 신호·빈 응답·다듬을 것) · 완성 주소를 새 탭에서 열어 이번 주 급식 JSON 맨눈 보기
8~30′①②③ 실습급식 페이지 추가 → 메뉴 카드 · 알레르기·칼로리 · 급식 없는 날 안내
30~42′③ 학기 전체스냅샷 154일로 전환 → 최다 등장 메뉴 TOP 10 가로 막대 — 1위가 무엇인지, 154일 중 며칠인지
42~47′예상 짝 기록"함께 자주 나올 것 같은 메뉴 짝 3개" 각자 기록·제출 — 12차시에 실제 규칙과 대조
47~50′갤러리포트폴리오(기온+영화 3페이지+급식) URL 게시 · 짝 상호 피드백 두 줄
🎙️ 시간이 밀리면

오늘 반드시 남길 산출물은 둘입니다 — ③ TOP 10 그래프(발견의 재료)와 예상 짝 3개 기록(12차시 회수용). 갤러리 게시(47~50′)는 다음 차시 시작으로 이월해도 되지만, 예상 짝 기록은 오늘을 넘기지 마세요. 12차시에 "데이터를 보기 전의 직감"과 대조하는 것이 핵심이라, 데이터를 더 들여다본 뒤에 적으면 가치가 줄어듭니다.

블록별 진행 노트

두 API 비교 (0~8′)

🎙️ 도입 멘트 — 오늘은 안내하지 않습니다

"2차시에 KOBIS를 만날 때는 제가 순서를 하나하나 안내했어요. 오늘은 두 번째 API입니다. 순서는 그때와 같아요 — 문서 발췌를 읽고, 완성 주소를 맨눈으로 보고, 문서를 붙여 부탁한다. 오늘은 여러분이 그 순서를 스스로 밟는 날입니다. 다른 점은 하나, 이번엔 인증키가 없어도 됩니다." 비교표의 네 줄을 학생과 함께 소리 내어 읽고, 완성 주소를 새 탭에서 열어 이번 주 급식 JSON을 30초만 훑습니다.

🙋 예상 질문

"키가 없어도 되면 KOBIS는 왜 키를 받았어요?" → "API마다 운영 방침이 달라요. 나이스는 키 없이 열어 두는 대신 한 번에 주는 건수를 제한해요. 공짜의 조건인 셈이죠. 키를 받아 쓰면 이 제한이 풀립니다 — 관리와 책임을 약속한 사용자니까요." · "우리 학교 말고 다른 학교 급식도 볼 수 있어요?" → "학교 코드(SD_SCHUL_CODE)만 바꾸면 됩니다. 전국 어느 학교든 같은 주소로 조회돼요 — 같은 약속, 다른 조건의 좋은 예입니다."

①②③ 실습 (8~30′)

🎙️ 멘트 — 결과가 똑같지 않아도 된다

"화면이 학생용 페이지의 ② 이런 모습이면 성공이에요. 글자까지 같을 필요 없어요." 프롬프트를 붙여 넣기 전에 "이번엔 secrets에 넣을 게 있나요?"라고 물어보세요 — "키가 없으니 없다"는 답이 나오면 전이가 일어난 것입니다. 완성한 학생에게는 일요일 날짜를 골라 보게 합니다.

🧯 예상 오류 (실측 기반)

주말·방학 날짜를 골랐더니 아무것도 안 나옴/오류 화면 → 오류가 아닙니다. 급식이 없는 날은 row 없이 RESULT 상자("해당하는 데이터가 없습니다", INFO-200)만 옵니다. 앱이 이 경우를 안내 문구로 받아 내는지가 ①의 요구사항 — 처리가 빠졌으면 "급식이 없는 날엔 안내 문구를 보여 줘"로 개선 프롬프트를 잇게 합니다. · 응답이 JSON이 아니라 XML로 옴 → 주소에 Type=json이 빠진 것입니다. 이 파라미터가 없으면 기본이 XML입니다. · 긴 기간을 조회했는데 앞부분만 옴 → 키 없는 호출의 건수 제한입니다(실측: 넉 달치 82건을 물어도 목록에는 5건만 옵니다). 오류가 나지 않아 학생이 알아채기 어려우니, "전체 건수와 목록 길이를 비교해 보라"고 알려 주세요. 조회 기간을 하루~한 주로 줄이면 해결됩니다. · 메뉴가 한 줄에 통째로 붙어 나옴 → 구분 기호 <br/> 처리가 빠진 것 — "메뉴를 <br/> 기준으로 낱개로 나눠 줘"로 개선하게 합니다.

③ 학기 전체 (30~42′)

🎙️ 멘트 — API에서 표로 갈아타는 이유

"달력 조회는 하루씩이에요. '한 학기 동안 뭐가 제일 자주 나왔나'는 API로 물으면 건수 제한에 걸립니다. 3차시에 하루치 박스오피스에서 365일 표로 갈아탔던 것 기억하죠? 오늘도 같은 장면이에요 — 미리 쌓아 둔 154일 표로 갑니다." TOP 10이 나오면 1위(배추김치 86일 · 56%)를 전체 화면으로 확인하고, "TOP 10이 전부 밥과 김치"라는 관찰을 학생 입에서 끌어냅니다.

📖 이론 심화 — 56%를 오늘 심어 두는 이유 (교사만)

배추김치 86일/154일(56%)은 12차시 연관 분석의 복선입니다. 그날 "제육볶음이 나오는 날의 56%에 배추김치가 나온다"는 그럴듯한 규칙이 등장하는데, 배추김치는 애초에 전체 날의 56%에 나오는 메뉴라 이 규칙은 정보가 없습니다 — 기준선(전체 등장 비율)과 비교해야 규칙의 가치를 잴 수 있다는 것이 12차시의 핵심 반전입니다. 오늘 56%라는 숫자를 학생 눈에 심어 둘수록 그날의 반전이 커집니다. 주의: 오늘은 연관 지표의 이름이나 수치를 미리 꺼내지 마세요. "이 숫자가 12차시에 다시 등장한다"까지만 말하고 멈추는 것이 설계 의도입니다.

예상 짝 기록 (42~47′)

🎙️ 멘트 + 운영

"데이터를 뒤지기 전에, 여러분의 직감을 먼저 기록합니다. '○○가 나오는 날엔 △△도 나온다' 꼴로 3개." 제출은 폼이 기본이고(응답이 시트에 남아 12차시에 그대로 투사 가능), 폼 사정이 안 되면 공책에 적고 사진으로 제출하게 합니다. 이 기록은 12차시 수업의 재료입니다 — 응답 시트를 삭제하지 말고 보관하세요. 12차시에 학급 예상 목록을 화면에 띄우고 실제 규칙과 대조하는 것이 그날 도입입니다. "배추김치 짝은 반칙 아니냐"는 학생이 나오면 정답 — "왜 반칙 같은지"를 한 마디 받아 두면 12차시 도입 멘트로 그대로 쓸 수 있습니다.

갤러리 (47~50′)

🎙️ 마무리 + 다음 차시 예고

"포트폴리오가 다섯 페이지가 됐어요. 주소를 갤러리에 올리고, 짝의 앱에서 좋았던 것 하나·궁금한 것 하나를 남기세요." 예고: "다음 시간부터는 만든 그래프 위에 직선을 긋기 시작합니다. 그래프를 읽는 데서, 예측하는 데로 넘어갑니다." 갤러리 주소는 클래스룸 공지로 미리 게시해 둡니다.

🧾 생기부 관찰 지점

질문 설정·전이 — 교사 안내 없이 두 API의 차이(키 유무·실패 신호)를 비교표로 정리하고, 새 API에 배운 순서를 스스로 적용한 학생. · 데이터 감식 — 건수 제한(전체 건수와 목록 길이의 불일치)이나 급식 없는 날의 RESULT 응답을 오류가 아닌 데이터의 성질로 구분해 말한 학생. · 결과 해석 — TOP 10이 밥·김치로 쏠린 까닭을 급식 운영의 구조(매일 나오는 기본 반찬)와 연결해 해석하거나, 예상 짝을 고를 때 "자주 나오는 메뉴끼리 묶으면 맞아도 의미가 없다"는 낌새를 스스로 말한 학생.

✅ 5차시 마무리 체크 (교사)

  • 전원 급식 페이지가 앱에 붙었나? (막힌 학생 → 학생용 ② 코드로 구제)
  • 급식 없는 날 처리를 전원 확인했나? (일요일 날짜 조회)
  • ③ TOP 10 그래프에서 1위(배추김치 86일 · 56%)를 함께 확인했나?
  • 예상 메뉴 짝 3개를 전원 제출했나? 응답 시트를 12차시용으로 보관했나?
  • 연관 지표의 이름·수치를 미리 말하지 않았나? (12차시 반전 보호)
  • 포트폴리오 URL이 갤러리에 올라갔나? (이월 시 다음 차시 시작에)
