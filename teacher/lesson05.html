5차시 · 교사용

두 번째 API · 우리 학교 급식 — 교사 진행안

학생용 5차시 페이지 ↗를 화면에 띄운 채 수업을 이어 갑니다. 이 문서에는 시간표, 멘트, 예상 질문, 예상 오류, 이론 심화가 덧붙여져 있습니다. 이번 차시는 팀 단위 미니 프로젝트 성격입니다. 학기말 5주 팀 프로젝트와 같은 순서를 한 차시로 압축한 구성입니다. 오늘 교사가 정해 주지 않는 것은 무엇을 알아낼지와 어떤 화면을 만들지입니다. 교사가 앞서 정해 줄수록 이 차시의 목적은 약화됩니다.

⏱️ 50분 진행 시간표

시간블록핵심
0~6′두 API 비교두 API 비교표 확인·완성 주소 새 탭 열기·응답 확인
6~12′인증키키 없이 되는 이유·건수 상한·팀당 한 개 발급·비밀 금고 입력
12~22′발산·수렴팀별 아이디어 세 개 이상 발산·하나로 수렴·기준 분석 가능성과 임팩트
22~28′프롬프트 작성공식 문서 발췌 붙이기·팀 문제 설명 프롬프트 작성
28~42′제작·조건 점검제작과 배포·필수 조건 세 가지 점검
42~47′공유·시상팀 앱 주소 공유·아이디어 시상
47~50′개인 미션개인 미션 설문 안내·제출
🎙️ 시간이 밀리면

오늘 반드시 남길 산출물은 팀이 고른 질문 하나와 개인 미션 설문입니다. 앱 제작과 갤러리 게시는 다음 차시 앞으로 이월할 수 있습니다. 설문은 오늘을 넘기지 않아야 합니다. 12차시에 데이터를 보기 전의 예상과 실제 규칙을 대조하기 때문입니다. 나중에 적으면 예상의 성격이 약해집니다.

블록별 진행 노트

두 API 비교와 완성 주소 (0~6′)

🎙️ 도입 멘트 — 오늘은 안내하지 않습니다

"지난 2차시 KOBIS에서는 교사가 순서를 하나하나 안내했습니다. 오늘은 같은 순서를 여러분이 스스로 반복합니다. 문서 발췌를 읽고 완성 주소를 확인하고 프롬프트에 문서를 붙이는 흐름입니다." 오늘은 인증키가 없어도 되는 API와 팀 단위 진행이라는 두 가지가 다릅니다. 비교표 세 줄을 함께 읽고 완성 주소를 새 탭에서 열어 30초간 확인하도록 안내합니다.

🙋 예상 질문

"키가 없어도 되면 KOBIS는 왜 키를 받았어요?" → "API마다 운영 방침이 달라요. 나이스는 키 없이 열어 두는 대신 한 번에 주는 건수를 제한해요. 공짜의 조건인 셈이죠. 키를 받아 쓰면 이 제한이 풀립니다 — 오늘 3절에서 팀당 하나를 받습니다." · "우리 학교 말고 다른 학교 급식도 볼 수 있어요?" → "학교 코드(SD_SCHUL_CODE)만 바꾸면 됩니다. 전국 어느 학교든 같은 주소로 조회돼요 — 오늘 필수 조건에 '학교 세 곳 이상'이 들어간 까닭입니다."

인증키 (6~12′)

🎙️ 멘트 — 없어도 되지만, 받으면 넓어진다

"키 없이 사용할 수 있는 대신 한 번에 오는 건수의 상한이 있습니다. 팀당 한 개를 발급받고 가입과 신청에 몇 분 걸립니다." 발급받은 키는 코드가 아니라 비밀 금고에 입력하며, 이는 2차시와 같은 위치입니다. 하루나 한 주만 조회하는 팀은 키 없이 진행할 수 있습니다. 발급이 막힌 팀을 위한 수업용 키는 클래스룸 게시글에 게시합니다.

🧯 예상 오류 — 인증키

가입 절차에서 본인 확인에 막힘 → 수업용 키로 우회합니다. 비밀 금고 입력값의 따옴표 누락으로 앱 오류 → 입력값을 다시 확인합니다. 키를 코드에 직접 적어 커밋 → 저장소를 여는 누구나 사용 가능하므로 키를 새로 발급하고 코드에서 제거합니다. 넓은 기간 요청 시 앞부분만 오는 현상 → 오류 표시 없이 나타나므로 요청 범위를 조정합니다. 응답이 XML로 오는 경우 → 주소에 Type 항목이 누락되었는지 확인합니다.

아이디어 발산과 수렴 (12~22′)

🎙️ 멘트 — 고르는 일까지가 팀의 몫

"지금 단계에서는 어떤 아이디어도 평가하지 않습니다. 팀당 세 개 이상씩 내십시오. 제가 아이디어를 골라 주지는 않습니다." 수렴 기준은 두 가지입니다. 급식 API가 주는 값으로 답할 수 있는지와 알아냈을 때의 임팩트를 기준으로 삼으십시오. 맛 평가나 잔반량처럼 데이터에 없는 값을 묻는 아이디어가 자주 나옵니다. 그런 아이디어에 교사는 "그 답을 어느 열에서 찾을 것인지"를 묻습니다.

🙋 예상 질문

"아이디어가 세 개도 안 나와요" → 학교 비교, 요일 비교, 알레르기 세 방향을 예시로 제시한 뒤 팀이 바꾸게 합니다. "다른 팀과 주제가 겹치는데요" → 같은 주제라도 보여 주는 화면과 비교 대상이 다르면 다른 결과이므로 그대로 진행합니다.

프롬프트 작성 (22~28′)

🎙️ 멘트 — 문서와 문제를 함께 붙인다

"프롬프트에 반드시 들어갈 것은 공식 문서 발췌와 팀이 풀려는 문제 설명 두 가지입니다. 문서 발췌를 붙이는 목적은 AI가 필드 이름을 지어내지 못하게 막는 데 있습니다." 문제 설명 없이 기능만 나열하는 사례가 자주 나타납니다. 교사는 팀의 프롬프트 첫 문장에 팀이 답하려는 질문이 들어 있는지 확인합니다.

제작과 조건 점검 (28~42′)

✔️ 필수 조건 점검

필수 조건은 세 가지입니다. plotly 그래프, 당곡고등학교를 기본값으로 두고 학교를 세 곳 이상 한 번에 고른 뒤 함께 비교하는 화면, 알아보기 쉬운 앱 주소를 모두 충족해야 합니다. 비교 화면은 하나면 되고 모든 화면이 비교일 필요는 없습니다. 배포 직후 순회하며 팀별로 확인합니다. 학교 선택에서 자주 막히는 지점은 키 없는 학교 검색이 한 번에 다섯 건까지 응답한다는 점입니다. 대응 방법은 두 가지입니다. 학교 이름을 정식 명칭으로 적게 하거나 학교 코드를 직접 입력하게 하십시오.

🧯 예상 오류 (실측 기반)

주말·방학 날짜를 골랐더니 아무것도 안 나옴/오류 화면 → 오류가 아닙니다. 급식이 없는 날은 row 없이 RESULT 상자("해당하는 데이터가 없습니다", INFO-200)만 옵니다. 응답의 구조 자체가 달라지므로, 분기 없이 바로 값을 꺼내는 코드는 이 날짜에서 멈춥니다 — "급식이 없는 날엔 안내 문구를 보여 줘"로 개선 프롬프트를 잇게 합니다. · 응답이 JSON이 아니라 XML로 옴 → 주소에 Type=json이 빠진 것입니다. 이 항목이 없으면 기본이 XML입니다. · 긴 기간을 조회했는데 앞부분만 옴 → 키 없는 호출의 건수 제한입니다(실측: 두 학기 중식 184건을 물어도 목록에는 5건만 오고, pSize·pIndex를 붙여도 무시됩니다). 오류가 나지 않아 학생이 알아채기 어려우니, "전체 건수와 목록 길이를 비교해 보라"고 알려 주세요. · 인증키를 넣었는데 데이터가 아예 안 옴 → 키를 잘못 옮겨 적으면 ERROR-290이 오고 응답이 비어 옵니다. 키 없이 부르면 5건은 오므로, 오타 난 키를 넣느니 KEY 항목을 빼는 편이 낫습니다. · 메뉴가 한 줄에 통째로 붙어 나옴 → 구분 기호 <br/> 처리가 빠진 것 — "메뉴를 <br/> 기준으로 낱개로 나눠 줘"로 개선하게 합니다.

공유와 시상 (42~47′)

🎙️ 운영 + 다음 차시 예고

팀당 30초로 고른 질문과 알아낸 것을 발표합니다. 시상 기준은 완성도가 아니라 아이디어의 재미와 독창성입니다. 선정 방법은 학급 투표 또는 교사 선정으로 정합니다. 발표 뒤 팀 앱 주소를 갤러리에 게시합니다. 다음 차시 예고에서는 그래프 위에 직선을 그어 예측으로 넘어가는 활동을 진행합니다.

개인 미션 설문 (47~50′)

🎙️ 운영

설문의 성격은 수행평가가 아니라 생기부 기록용 활동입니다. 설문에는 함께 나올 것 같은 메뉴 짝 세 개를 예상하는 문항이 하나 포함됩니다. 12차시 도입에서 이 응답을 화면에 띄워 실제 규칙과 대조합니다. 응답 시트는 삭제하지 않고 보관합니다. 미제출 학생의 설문은 교사가 다음 차시 시작에 회수합니다.

📖 이론 심화 — 오늘의 표를 12차시에 회수한다 (교사만)

학생용 5절의 최다 등장 메뉴 표는 12차시 연관 분석의 복선입니다. 12차시에 등장하는 그럴듯한 규칙은 제육볶음이 나오는 날에 배추김치가 함께 나온다는 관찰입니다. 그 규칙에 정보가 없는 까닭은 배추김치가 원래 절반이 넘는 날에 나오는 메뉴이기 때문입니다. 12차시의 핵심은 기준선과 비교해야 규칙의 가치를 판정할 수 있다는 점입니다. 오늘은 연관 지표의 이름과 수치를 미리 꺼내지 않습니다. 오늘 말하고 멈출 곳은 이 표가 12차시에 다시 등장한다는 예고입니다.

🧾 생기부 관찰 지점

질문 설정 — 데이터에 없는 값을 요구하는 아이디어를 스스로 걸러 낸 학생. · 데이터 감식 — 건수 상한이나 급식이 없는 날의 응답을 오류가 아니라 데이터의 성질로 구분해 말한 학생. · 결과 해석 — 팀이 만든 그래프에서 읽어 낸 것을 급식 운영의 구조와 연결해 해석한 학생. · 한계 인식 — 우리 팀 결과로는 무엇을 답할 수 없는지 짚은 학생.

✅ 5차시 마무리 체크 (교사)

  • 전 팀이 아이디어를 세 개 이상 내고 하나로 수렴했나?
  • 전 팀의 프롬프트에 공식 문서 발췌와 팀의 문제 설명이 함께 들어갔나?
  • 필수 조건 세 가지를 팀별로 확인했나?
  • 인증키를 발급한 팀이 키를 코드가 아니라 비밀 금고에 넣었나?
  • 팀 앱 주소가 갤러리에 게시됐나?
  • 개인 미션 설문을 전원 제출했고 응답 시트를 보관했나?
  • 연관 지표의 이름과 수치를 미리 말하지 않았나?
