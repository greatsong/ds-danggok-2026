데이터베이스와 테이블의 정의

데이터베이스(database)는 여러 사람이 공유하여 사용하기 위해 통합 관리되는 데이터의 집합으로, 데이터베이스 시스템을 사용하면 대규모의 데이터를 효율적으로 저장하고 검색하며, 업데이트하고 관리할 수 있다
데이터베이스에는 여러 종류의 데이터셋이 들어가는데, 이때 각각의 데이터셋은 표 형태로 저장되며 이를 테이블(table)이라고 한다

샘플 프롬프트 작성

반찬 월드컵 스트림릿 앱을 만들어 줘. 파일 이름은 main.py 하나로.
후보는 제육볶음·간장찜닭·가자미순살튀김·돈육불백·미트볼데리야끼볶음·수육·진미채고추장볶음·치즈떡닭갈비 여덟 가지야.
8강 토너먼트로 진행해 줘. 판을 시작할 때 후보 순서를 섞고, 두 반찬을 나란히 보여 준 뒤 하나를 고르게 해.
이긴 반찬만 다음 라운드로 올려서 8강 네 번, 4강 두 번, 결승 한 번으로 모두 일곱 번 고르게 해 줘.
이름·학번·비밀번호는 받지 마.
서로 다른 두 후보 중 하나를 골랐을 때만, 교사가 준비한 표에 대결을 한 행씩 저장해 줘.
표 이름은 menu_duels이고 public 스키마에 있어. 표 이름에 스키마 이름을 붙여 쓰지는 마.
이 표의 열 이름은 id, game_id, round, left_menu, right_menu, winner, created_at 일곱 가지야.
id는 자동으로 늘어나는 정수이고 created_at은 저장 시각이 기본값이라 앱이 넣지 않아.
앱이 채우는 열은 game_id(한 판을 묶는 문자열), round('8강'·'4강'·'결승' 가운데 하나), left_menu, right_menu, winner 다섯이고 모두 문자열이야.
새 표를 만들지 말고 이 표에 그대로 연결해 줘. 수정·삭제 기능은 넣지 마.
접속 정보는 비밀 금고(secrets)의 SUPABASE_URL과 SUPABASE_KEY에서 읽어 줘.
판이 끝나면 우승 반찬을 보여 주고, 다시 시작하는 단추를 넣어 줘.
저장 결과를 확인하지 못하면 대결을 진행하지 말고 재선택을 잠근 뒤 확인이 필요하다고 안내해 줘.
필요한 라이브러리 목록(requirements.txt)도 같이 줘. 버전 숫자 없이 이름만.

교재 ①과 같은 문장 · 표·열 이름, 새 표 금지, 비밀 금고, 무결성 조건이 프롬프트 안에 있음

13-11 · 실습

개선 프롬프트 — 학급 대결 기록 분석

이 앱에 학급 전체의 대결 기록을 분석하는 화면을 추가해 줘.
menu_duels에 저장된 전체 기록을 대상으로 해. id, game_id, round, left_menu, right_menu, winner 여섯 열을 읽어서 반찬별 대결 수·승리 수·승률·우승 횟수를 비교하게 해 줘.
대결 수는 left_menu와 right_menu 양쪽을 모두 세고, 우승 횟수는 round가 '결승'인 행의 winner를 세어 줘.
모든 후보를 표시하고 대결 기록이 없는 후보의 승률은 아직 알 수 없다고 안내해 줘.
승률은 백분율로 보여 주고 높은 순서의 표와 가로 막대그래프로 비교해 줘.
그래프는 plotly로 그려 줘.
집계에 사용한 대결 기록 수와 판 수를 화면에 적어 줘. 기록 수와 참여 인원은 다르며, 진행 중에 남긴 대결도 집계에 들어간다고 표시해 줘.
한 판이 끝난 화면에서도 분석을 볼 수 있게 하고 결과를 다시 불러오는 단추를 넣어 줘.
기록이 아직 없을 때와 조회에 실패했을 때를 구분해 안내해 줘.
필요한 라이브러리 목록(requirements.txt)도 같이 줘. 버전 숫자 없이 이름만.

교재 ③과 같은 문장 · main.py와 requirements.txt 두 파일 · requirements.txt는 streamlit·supabase·pandas·plotly 네 줄

읽기 — SELECT 한 문장의 네 낱말

낱말뜻우리말로 읽으면
SELECT가져올 열 고르기 · *는 모든 열"메뉴와 저장 시각을 보여 줘"
FROM어느 테이블에서 가져올지"대결 기록 표에서"
WHERE조건에 맞는 행만 남기기"제육볶음을 선택한 표만"
ORDER BY정렬 기준 · DESC는 내림차순, ASC는 오름차순"최근 대결부터"

SELECT * FROM menu_duels WHERE winner = '제육볶음';

설계표에서 CREATE TABLE로

속성명설명데이터형조건
id기록 번호정수자동 증가 · 기본 키
game_id한 판을 묶는 번호문자열NULL·빈 값 불가
round대결 라운드문자열8강·4강·결승 중 하나
left_menu · right_menu겨룬 두 반찬문자열여덟 후보 중 서로 다른 반찬 · NULL 불가
winner이긴 반찬문자열겨룬 두 반찬 중 하나 · NULL 불가
created_at저장 시각날짜·시각현재 시각을 기본값으로 사용

설계표의 한 칸이 SQL의 한 낱말 — 속성명은 열 이름, 데이터형은 text·bigint·timestamptz, 조건은 NOT NULL·PRIMARY KEY·CHECK·DEFAULT

기본 키는 행을 유일하게 구분하는 열 또는 열의 조합 · NOT NULL은 NULL을 막지만 빈 문자열까지 막지는 않으므로 판 번호는 CHECK로 빈 값을 검사

묶어서 세기 — GROUP BY와 집계

  • COUNT(*) — 조건에 맞는 행의 개수 · SUM·AVG·MAX·MIN — 묶음마다 합계·평균·최댓값·최솟값
  • LIKE '%배추김치%' — 문자열 안에 "배추김치"가 들어 있는 행 · %는 "무엇이든"
  • GROUP BY — 같은 값끼리 묶음 · AS — 결과 열에 붙일 이름 · LIMIT — 앞에서 몇 행만
  • 묶은 열이 아닌 열은 한 칸에 값이 여러 개이므로 집계 함수로 감싸야 함
SELECT 요일, COUNT(*) AS 일수, AVG(칼로리) AS 평균칼로리 FROM meals WHERE 식사 = '중식' GROUP BY 요일 ORDER BY 평균칼로리 DESC LIMIT 5;
