2차시 · 교사용

반정형 데이터 · API와 JSON — 교사 진행안

학생용 2차시 페이지 ↗를 화면에 띄운 채 진행합니다. 여기에는 시간표 · 멘트 · 예상 질문 · 예상 오류 · 판서와 시연을 덧댔습니다. 수업 전 준비물: 클래스룸에 KOBIS 공용 키(학급별 분리)와 완성 주소(키가 든 요청 주소)를 비공개 게시해 둡니다.

⏱️ 50분 진행 시간표

시간블록핵심
0~5′도입예매 앱의 순위는 어디서 오나 · 1차시 대비: 기온은 내려받은 파일, 오늘은 내려받지 않는다
5~15′개념정형(식단표)/반정형(API 응답)/비정형(급식 사진) 실물 세 가지 · JSON = 라벨 붙은 상자 · API = 요청과 응답의 약속(4요소 표 · 접힘 '움직여 보기' SVG는 필요하면 펼쳐 시연)
15~25′맨눈 보기위젯에 키 붙여넣기 → 새 탭에서 JSON 확인 → 주소 해부: boxOfficeResult → dailyBoxOfficeList → 영화 한 편=상자 하나 · 함정 예고: "audiCnt" 값 — 숫자가 글자로 온다
25~46′실습 ①②③작업 순서 그대로 — ① 프롬프트 복붙 → ② 두 파일 받기 → 깃허브에 올려 커밋(파일 이름은 복붙) → 스트림릿 Secrets에 키 저장(이름 세 곳) → 확인 → ③ 개선. 막히면 학생용의 ② 코드로 구제
46~50′정리성공 판정: 오늘 저녁 포털 박스오피스와 내 앱 대조(과제: 스크린샷) · 과제: Ⅰ-01c(수행평가 I)

합산 검산: 5+10+10+21+4 = 50분 (휴식 없음).

📋 판서·시연 3종 (미리 준비)

🎙️ 시연 ① — 날짜의 약속 (맨눈 보기 블록)

완성 주소의 targetDt를 오늘 날짜로 고쳐 접속해 보입니다. 오류가 아니라 "dailyBoxOfficeList": [] — 빈 목록이 옵니다. 판서: targetDt는 하이픈 없는 여덟 자리 · 가장 늦은 조회일은 어제 · 오늘=오류가 아니라 빈 목록(집계 전). "비어 있음 ≠ 고장"을 여기서 한 번 보여 두면 ①②③ 블록의 질문이 절반으로 줄어듭니다.

🎙️ 시연 ② — faultInfo 라이브 (맨눈 보기 블록)

완성 주소에서 키의 마지막 한 글자를 지우고 접속합니다. 상태코드는 200인데 응답은 {"faultInfo":{"message":"유효하지않은 키값입니다.","errorCode":"320010"}} — 실측으로 확인된 실제 응답입니다. 멘트: "번호표(상태코드)는 성공인데 서류 내용은 오류예요. 둘 다 봐야 합니다." 브라우저 개발자 도구의 네트워크 탭으로 200을 함께 보여 주면 효과가 큽니다.

🎙️ 시연 ③ — KeyError 대처 (secrets 블록)

앱이 KeyError: 'KOBIS_KEY'로 멈춘 화면을 보여 주고(또는 이름을 일부러 틀리게 저장해 재현), 학생용 실습 4단계의 이름 세 곳 표로 돌아갑니다. 점검 순서 판서: ① 금고(Secrets)의 이름 → ② 프롬프트의 이름 → ③ 코드의 이름 — 대문자·밑줄까지 똑같은가. 이 오류는 오늘 가장 잦은 병목입니다 — 표를 화면에 띄워 둔 채 실습을 진행하세요.

블록별 진행 노트

도입 (0~6′)

🎙️ 도입 멘트 — 오늘은 내려받지 않는다

"예매 앱을 열면 나오는 박스오피스 순위, 저 숫자는 어디서 올까요? 1차시 기온 앱은 내려받아 둔 파일로 만들었어요. 그 파일은 내려받은 날에 멈춰 있죠. 오늘은 아무것도 내려받지 않고, 앱이 열릴 때마다 서버에 물어봐서 어제의 극장 기록을 받아 옵니다." 오늘의 도착점(어제의 박스오피스 대시보드)을 학생용 상단 배너로 먼저 보여 주고 시작합니다.

개념 (6~16′)

🎙️ 멘트 — 실물 세 개로 형태 구분

"같은 급식 하루가 세 그릇에 담겨 있어요. 표(CSV)면 정형, 라벨 붙은 상자(JSON)면 반정형, 사진이면 비정형." 학생용 specimen 세 칸을 화면에 띄우고 각 10초씩 가리키며 구분합니다. 이어서 KOBIS 실응답으로 JSON 상자 열기 — "겉상자 boxOfficeResult, 그 안의 목록 dailyBoxOfficeList, 영화 한 편이 상자 하나." API 그림(클릭 SVG)은 학생에게 네 번 클릭을 시키면 1분이면 끝납니다.

🙋 예상 질문 (개념)

"JSON은 왜 표로 안 주고 상자로 줘요?" → "받는 쪽마다 쓰임이 달라서예요. 표는 행·열이 고정이지만, 상자는 항목을 더하거나 빼기 쉽죠. 교과서 20쪽의 '구조를 바꿀 수도 있는 유연한 형태'가 그 뜻이에요. 우리는 받아서 표로 바꿔 씁니다." · "반정형은 정형이 되다 만 건가요?" → "열등한 게 아니라 공유에 유리한 형태예요. 그래서 API 응답의 표준이 됐어요."

📖 이론 심화 — 왜 API 응답의 숫자가 글자로 오나

JSON 자체에는 숫자 타입이 있지만, KOBIS는 모든 값을 문자열로 보냅니다. 오래된 시스템과의 호환, 자릿수 보존(선행 0), 언어별 숫자 정밀도 차이를 피하는 보수적 설계가 흔한 이유입니다. 학생에게는 "보내는 쪽 사정으로 흔히 있는 일이고, 받는 쪽이 숫자로 바꿔 쓰는 게 상식"까지만. 사전순 정렬 사고(문자열 "9" > "164393")는 지필 단골 소재입니다.

맨눈 보기 (16~26′)

🎙️ 멘트 — 코드 전에 브라우저로

"코드를 쓰기 전에, 이 약속이 진짜인지 브라우저로 확인할 거예요. 클래스룸에서 받은 키를 학생용 페이지 4절의 주소 만들기 상자에 붙여 넣으세요. 완성 주소가 만들어지면 '새 탭에서 열어 보기'를 누릅니다." (상자에 넣은 키는 실습 4단계의 Secrets 예시에도 자동으로 채워지므로, secrets 저장 때 그대로 복사하면 됩니다 — 키를 클래스룸 비공개 게시로 전달하는 절차는 그대로.) 학생용의 접힘 자료 '더 알아보기 — API 문서 읽는 법'은 수업 중에는 다루지 않고, 5차시 전에 읽어 오라고 한 줄만 안내합니다. 전원이 JSON 원문을 띄우면 시연 ①(오늘 날짜 → 빈 목록)과 시연 ②(키 한 글자 삭제 → faultInfo)를 이어서 보여 줍니다. 마지막으로 audiCnt 값(교재 예시는 164393 — 당일 화면에는 다른 숫자가 떠 있습니다)을 확대해 "숫자가 따옴표에 싸여 있죠? 이 함정은 프롬프트 한 줄로 미리 막을 겁니다."

🧯 예상 오류 (맨눈 보기)

JSON이 한 줄로 뭉쳐 보임 → 정상입니다. 브라우저에 따라 보기 좋게 접어 주기도 하고 날것으로 보여 주기도 합니다. 구조는 학생용 2절의 발췌로 확인. · 주소를 직접 타이핑해서 404 → 완성 주소를 반드시 복사·붙여넣기로. · kobis.or.kr 접속 불가 → 학교 방화벽 확인(사전 점검 목록의 허용 도메인: kobis.or.kr).

secrets (26~30′)

🎙️ 멘트 — 키는 코드 밖에

"키를 코드에 붙여 넣으면 커밋과 함께 전 세계에 공개됩니다. 남이 내 이름으로 호출하면 한도(하루 3,000회)도, 책임도 내 몫이에요. 키가 갈 곳은 코드가 아니라 비밀 금고(Secrets)입니다." 절차는 학생용 실습(5절)의 '스트림릿에서 키 넣기' 단계(자세한 판은 6절)를 화면에 띄우고 그대로 따라 하게 합니다. 저장 후 앱이 스스로 다시 시작되며 잠깐 깜빡이는 것까지 예고해 두세요.

🙋 예상 질문 (secrets)

"키를 친구한테 보여 줘도 돼요?" → "오늘 키는 반 전체가 나눠 쓰는 공용 키라 반 안에서는 공유가 전제예요. 다만 공개된 곳(코드·저장소·게시물)에 올리는 것은 금지 — 한도를 모르는 사람들이 쓰기 시작하면 우리 반 실습이 멈춥니다." · "secrets에 넣으면 절대 안 새요?" → "코드와 저장소에는 남지 않아요. 화면을 공유할 때 Secrets 설정 창을 띄워 두는 실수만 조심하면 됩니다."

①②③ 실습 (30~46′)

🎙️ 멘트 — 결과가 똑같지 않아도 된다

"프롬프트를 통째로 복사해 붙이고, AI가 준 main.py로 교체해서 커밋하세요. 여러분 코드가 예시와 글자까지 같을 필요는 없어요. 어제 순위표·1위 카드·막대그래프가 뜨면 성공입니다." ③ 개선(달력·순위 증감 화살표·트로피)은 "좋아, 여기서 이어서 고쳐 줘."로 같은 대화창에서 잇는 것을 강조 — 새 대화를 열면 AI가 코드를 잊습니다.

🧯 예상 오류 (실습 — 잦은 순서대로)

KeyError: 'KOBIS_KEY' → 시연 ③의 점검 순서. 대부분 Secrets의 이름 오타이거나 저장을 안 누른 경우. · faultInfo 화면 → 키 복사가 잘렸는지(앞뒤 공백·한 글자 누락) 확인. · 빈 목록 안내 → 서버 시간대 문제로 코드가 '어제'를 오늘로 계산했을 가능성. ① 프롬프트의 한국 시간 줄이 빠졌는지 확인하고, 빠졌다면 "어제를 한국 시간 기준으로 계산해 줘"를 이어서 요청. · ModuleNotFoundError → requirements.txt에 requests·plotly가 있는지 확인(① 프롬프트가 함께 만들게 되어 있음). · 그래프 순서가 이상함 → 숫자 변환 줄이 빠진 것. "관객수가 글자로 정렬됐어. 숫자로 바꿔서 다시"를 이어서 요청.

🙋 예상 질문 (실습)

"왜 문서를 프롬프트에 통째로 붙여요?" → "문서를 안 주면 AI가 라벨 이름을 그럴듯하게 지어냅니다. 지어낸 이름으로 짠 코드는 실행하면 바로 무너져요. AI가 볼 수 없는 사실(문서)은 우리가 준다 — 오늘 프롬프트의 핵심 요령입니다." · "캐시(한 시간 기억)는 왜 넣어요?" → "우리 반 전원이 새로고침할 때마다 호출하면 하루 한도 3,000회가 금방 찹니다. 같은 답을 다시 묻지 않는 게 서버에도 우리에게도 이득이에요."

정리 (46~50′)

🎙️ 마무리 + 검증 과제

"오늘 만든 순위표는 여러분이 내려받은 적 없는, 어제의 진짜 극장 기록이에요. 진짜인지 확인하는 방법 — 오늘 저녁 포털에서 '박스오피스'를 검색해 내 앱과 대조하고 스크린샷을 과제로 내세요." 다음 차시 예고: "오늘 받은 건 어제 하루치뿐이에요. '이 영화는 뜨는 중인가'는 하루치로 답할 수 없죠 — 다음 시간에 365일 치를 쌓은 표로 그 질문을 엽니다."

📝 폼·과제 처리

수업 중: Ⅰ-02c(데이터 형태 구분). 과제: Ⅰ-02a·b, 그리고 Ⅰ-01c(수행평가 I — 누락 금지)를 이번 주 과제로 공지합니다. 포털 대조 스크린샷 과제는 클래스룸 과제로 수합합니다.

🧾 생기부 관찰 지점

데이터 감식 — 따옴표 친 숫자를 스스로 발견하고 "사전순 정렬이 되니 숫자로 바꿔야 한다"고 이유까지 말한 학생. 결과 해석 — 시연 ②에서 "상태코드만으로 성공을 판단할 수 없다"는 결론을 자기 말로 정리한 학생. 검증 습관 — 포털 대조 과제에서 수치 불일치(집계 시점 차이 등)를 발견하고 원인을 추측해 기록한 학생을 채집.

✅ 2차시 마무리 체크 (교사)

  • 전원이 주소창에서 JSON 원문을 열어 보았나? (접속 불가 → 방화벽·완성 주소 복사 확인)
  • 전원 Secrets에 KOBIS_KEY를 저장했고, 코드에 키를 붙여 넣은 학생이 없나? (커밋 전 육안 점검)
  • 어제의 박스오피스 대시보드가 전원 배포되었나? (막힌 학생 → 학생용 ② 코드 예시로 교체 커밋)
  • 폼 Ⅰ-02c 제출과 과제 공지(Ⅰ-02a·b, Ⅰ-01c 수행평가 I, 포털 대조 스크린샷)를 마쳤나?
