모델 도감 — 교과서 너머

"모든 모델은 틀렸다. 그러나 몇몇은 쓸모가 있다."
조지 박스(통계학자) — 그래서 필요한 것은 완벽한 모델이 아니라, 여럿을 같은 시험에 세워 보고 고르는 눈입니다

이 페이지는 차시가 아니라 자유 실습입니다. 한 학기 동안 배운 모델은 넷 — 회귀·분류(로지스틱·트리)·군집·연관이었습니다. 실제 데이터 분석 현장에서는 여기에 몇 가지 모델이 더 자주 등장하는데, 그 원리는 전부 이미 배운 내용의 연장입니다. 세 가지를 그림으로 이해하고, 마지막에 다섯 모델을 한 문제에 세워 성적을 비교하는 모델 오디션을 엽니다. 팀 프로젝트 3주차의 예행연습입니다.

🎯 오늘 만나는 것
  • k-최근접 이웃(kNN) — 가장 가까운 이웃들에게 물어본다 (11차시의 거리 재사용)
  • 랜덤 포레스트 — 나무 한 그루가 아니라 숲의 투표 (9차시 트리의 연장)
  • XGBoost — 틀린 문제를 다음 나무가 다시 푼다 (오답 노트 학습)
  • 모델 오디션 — 다섯 모델, 같은 시험, 성적표 하나 (①②③)

0. 지도 — 배운 것과 오늘 만날 것

모델어디서한 줄 원리
선형·다중 회귀6~8차시과거 데이터에 직선을 긋는다
로지스틱 회귀9~10차시직선을 확률(0~1)로 눌러 담는다
의사결정트리9~10차시스무고개처럼 질문을 던져 나눈다
k-평균 군집11차시거리로 비슷한 것끼리 묶는다
k-최근접 이웃오늘 §1가장 가까운 k명의 다수결을 따른다
랜덤 포레스트오늘 §2서로 다른 나무 여러 그루의 투표
XGBoost오늘 §3남은 오차를 다음 나무가 이어서 학습

새 이름이 셋 나오지만 새 수학은 없습니다 — 거리(11차시), 트리(9차시), 오차(8차시)를 이미 손으로 다뤄 봤기 때문입니다.

1. k-최근접 이웃(kNN) — 가장 가까운 이웃들에게 물어본다

kNN은 k-Nearest Neighbors(k개의 가장 가까운 이웃)의 약자입니다. 교과서 135쪽에서 분류 모델의 하나로 이름을 소개한 그 모델입니다. 원리는 한 문장으로 정리됩니다 — 새 영화가 성공할지 궁금하면, 속성이 가장 비슷한(거리가 가까운) 과거 영화 k편을 찾아 그 다수결을 따릅니다. 학습이라 할 것이 거의 없고, 판정 순간에 거리를 재는 것이 전부입니다.

아래에서 k 값을 바꿔 보세요. 같은 영화인데 k에 따라 판정이 뒤집힙니다.

🔬 움직여 보기 — k를 바꾸면 판정이 바뀐다
초록 ●는 성공했던 영화, 붉은 ✕는 실패했던 영화. 점선 원 안이 "이웃"으로 뽑힌 영화들입니다.
📐 왜 통하는가 — k의 양 끝을 생각하면 보인다

k=1이면 가장 가까운 영화 한 편이 전권을 쥡니다. 그 한 편이 우연히 특이한 영화라면 판정도 그대로 흔들립니다 — 우연에 가장 민감한 상태입니다. 반대로 k를 데이터 전체(216)까지 키우면 "가깝다"는 정보가 완전히 사라지고, 어떤 새 영화가 와도 항상 다수 클래스로 판정합니다 — 10차시의 "전부 실패로 찍는 기준선 모델"과 정확히 같아집니다. 좋은 k는 이 양 끝 사이에 있습니다. 우연 한 편에 흔들리지 않을 만큼 크게, "이웃답다"는 정보가 살아 있을 만큼 작게. 위 그림에서 판정이 뒤집힌 것은 오류가 아니라, 이 균형이 실제로 움직이는 모습입니다.

⚠️ kNN의 급소 — 정규화 없이는 거리가 거짓말을 한다

11차시에서 본 그대로입니다. 스크린 수(수백 단위)와 첫 주 관객(수십만 단위)을 그대로 재면 큰 단위가 거리 계산을 지배합니다. kNN은 거리로만 판단하는 모델이라, 군집 때보다도 정규화가 더 절실합니다. k를 몇으로 할지도 사람의 판단입니다 — 위 그림처럼 k 하나로 답이 뒤집히니까요.

2. 랜덤 포레스트 — 나무 한 그루가 아니라 숲의 투표

9차시의 의사결정트리는 질문을 던져 데이터를 나누는 모델이었습니다. 트리 하나는 이해하기 쉽지만, 학습 데이터의 우연한 특징까지 외워 버리기 쉽습니다. 랜덤 포레스트(Random Forest)는 이 약점을 수로 해결합니다 — 전체 데이터에서 중복을 허용해 무작위로 표본을 다시 뽑는 방식으로 조금씩 다르게 공부한 트리 수십~수백 그루를 기르고, 새 영화가 오면 전원 투표로 판정합니다. 이렇게 여러 모델을 묶는 방식을 앙상블(ensemble)이라 부릅니다.

아래 나무 다섯 그루를 하나씩 눌러 표를 열어 보세요. 표가 갈려도, 숲의 판정은 다수결이 정합니다.

🔬 움직여 보기 — 다섯 그루의 투표
나무 아래 색 조각은 그 나무가 공부한 표본입니다. 데이터를 나눠 갖는 것이 아니라 전체에서 중복을 허용해 무작위로 다시 뽑기 때문에, 표본들은 서로 많이 겹치면서도 조금씩 다릅니다 — 이 "조금씩 다름"이 투표를 의미 있게 만듭니다.
📐 왜 통하는가 — 다수결의 수학

나무 한 그루가 열에 일곱을 맞히고(오답률 30%), 나무들의 실수가 서로 다른 곳에서 일어난다고 해 봅시다. 다수결이 틀리려면 절반이 넘는 나무가 같은 문제에서 동시에 틀려야 하는데, 실수가 제각각이라면 그런 일은 드뭅니다. 확률로 계산하면 이렇게 됩니다.

나무 수다수결이 틀릴 확률 (실수가 서로 독립일 때)
1그루30%
5그루약 16%
25그루약 2%
101그루0.1% 미만

같은 실력의 나무인데 수만 늘려도 오답이 줄어듭니다. 단, 조건이 둘 있습니다 — ①각 나무가 찍기보다는 나아야 하고(반타작 이하면 모을수록 나빠집니다) ②실수가 서로 겹치지 않아야 합니다. 전원이 같은 데이터로 공부하면 같은 곳에서 같이 틀리므로, 일부러 표본을 무작위로 흔드는 것(부트스트랩)이 바로 조건 ②를 만드는 장치입니다. 현실의 나무들은 완전히 독립이 아니어서 표의 수치만큼 좋아지지는 않지만, 방향은 같습니다.

대신 잃는 것도 있습니다 — 트리 한 그루는 "무엇을 먼저 물었는지"를 눈으로 읽을 수 있었지만(9차시), 수백 그루의 숲은 그 설명을 한눈에 보여 주지 못합니다. 성능과 설명 가능성 사이의 선택 — 이것도 사람의 판단입니다.

3. XGBoost — 틀린 문제를 다음 나무가 다시 푼다

XGBoost는 eXtreme Gradient Boosting의 약자로, 표 형태 데이터 분석 대회에서 우승을 휩쓸어 온 현대의 대표 모델입니다. 랜덤 포레스트가 나무들을 한꺼번에 길러 투표시킨다면, 부스팅(boosting)은 나무를 한 그루씩 차례로 기릅니다 — 오답 노트 공부법과 같습니다. 첫 나무가 문제를 풀면, 두 번째 나무는 첫 나무가 남긴 오차만 집중해서 배우고, 세 번째 나무는 그러고도 남은 오차를 배웁니다. 8차시에 손으로 계산했던 그 "오차"가 여기서는 다음 학습의 교재가 됩니다.

아래에서 라운드를 진행해 보세요. 나무가 더해질수록 남은 오차가 줄어듭니다.

🔬 움직여 보기 — 라운드마다 오차가 줄어드는 학습 과정
실제 XGBoost는 이런 라운드를 수백 번 반복합니다. 라운드 수·나무 깊이 같은 설정값은 사람이 정합니다.
📐 왜 통하는가 — 투표가 아니라 덧셈

랜덤 포레스트의 최종 판정이 투표라면, 부스팅의 최종 예측은 나무들의 예측을 더한 합입니다. 각 나무가 배우는 것이 정답 자체가 아니라 "지금까지의 합과 정답 사이에 남은 차이"이기 때문에, 나무가 하나 더해질 때마다 합은 정답에 조금씩 가까워집니다 — 위 그림의 오차 막대가 줄어드는 이유가 정확히 이것입니다. 8차시에 손으로 잰 오차가 여기서는 다음 나무의 정답지가 됩니다. 이름의 gradient(기울기)는 오차가 가장 빨리 줄어드는 방향을 계산해 그쪽으로 나아간다는 뜻입니다. 그리고 나무 한 그루가 오차를 줄이는 몫은 일부러 작게 잡습니다 — 한 그루가 오차를 한 번에 다 지우려 들면 학습 데이터를 외우는 것과 같아지기 때문입니다.

⚠️ 잘 배우는 모델일수록 잘 외운다

오차를 집요하게 줄이는 모델은 학습 데이터의 우연까지 외울 위험도 그만큼 큽니다. 그래서 XGBoost 같은 강한 모델일수록 7·10차시의 규칙이 더 중요해집니다 — 학습에 쓰지 않은 데이터로 점수를 재고, 성능이 급등하면 실력보다 누수를 먼저 의심합니다. 모델이 강해져도 시험 감독의 원칙은 그대로입니다.

4. 모델 오디션 — 다섯 모델, 같은 시험, 성적표 하나 (①②③)

이제 배운 모델을 전부 한 무대에 세웁니다. 9~10차시와 같은 문제 — kobis_movies.csv(영화진흥위원회 KOBIS 원출처, 216편)로 흥행 성공을 분류 — 에 다섯 모델을 같은 조건으로 학습시키고, 성적을 한 표에서 비교합니다. 4차시 멀티페이지 앱에 페이지 하나를 추가하는 방식입니다.

  1. ① 샘플 프롬프트 — 그대로 붙여 넣기
    ① 프롬프트
    스트림릿 멀티페이지 앱에 추가할 새 페이지를 만들어 줘. 제목은 '모델 오디션'.
- 데이터는 이 주소에서 불러와:
  https://raw.githubusercontent.com/greatsong/modudata/main/data/kobis_movies.csv
  1년간 박스오피스 10위권에 든 영화 216편의 요약표야. 열은
  movieNm(영화명) · genre(장르) · nation(제작 국가) · first_scrn(개봉일 스크린수) ·
  first_show(개봉일 상영횟수) · first_week_audi(개봉 첫 주 관객) · total_audi(총 관객).
- 총 관객 100만 명 이상이면 성공(1), 아니면 실패(0)로 라벨을 만들어 줘.
- 변수는 개봉 전에 알 수 있는 것만 써: first_scrn, first_show, 그리고 장르(첫 번째 장르만).
  first_week_audi는 예측 시점에 알 수 없는 값이니 절대 넣지 마.
- 데이터를 학습용과 시험용으로 나누고, 다섯 모델을 똑같은 조건으로 학습시켜 줘:
  로지스틱 회귀, 의사결정트리, k-최근접 이웃, 랜덤 포레스트, XGBoost.
  거리를 쓰는 모델을 위해 숫자 변수는 정규화해 줘.
- 결과는 모델별 정확도·정밀도·재현율을 한 표로 보여 주고,
  맨 위에 "전부 실패로 찍는 기준선" 행을 넣어 줘.
- 표 아래에 '내가 고른 모델과 그 이유'를 적는 글상자를 만들어 줘.
- 필요한 라이브러리 목록(requirements.txt)도 같이 줘. 버전 숫자 없이 이름만.
    선생님이 실행해 확인한 예시 코드

    새 페이지 파일로 올립니다. XGBoost는 설치돼 있을 때만 오디션에 참가합니다

    pages/모델_오디션.py
    # pages/모델_오디션.py — 같은 문제에 다섯 모델을 세운다
import streamlit as st
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.neighbors import KNeighborsClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import accuracy_score, precision_score, recall_score

DATA_URL = "https://raw.githubusercontent.com/greatsong/modudata/main/data/kobis_movies.csv"

st.header("모델 오디션")


@st.cache_data
def load_data():
    df = pd.read_csv(DATA_URL)
    df["장르"] = df["genre"].str.split("|").str[0]
    df["성공"] = (df["total_audi"] >= 1_000_000).astype(int)
    return df


df = load_data()
X = pd.get_dummies(df[["first_scrn", "first_show", "장르"]])   # 첫 주 관객은 넣지 않는다
y = df["성공"]


def 모델들():
    models = {
        "로지스틱 회귀": make_pipeline(StandardScaler(), LogisticRegression(max_iter=2000)),
        "의사결정트리": DecisionTreeClassifier(max_depth=3, random_state=0),
        "k-최근접 이웃": make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5)),
        "랜덤 포레스트": RandomForestClassifier(n_estimators=200, random_state=0),
    }
    try:                                   # XGBoost는 설치돼 있을 때만 넣는다
        from xgboost import XGBClassifier
        models["XGBoost"] = XGBClassifier(n_estimators=200, eval_metric="logloss")
    except ImportError:
        st.caption("XGBoost가 설치되어 있지 않아 네 모델만 세웁니다. requirements.txt에 xgboost를 넣어 보세요.")
    return models


def 한판(seed):
    Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=seed, stratify=y)
    결과 = [{"모델": "전부 실패로 찍기", "정확도": round((yte == 0).mean(), 3), "정밀도": 0.0, "재현율": 0.0}]
    for 이름, m in 모델들().items():
        m.fit(Xtr, ytr)
        p = m.predict(Xte)
        결과.append({"모델": 이름,
                   "정확도": round(accuracy_score(yte, p), 3),
                   "정밀도": round(precision_score(yte, p, zero_division=0), 3),
                   "재현율": round(recall_score(yte, p, zero_division=0), 3)})
    return pd.DataFrame(결과)


st.subheader("한 번 나눠 본 결과")
st.dataframe(한판(42), hide_index=True)

  2. ② 성적표 읽기 — 표가 뜨면 절반, 읽어야 완성
    화면에 여섯 줄짜리 성적표(기준선 + 다섯 모델)가 뜨면 성공입니다. 읽는 순서는 10차시 그대로입니다. 첫째, 기준선(약 89%)을 넘지 못한 모델부터 지웁니다 — 정확도가 높아 보여도 기준선 아래면 다수결만 못한 것입니다. 둘째, 남은 모델끼리는 재현율을 봅니다 — 정작 잡고 싶은 성공작을 몇이나 잡았는지. 셋째, 표에 없는 것도 하나 고려합니다 — 그 모델의 판단을 설명할 수 있는가(트리는 보여 주고, 숲은 감춥니다).

    # 나누는 방법을 바꿔 가며 다섯 번
st.subheader("다섯 번 반복한 결과")
쌓기 = pd.concat([한판(s) for s in range(5)])
요약 = (쌓기.groupby("모델")["정확도"].agg(평균="mean", 최저="min", 최고="max").round(3)
          .sort_values("평균", ascending=False).reset_index())
요약["최고-최저"] = (요약["최고"] - 요약["최저"]).round(3)
st.dataframe(요약, hide_index=True)
st.text_area("내가 고른 모델과 그 이유")
st.caption("한 번의 성적만 보고 고르면 우연에 속을 수 있습니다.")
    다시 배포하면 표에 폭이 나타납니다. 평균이 비슷한 두 모델이라면 폭이 좁은 쪽이 더 믿을 만합니다. 한 번의 시험 성적이 아니라 여러 번의 안정성으로 고르는 것 — 팀 프로젝트에서 모델을 고를 때 그대로 쓰는 방법입니다.
✅ 오디션의 규칙 — 프로젝트에서 그대로 씁니다

①같은 데이터, 같은 나누기, 같은 지표로 시험한다 ②기준선을 표의 첫 줄에 세운다 ③점수만이 아니라 설명 가능성·안정성까지 근거로 적는다. 이 세 줄이 팀 프로젝트 안내의 "모델 오디션" 규칙 그대로입니다.

✅ 오늘의 체크

  • kNN·랜덤 포레스트·XGBoost의 원리를 배운 모델(거리·트리·오차)과 연결해 설명할 수 있다.
  • 모델 오디션 페이지를 배포하고, 기준선을 넘은 모델과 넘지 못한 모델을 확인했다.
  • 내가 고른 모델과 그 이유(점수·재현율·설명 가능성)를 글상자에 적었다.
